Bob AI Helper: configure Cursor, Claude Code and Codex in one place

Version v1.0.88 · Windows & macOS · MIT license · Last updated 2026-11-24

Bob AI Helper (shown in the app as AI Helper) is a free, open-source (MIT) desktop app for Windows and macOS that sets the API endpoint, API key and model for seven AI coding clients — Cursor, Claude Code, OpenAI Codex CLI, ChatGPT Desktop, WorkBuddy, Accio Work and DeepSeek Harness. Pick the BobAPI official node (or the TaijiAI backup node), enter your API key and model, and AI Helper finds the clients installed on your machine, runs a real streaming connection test, writes their config files locally and restarts the client so the change takes effect. Your API traffic goes from the client (or AI Helper's local bridge) straight to the node you choose.

What it does

  • Detects clients automatically — scans PATH, the Windows registry, npm global installs and Microsoft Store apps, and on macOS also checks Homebrew and NVM install locations.
  • Built-in BobAPI nodes — every client panel offers two nodes: the BobAPI official node (https://bob-api.com/, recommended) and the TaijiAI accelerated node (https://taijiai.online/, backup line). Enter your API key and model by hand, or sign in to a Bob API account for one-click setup, and fetch the model list from the selected node.
  • Writes config safely — only endpoint, key and model fields are changed; other settings are preserved. Files are written atomically with locking, and a snapshot is taken before the first change so you can restore it from Settings.
  • Tests before saving — sends a real streaming request and reports the HTTP status, time to first byte and common error hints.
  • Connects Cursor to third-party models — a local bridge (default 127.0.0.1:8969) translates Cursor's Connect-RPC / HTTP2 traffic to OpenAI-style requests to the BobAPI node, with streaming, reasoning output and image input.
  • Bridges Accio Work — a local bridge (default 127.0.0.1:8787) adapts model lists, chat, image generation, the Responses API and MCP proxying.
  • Splits one key across DeepSeek Harness routes — fetches every chat model your API key can use and writes it to the matching route by protocol: aihelper-claude (Anthropic Messages), aihelper-codex (OpenAI Responses) or aihelper-cn (Chat Completions, for DeepSeek, Qwen, GLM and other Chinese models). Edits are line-level, so your own routes, comments, !!js tags and the official DeepSeek account are kept.
  • Signed updates — update manifests are signature-checked, SHA-256 verified and protected against rollback.

How it works

  1. Detect. AI Helper looks for each client in PATH, the Windows registry, npm global installs and Microsoft Store packages. GUI apps on macOS don't inherit your terminal's environment, so it also checks /opt/homebrew/bin, /usr/local/bin and the newest Node.js under ~/.nvm/versions/node to find Claude Code and Codex CLI installed with npm.
  2. Test. When you pick a node and enter a key and model, AI Helper sends a real streaming request and shows the HTTP status, time to first byte and hints for common errors such as 401 or model_not_found.
  3. Write config. It writes only the endpoint, key and model fields to the client's own config file, atomically and under a file lock, after saving a snapshot of the original on the first change.
  4. Restart. It closes the client's process tree, waits for file handles to be released and relaunches it with the new settings. Electron clients such as DeepSeek Harness get a graceful shutdown request first.

Cursor: local Connect-RPC bridge (127.0.0.1:8969)

Cursor  →  AI Helper bridge (127.0.0.1:8969)  →  BobAPI node (OpenAI-style API)
        Connect-RPC / HTTP2                OpenAI-compatible requests

The bridge is built in Rust and speaks Cursor's Connect-RPC protocol, including gzip compression and h2c. A reversible patch points Cursor's Agent and Composer requests at the bridge, which translates them to OpenAI-style calls to the BobAPI node with streaming, reasoning output and image input, and serves your model list to Cursor. Details: use third-party models in Cursor.

Accio Work: local bridge (127.0.0.1:8787)

For Accio Work, AI Helper runs a separate local bridge that handles model lists, chat, image generation, the Responses API and MCP proxying, and injects your models into Accio Work's model list.

DeepSeek Harness: routing by protocol

Each DeepSeek Harness route speaks one protocol, so AI Helper fetches every chat model your key can use and sorts them into three managed routes in the desktop profile:

RouteProtocolModels
aihelper-claudeAnthropic MessagesClaude family
aihelper-codexOpenAI ResponsesGPT / Codex family
aihelper-cnOpenAI Chat CompletionsDeepSeek, Qwen, GLM and other Chinese models

Every route is tested with its own protocol and the file is written only if all of them pass. Keys from several groups can sit side by side, and AI Helper shares DeepSeek Harness's write lock so the two never write the file at the same time. Privacy and security

  • Local only. All configuration is written on your machine. Your API key is only sent to the BobAPI node you selected — during a connection test, or when the client itself makes model requests.
  • Protected session credentials. Session credentials are protected with DPAPI on Windows and stored in the Keychain on macOS.
  • HTTPS only. Both built-in nodes (https://bob-api.com/ and https://taijiai.online/) use HTTPS, and HTTPS is required.
  • Locked-down bridges. Both bridges listen only on the loopback address. The Cursor bridge only accepts connections from processes owned by the same OS user and validates the Host, Origin and Content-Type headers. The Accio Work bridge requires a per-instance path token (/i/<token>), checks Host and Origin, and applies rate limits and a request size cap.
  • Signed updates. Update manifests are signature-checked, each package is SHA-256 verified, and rollback to an older version is blocked. Updates come from the official site, a China mirror or GitHub Releases.
  • Reversible. A snapshot is taken before AI Helper first changes a client, and one click in Settings restores it.

FAQ

What is Bob AI Helper?

Bob AI Helper (shown in the app as AI Helper) is a free, MIT-licensed desktop app for Windows and macOS that sets the API endpoint, API key and model for AI coding clients: Cursor, Claude Code, OpenAI Codex CLI, ChatGPT Desktop, WorkBuddy, Accio Work and DeepSeek Harness. It finds the clients installed on your machine, runs a streaming connection test, writes their local config files once it passes, and launches or restarts the client when needed.

Which AI coding clients are supported, and where does each config go?

Seven clients: Claude Code (~/.claude/settings.json), OpenAI Codex CLI (~/.codex/config.toml), Cursor (~/.ai-helper/cursor_config.json, connected through a local bridge), WorkBuddy (~/.workbuddy/models.json), Accio Work (~/.ai-helper/accio_config.json, connected through a local bridge), DeepSeek Harness desktop (~/.dsh/profiles/desktop/cordis.patch.yml, or under DSH_HOME if it is set), and ChatGPT Desktop (install detection, launch and device management only).

Which API endpoints can I use?

AI Helper works with the BobAPI service. Every client panel offers two built-in nodes: the BobAPI official node (https://bob-api.com/, recommended) and the TaijiAI accelerated node (https://taijiai.online/, a backup line). Choose a node, then enter your API key and model by hand, or sign in to a Bob API account and use one-click setup. You can also fetch the model list from the selected node. There is no field for other URLs, and HTTPS is required. Keys picked from your Bob API account, and one-click setup, only work with the BobAPI official node. The first time you use a hand-entered key with a node, AI Helper asks you to confirm it for that node (确认用于此节点) before it can test, fetch models or save.

What does one-click setup configure, and what are the "groups"?

One-click setup requires signing in to a Bob API account (Bob API is the related API service). For each client it picks an API key from the matching key group and a recommended model: Claude Code uses the CC-Kiro-Max group with claude-sonnet-5-5; Codex CLI and ChatGPT use the Codex-不降质 group with gpt-5.6-sol; Cursor, WorkBuddy and Accio Work use the 国产Token计划 (Chinese models) group with glm-5.3; DeepSeek Harness uses the 国产Token计划 key and writes every chat model available to it, with deepseek-v4.1-flash as the default. A group is simply the name of an API-key group inside a Bob API account, not a model name. If a group has no key yet, AI Helper creates one. With manual setup you don't need to sign in: type your API key and model yourself.

Will AI Helper overwrite my existing configuration?

No. AI Helper only changes the fields it needs: API endpoint, key and model. Other settings in Claude Code, Codex and WorkBuddy are kept, and models you added to WorkBuddy yourself are not removed. For DeepSeek Harness it only writes aihelper-* routes and AIHELPER_* key references; your own routes, comments and official-account routes are kept byte for byte. A snapshot is saved before the first change and can be restored from Settings. Backing up important configs yourself is still a good idea.

Is my API key uploaded anywhere?

No. All configuration is written locally, and session credentials are protected with DPAPI on Windows and the Keychain on macOS. Your API key is only sent to the BobAPI node you selected, when you run a connection test or when the AI coding client makes model requests.

Why does Cursor need a local bridge?

Part of Cursor's traffic uses Connect-RPC / HTTP2 and internal message formats, so changing an OpenAI base URL alone cannot fully connect a third-party model. AI Helper runs a bridge on your machine (127.0.0.1:8969 by default) that translates between Cursor's requests and the OpenAI-style API of the BobAPI node, with support for streaming, reasoning output and image input. The patch to the Cursor client can be reverted at any time.

Does configuring DeepSeek Harness touch my official DeepSeek account?

No. AI Helper only configures the DeepSeek Harness desktop profile (~/.dsh/profiles/desktop/cordis.patch.yml, or under DSH_HOME if it is set) and only writes aihelper-* routes and AIHELPER_* key references. Your official DeepSeek account sign-in, the official API-key route (api.deepseek.com) and your own routes are left as they are, and a default model that points at an official model is kept. Launch DeepSeek Harness once before first use so it can initialize, and restart it after saving to see the new routes.

Is AI Helper free and open source?

Yes. AI Helper is open source under the MIT license, with its source code on GitHub (TF49/AI-Helper), and free for both individuals and companies. The app itself costs nothing; model usage is billed by your BobAPI account.

Which macOS build should I download, and what if macOS says the app is damaged?

Download the aarch64 DMG for Apple Silicon Macs (M1 to M5 series, including Pro, Max and Ultra) and the x64 DMG for Intel Macs; macOS 11 or later is required. If macOS says the app is damaged or that the developer cannot be verified, that is Gatekeeper quarantining an app that is not notarized by Apple. Run xattr -cr /Applications/AI\ Helper.app in Terminal, or Control-click the app in Finder and choose Open.
