如何给 Cursor 配置 glm-5.3 等第三方模型

适用于 AI Helper v1.0.88 · Windows 与 macOS · 最后更新 2026-11-22 · 作者 TF49

简短回答：Cursor 的 Agent 和 Composer 使用 Connect-RPC / HTTP2 和内部消息格式通信，只在设置里改 OpenAI Base URL 无法完整接入第三方模型。AI Helper 会在本机运行一个 Bridge（默认监听 127.0.0.1:8969），把 Cursor 的请求转换成 OpenAI 兼容接口请求，再转发到你指定的 API 地址，因此可以让 Cursor 使用 glm-5.3 或任意 OpenAI 兼容模型。

准备工作

  • 已安装 Cursor，并至少启动过一次。
  • 一个 OpenAI 兼容的 API 地址和 API Key（例如以 /v1 结尾的地址）。
  • 已安装 AI Helper（下载地址，Windows 10/11 或 macOS 11+）。

配置步骤

  1. 打开 Cursor 面板。启动 AI Helper，首页会自动检测 Cursor 的安装路径；进入 Cursor 配置面板。
  2. 填写 API 地址和 API Key。可以选择预置节点，也可以手动填写外部 API 地址。对于不在白名单内的地址，AI Helper 会显示目标 Origin 并要求确认，默认要求 HTTPS。
  3. 选择模型。AI Helper 会从该地址读取模型列表，选择 glm-5.3 或其他模型；也可以手动输入模型名。
  4. 保存并应用。点击「保存并应用 Cursor 配置」。AI Helper 会把配置写入 ~/.ai-helper/cursor_config.json，启动本地 Bridge，并修补 Cursor 客户端，使其请求发往 Bridge。
  5. 重启 Cursor。点击「重启 Cursor」，然后在 Cursor 的模型选择器中选择刚才配置的模型。
如果你使用 Bob API 账号登录 AI Helper 并执行「一键配置」，Cursor 会自动使用「国产Token计划」分组（Bob API 账号下国产模型专用的令牌分组，分组说明）的 API Key，推荐模型为 glm-5.3；账号下没有该分组的 Key 时会自动创建。

Bridge 支持哪些能力

  • Cursor 请求与 OpenAI 兼容请求之间的双向转换，支持流式响应。
  • 文本、思考内容（reasoning）和图片输入。
  • 向 Cursor 提供可用模型列表与默认模型。
  • 让 Cursor Agent 在当前工作区读取、搜索文件；写入、删除等操作需要先在面板中授权该工作区（授权记录在 ~/.ai-helper/agent_workspaces.json）。

关闭 AI Helper 主窗口后，它会留在系统托盘中，Bridge 继续运行；从托盘彻底退出后 Bridge 才会停止，此时 Cursor 中的第三方模型将不可用。

安全措施

Bridge 只监听本机回环地址。每条连接的第一个请求会根据对端端口找到发起连接的进程，只接受与 AI Helper 属于同一系统用户的进程，无法确认时一律拒绝；同时校验 Host、Origin 和 Content-Type。

如何还原为 Cursor 官方连接

在 Cursor 面板中点击「恢复官方连接」，或在 AI Helper 设置页使用一键恢复：Bridge 会停止，Cursor 客户端补丁会被还原。

常见问题

端口 8969 被占用怎么办？

在 Cursor 面板的「Bridge 网关端口」中改成其他空闲端口，保存后重新应用即可。

Cursor 升级后第三方模型失效了？

Cursor 更新可能覆盖被修补的文件。重新打开 AI Helper 的 Cursor 面板，再执行一次「保存并应用 Cursor 配置」。
