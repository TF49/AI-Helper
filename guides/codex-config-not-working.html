Codex CLI 修改 config.toml 不生效怎么排查

适用于 AI Helper v1.0.88 · Windows 与 macOS · 最后更新 2026-11-24 · 作者 TF49

简短回答：Codex 只在启动时读取 ~/.codex/config.toml。改了不生效时依次检查：文件是否就是 Codex 实际读取的那一份（Windows 为 %USERPROFILE%\.codex\config.toml，设置了 CODEX_HOME 时以它为准）；顶层 model_provider 是否指向你在 [model_providers.xxx] 中定义的 provider；base_url 是否以 /v1 结尾；env_key 指定的环境变量在当前终端里是否有值；是否有 profile 覆盖了顶层设置；TOML 语法是否正确。最后关闭并重新打开终端，再运行 codex。

症状、原因与处理速查

症状常见原因处理方法
改了 [model_providers.custom]，Codex 仍连官方或旧地址顶层没有 model_provider = "custom"，或该行写在了某个 [表] 下面把 model_provider 放在文件开头、所有表头之前
提示缺少环境变量 / 找不到 API Keyenv_key 指定的变量在当前终端中没有值设置变量后重新打开终端；macOS 需自行写入 shell 配置文件
HTTP 404base_url 少了或多了 /v1；服务不支持 Codex 使用的接口base_url 写成 https://bob-api.com/v1，或在 AI Helper 中选择节点重新保存
HTTP 401Key 错误或被吊销，或环境变量里是另一服务的 Key核对 env_key 对应变量的值
模型不对或 model_not_found活动 profile 覆盖了 model；模型不在该 Key 可用范围内检查 profile 与 [profiles.xxx]；从可用模型中重新选择
Codex 启动时报配置解析错误TOML 语法错误：中文引号、重复的表、Windows 路径反斜杠未转义按第五节修正语法
改的文件没有被读取设置了 CODEX_HOME，或改的不是当前用户目录下的文件确认 Codex 实际使用的配置目录

一、确认改的是 Codex 实际读取的文件

  • macOS / Linux：~/.codex/config.toml。
  • Windows：C:\Users\你的用户名\.codex\config.toml（即 %USERPROFILE%\.codex\config.toml）。注意文件扩展名必须是 .toml，资源管理器隐藏扩展名时容易存成 config.toml.txt。
  • 如果设置了环境变量 CODEX_HOME，Codex 会从该目录读取配置。AI Helper 始终写入用户目录下的 ~/.codex/config.toml，因此使用 CODEX_HOME 时，AI Helper 写入的配置不会被 Codex 读取。
# Windows（PowerShell）：查看是否设置了 CODEX_HOME
echo $env:CODEX_HOME

# macOS
echo $CODEX_HOME

二、model_provider 与 model_providers 不要混淆

这是最常见的“不生效”原因。两者作用不同：

  • [model_providers.custom]（复数，表）：定义一个名为 custom 的 provider 的连接参数，如 base_url、env_key。
  • model_provider = "custom"（单数，顶层字符串）：选择当前使用哪个 provider。

只定义 provider 而不选择它，Codex 仍会使用默认 provider。另外 TOML 中写在某个 [表头] 之后的键都属于这张表，所以顶层的 model 和 model_provider 必须写在文件开头、第一个表头之前：

model = "gpt-5.6-sol"
model_provider = "custom"          # 必须在所有 [表头] 之前

[model_providers.custom]
name = "Custom"
base_url = "https://bob-api.com/v1"
env_key = "CUSTOM_OPENAI_API_KEY"

三、base_url 与 wire_api

Codex 会直接在 base_url 后面拼接接口路径，因此 base_url 需要以 /v1 结尾，手动编辑时容易漏掉。AI Helper 保存时会写入所选节点的地址并自动补上 /v1，例如选择 BobAPI 官方节点时写入 https://bob-api.com/v1。

wire_api 用于指定 Codex 以哪种协议（Responses 或 Chat Completions）请求该 provider，可选值与默认值会随 Codex 版本变化，请以官方配置文档为准。AI Helper 不写入 wire_api；它的连通性测试向 /v1/responses 发送请求，测试通过说明所选节点和模型可以通过 OpenAI Responses API 调用。测试返回 404 时，请从读取到的模型列表中重新选择模型，或切换到另一个节点重试。

四、env_key：Key 放在环境变量里

Codex 从 env_key 指定名称的环境变量中读取 API Key，而不是从 config.toml 中读取。AI Helper 使用的变量名是 CUSTOM_OPENAI_API_KEY，并会移除 custom provider 中的 experimental_bearer_token、带凭据的请求头等字段，让 Key 只来自环境变量。

  • Windows：AI Helper 把 Key 写入当前用户的环境变量 CUSTOM_OPENAI_API_KEY，并通知系统刷新。已经打开的终端不会获得新值，请关闭后重新打开；在 VS Code、Cursor 等编辑器的内置终端中运行 Codex 时，需要重启编辑器。
  • macOS：AI Helper 不会修改 shell 配置文件，需要自己在 ~/.zshrc（或你使用的 shell 配置文件）中加入 export CUSTOM_OPENAI_API_KEY="你的 API Key"，然后重新打开终端。
# 检查当前终端里是否有值
# Windows（PowerShell）
if ($env:CUSTOM_OPENAI_API_KEY) { "已设置" } else { "未设置" }

# macOS
[ -n "$CUSTOM_OPENAI_API_KEY" ] && echo 已设置 || echo 未设置
如果你手动把 custom provider 的 env_key 改成了其他变量名，AI Helper 会提示“Codex env_key 无效，请先修复配置”并停止保存，以免 Key 与地址对不上。

五、TOML 语法错误

  • 中文引号：用中文输入法输入的 “ ” 不是合法的 TOML 引号，字符串必须使用英文 " 或 '。
  • 重复的表：同一个 [model_providers.custom] 写了两次会导致解析失败，请合并为一处。
  • Windows 路径：双引号字符串中的 \ 是转义符，"C:\Users\..." 会报错。改用单引号 'C:\Users\...' 或写成 "C:\\Users\\..."。
  • 文件编码：请保存为 UTF-8。现有文件不是 UTF-8 时，AI Helper 会提示“现有 Codex 配置不是 UTF-8，已停止写入”。

可以用 Python 3.11 及以上版本快速检查语法，出错时会指出行号：

python -c "import tomllib, pathlib; tomllib.loads((pathlib.Path.home()/'.codex'/'config.toml').read_text(encoding='utf-8')); print('OK')"

六、profile 覆盖了顶层设置

顶层的 profile = "名称" 或启动时的 codex --profile 名称 会启用 [profiles.名称] 中的设置，其中的 model、model_provider 会覆盖顶层同名字段。改了顶层却不生效时，先看是否有活动 profile。

AI Helper 会读取当前活动 profile：如果它选择的是其他 provider，会拒绝保存并提示“Codex 活动 profile 使用其他 provider；请先切换到 custom profile 再保存，避免配置显示与实际运行目标不一致”；如果它选择的就是 custom 并单独设置了 model，AI Helper 会同步更新该 profile 的 model，其他 profile 和设置保持不变。

七、AI Helper 写入了什么

AI Helper（MIT 开源、在本机运行）在连通性测试通过后才会写入，测试失败时不修改本地配置。它只管理名为 custom 的 provider：

位置AI Helper 的处理
顶层 model写入所选模型
顶层 model_provider设为 "custom"
[model_providers.custom] 的 base_url写入所选节点的地址，自动补齐 /v1
[model_providers.custom] 的 env_key设为 "CUSTOM_OPENAI_API_KEY"
[model_providers.custom] 的 name、api缺少时补上 name = "Custom"、api = "openai-responses"，已有值不改
custom 中的 experimental_bearer_token、requires_openai_auth 及带凭据的请求头移除
其他 provider、profile、sandbox 等设置保持不变

写入前，原文件会备份为同目录下的 config.toml.bak；首次修改前 AI Helper 还会保存快照（包括 config.toml 和 CUSTOM_OPENAI_API_KEY 环境变量），可在设置页通过「恢复所有客户端原生配置」还原。切换到不同域名的节点时，如果 custom 中仍有自定义的 query_params，AI Helper 会提示先清理，避免把旧节点的参数发到新节点。

常见问题

model_provider 和 model_providers 有什么区别？

model_providers（复数）是一组表，用来定义各个 provider 的 base_url、env_key 等连接参数，例如 [model_providers.custom]；model_provider（单数）是顶层的一个字符串，用来选择当前使用哪个 provider，例如 model_provider = "custom"。只定义了 [model_providers.custom] 而没有把 model_provider 指向它，Codex 仍会使用默认 provider。

base_url 要不要带 /v1？

需要带。Codex 会直接在 base_url 后面拼接接口路径（如 /responses），所以手动编辑时 base_url 一般写成 https://bob-api.com/v1。用 AI Helper 保存时，它会写入所选节点的地址并自动补上 /v1，无需手动处理。

Codex 提示缺少环境变量或找不到 API Key 怎么办？

Codex 从 env_key 指定的环境变量读取 Key，AI Helper 使用的变量名是 CUSTOM_OPENAI_API_KEY。Windows 上 AI Helper 会把它写入当前用户的环境变量，但已经打开的终端不会自动获得新值，需要重新打开终端（在编辑器内置终端中使用时要重启编辑器）。macOS 上 AI Helper 不会修改 shell 配置文件，需要自己在 ~/.zshrc 等文件中 export CUSTOM_OPENAI_API_KEY。

设置了 profile 后为什么顶层配置不生效？

当前生效的 profile 中的 model、model_provider 会覆盖顶层同名字段。如果活动 profile 选择的是其他 provider，AI Helper 会拒绝保存并提示“Codex 活动 profile 使用其他 provider；请先切换到 custom profile 再保存，避免配置显示与实际运行目标不一致”。请切换或修改 profile 后再保存。

AI Helper 会覆盖我的 config.toml 吗？

不会整体覆盖。AI Helper 只修改顶层 model、model_provider 和 [model_providers.custom] 中与连接相关的字段，其他 provider、profile、sandbox 等设置保持不变；写入前会把原文件备份为 config.toml.bak，并在首次修改前保存快照，可在设置页一键恢复。现有文件无法解析时，它会停止写入而不是覆盖。
