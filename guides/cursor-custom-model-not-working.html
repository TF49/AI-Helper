Cursor 自定义模型不生效 / 第三方模型连不上怎么排查

适用于 AI Helper v1.0.88 · Windows 与 macOS · 最后更新 2026-11-24 · 作者 TF49

简短回答：Cursor 的 Agent 等功能走 Cursor 自己的 Connect-RPC 接口，只改 OpenAI Base URL 接不全第三方模型。使用 AI Helper 的本地 Bridge 时，按顺序检查四件事：Bridge 是否在 127.0.0.1:8969（或自动切换后的端口）运行；Cursor 面板是否显示「已挂接 Bridge」且端口一致；Cursor 是否已重启；所选模型是否支持工具调用、API Key 与所选节点是否通过连通性测试。Cursor 升级后补丁会被覆盖，需要重新「接入 AI Helper」。

一、为什么只改 OpenAI Base URL 不够

Cursor 设置里的 OpenAI API Key 与 Base URL 覆盖是 Cursor 官方的“自带 Key”方式，但 Agent 等功能通过 Cursor 自己的 Connect-RPC 接口和内部消息格式与后端通信，并不是直接调用 OpenAI 兼容接口，所以只改 Base URL 无法让这些功能完整改用第三方模型。

AI Helper（MIT 开源、在本机运行）采用的做法是：在本机启动一个 Bridge，修补 Cursor 客户端让请求发往这个 Bridge，再由 Bridge 把请求转换成 OpenAI 兼容或 Anthropic 兼容请求，转发到你在面板中选择的节点（BobAPI 官方节点或 TaijiAI 加速节点）。所以“Cursor 用不了第三方模型”通常要从 Bridge、补丁、模型、Key 四个环节逐一排查。完整的配置步骤见 Cursor 配置第三方模型。

二、确认 Bridge 正在运行

Bridge 默认监听 127.0.0.1:8969，只接受本机回环地址的连接。可以在终端里访问它的健康检查地址：

# Windows（PowerShell 中请使用 curl.exe）
curl.exe http://127.0.0.1:8969/health

# macOS
curl http://127.0.0.1:8969/health

Bridge 正常时会返回 {"status":"ok","service":"ai-helper-cursor-bridge"}。连接被拒绝说明 Bridge 没有运行，常见原因：

  • AI Helper 已从托盘彻底退出。关闭主窗口时 AI Helper 会留在系统托盘，Bridge 继续运行；从托盘退出后 Bridge 才会停止。
  • 未开启自动拉起。Cursor 面板中的「随 AI Helper 自动拉起 Bridge (后台常驻)」开启且已填写 API Key 时，AI Helper 启动后会自动拉起 Bridge；关闭该选项后需要在面板中手动启动。
  • 端口被其他程序占用。见下一小节。

端口 8969 被占用

Bridge 启动时如果首选端口被占用，会先短暂重试，然后依次尝试其后的 20 个端口（8970 到 8989），成功后把实际端口写回 ~/.ai-helper/cursor_config.json。AI Helper 只会避让，不会结束占用端口的未知程序。可以这样查看端口被谁占用：

# Windows
netstat -ano | findstr :8969

# macOS
lsof -nP -iTCP:8969 -sTCP:LISTEN
端口自动切换后，Cursor 仍可能指向原来的端口。此时在 AI Helper 的 Cursor 面板点击「重启 Cursor」即可：它会先确认 Bridge 在线，发现 Cursor 指向的地址与实际端口不一致时重新修补，再重启 Cursor。直接从系统里重新打开 Cursor 不会触发这一步。

三、确认客户端补丁已应用

打开 AI Helper 的 Cursor 面板，查看接入状态：「已挂接 Bridge」表示补丁有效，「原生官方直连」表示 Cursor 仍在使用官方连接，需要点击「接入 AI Helper」。接入时 AI Helper 会做以下修改（都会先备份）：

  • 把 Cursor 安装目录 resources/app 中 workbench.desktop.main.js（以及新架构下的 workbench.glass.main.js）里的 Cursor 后端地址替换为 http://127.0.0.1:端口，并同步更新 product.json 中的校验和。原文件备份在同目录的 .ai-helper-backup 中。
  • 更新 Cursor 本地状态库 state.vscdb 中保存的后端地址（备份为 state.vscdb.ai-helper-bak）。
  • 在 Cursor 用户设置 settings.json 中设置 "cursor.general.disableHttp2": true 和 "http.proxySupport": "on"（原值备份为 settings.ai-helper-bak，还原时恢复）。

接入和还原都需要先关闭 Cursor，AI Helper 会自动结束正在运行的 Cursor 进程；如果 5 秒内没有退出，会提示“Cursor 进程清理超时（5秒），请手动关闭所有 Cursor 窗口后重试”。

Cursor 升级后失效

Cursor 更新会用新版本文件替换被修补的文件，面板状态会变回「原生官方直连」，这是第三方模型突然“消失”最常见的原因。重新点击「接入 AI Helper」即可，AI Helper 会校验新版本文件后重新建立备份。

如果提示“原始备份不完整或版本不匹配，拒绝覆盖已修补文件”，说明当前文件仍带有补丁，但备份属于另一个 Cursor 版本。AI Helper 会拒绝覆盖以免丢失原始文件，此时请先尝试「恢复官方连接」，不行再重新安装当前版本的 Cursor，然后重新接入。

四、重启 Cursor 并检查模型名

修补和配置都要在 Cursor 重新启动后才生效。建议使用面板中的「重启 Cursor」而不是手动重开，原因见上文端口一节。

Cursor 模型选择器中的列表由 Bridge 提供：Bridge 会用你的 API Key 读取所选节点的 /v1/models；读取失败时，只显示你在 AI Helper 中配置的模型。Bridge 按模型名选择上游接口：

  • 名称包含 claude、sonnet、anthropic 的模型使用 Anthropic Messages（/v1/messages）；
  • gpt-5、gpt-6、o1、o3、o4 开头或包含 codex 的模型使用 OpenAI Responses（/v1/responses）；
  • 其他模型（如 glm-5.3、DeepSeek、Qwen 等）使用 Chat Completions（/v1/chat/completions）。

上游没有对应的 Messages 或 Responses 端点（返回 404、405、501 等）时，Bridge 会改用 Chat Completions。模型名必须与节点模型列表中的名称完全一致，否则上游会返回模型不存在之类的错误。

五、用连通性测试检查 API Key、节点与模型

在 Cursor 面板点击「确认并保存 Cursor 配置」时，AI Helper 会先做一次连通性测试，测试不通过就不会修改本地配置。Cursor 的测试不只是发一句“Hi”，而是要求模型调用一个只读的探测函数，用来确认模型支持 Cursor Agent 需要的工具调用。测试日志会显示目标端点、HTTP 状态码、耗时和错误详情（Key 会被打码）：

测试结果含义
连接成功，且已验证工具调用能力节点、Key、模型均可用
连接成功，但未验证工具调用能力能连通，但模型没有返回工具调用；Cursor 将无法使用项目文件与 Agent 工具，请换用支持 Function Calling / Tool Use 的模型
HTTP 401身份认证失败，检查 API Key 是否填错或已被吊销
HTTP 403当前账号可能无权访问该模型，或存在 IP 地域限制
HTTP 404上游不提供所测协议的端点，或模型名不对
HTTP 429触发频控，或余额不足
HTTP 5xx上游服务异常，稍后重试，或在面板中切换到另一个节点（TaijiAI 加速节点需手动填写 Key，见下文）
错误中含 model_not_found该模型不在此 API Key 当前所属分组中，重新拉取可用模型后再选
受管 Key 不得发往未授权目标 …从 Bob API 账号选择的 Key（含一键配置）或已确认用于 BobAPI 官方节点的 Key 被用在了 TaijiAI 加速节点；切换回 BobAPI 官方节点，或手动填写可用于该节点的 Key
此密钥尚未获准用于当前节点，请在密钥输入处确认目标手动填写的 Key 还没有确认用于当前节点，在密钥输入处点击「确认用于此节点」后再测试
请求超时 (超过 60 秒未收到响应)网络不通或代理设置有问题

面板中的两个节点是「BobAPI 官方节点」（https://bob-api.com/，推荐首选）和「TaijiAI 加速节点」（https://taijiai.online/，备用专线），都使用 HTTPS。Bridge 和测试会先去掉地址末尾的 /v1 再拼接具体路径。一个节点超时或频繁返回 5xx 时，可以切换到另一个节点后重新测试保存，但要注意 Key 的来源：从 Bob API 账号选择的 Key、一键配置使用的 Key，以及已确认用于 BobAPI 官方节点的 Key，都只能发往 BobAPI 官方节点；改用 TaijiAI 加速节点时，需要手动填写 Key，并在密钥输入处点击「确认用于此节点」。

六、如何还原为 Cursor 官方连接

  • 只还原 Cursor：在 Cursor 面板点击「恢复官方连接」。AI Helper 会关闭 Cursor，从备份还原 workbench 文件和 product.json、state.vscdb 中的路由以及 Cursor 用户设置。
  • 还原所有客户端：在 AI Helper 设置页使用「恢复所有客户端原生配置」，Cursor 部分还会停止 Bridge，并删除 ~/.ai-helper/cursor_config.json 等 AI Helper 专用配置。

如果提示“Cursor Glass 仍包含 AI Helper 补丁，但缺少原始备份，无法安全恢复”，说明备份文件已丢失，重新安装 Cursor 即可恢复为官方文件。

常见问题

只在 Cursor 设置里填 OpenAI Base URL 为什么不够？

Cursor 的 Agent 等功能通过 Cursor 自己的 Connect-RPC 接口和内部消息格式与后端通信，并不是直接调用 OpenAI 兼容接口，所以只覆盖 OpenAI Base URL 无法让这些功能完整改用第三方模型。AI Helper 的做法是在本机运行 Bridge，把 Cursor 的请求转换成 OpenAI 兼容或 Anthropic 兼容请求后再转发到你选择的 BobAPI 节点。

端口 8969 被占用会怎样？

Bridge 启动时如果首选端口被占用，会自动尝试其后的 20 个端口，并把实际端口写回 ~/.ai-helper/cursor_config.json。此时请在 AI Helper 的 Cursor 面板点击「重启 Cursor」，它会在 Cursor 指向的端口与实际端口不一致时重新修补。如果 21 个端口都被占用，会提示“无法在端口 8969..=8989 建立 Cursor Bridge，请检查本机端口占用”，需要先释放端口或改用其他端口。

Cursor 升级后第三方模型失效了怎么办？

Cursor 更新会用新版本文件替换被修补的文件，Cursor 面板的状态会变回「原生官方直连」。在 Cursor 面板点击「接入 AI Helper」重新修补即可，AI Helper 会为新版本重新建立备份。

连通性测试提示“连接成功，但未验证工具调用能力”是什么意思？

说明所选节点和 API Key 可用，但该模型没有按要求返回工具调用。Cursor 读取、搜索项目文件等 Agent 能力依赖 Function Calling / Tool Use，因此 AI Helper 不会保存这次配置。请从模型列表中换用支持工具调用的模型。

如何彻底还原 Cursor 官方连接？

在 Cursor 面板点击「恢复官方连接」，或在 AI Helper 设置页使用「恢复所有客户端原生配置」。AI Helper 会关闭正在运行的 Cursor，从备份还原被修补的文件、state.vscdb 中的路由和 Cursor 用户设置；设置页的恢复还会删除 ~/.ai-helper/cursor_config.json。
