How to connect DeepSeek Harness to Claude, GPT and Chinese models

For AI Helper v1.0.88 · Windows & macOS · Last updated 2026-11-24 · By TF49

Short answer: DeepSeek Harness (DSH) desktop keeps its model routes in ~/.dsh/profiles/desktop/cordis.patch.yml and its keys in ~/.dsh/.credentials.yaml. Claude, GPT and Chinese models speak different protocols, so they need three separate routes. AI Helper, an MIT-licensed open-source app running on your machine, takes one BobAPI API key, fetches every chat model it can use and writes each model to the matching aihelper-* route by protocol — your own routes and your official DeepSeek account stay exactly as they were.

AI Helper's interface is currently in Chinese. Menu and button names in this guide are translated, with the original label in parentheses where it helps.

Why different models go into different routes

Each DeepSeek Harness route speaks exactly one API protocol, but the models behind one API key may use different protocols. So AI Helper sorts them into three routes:

RouteName shown in DSHProtocolModels
aihelper-claudeAI Helper · ClaudeAnthropic MessagesClaude family
aihelper-codexAI Helper · CodexOpenAI ResponsesGPT / Codex family
aihelper-cnAI Helper · 国产模型 (Chinese models)OpenAI Chat CompletionsDeepSeek, Qwen, GLM and other Chinese models

AI Helper works out the protocol for you; all you do is tick the models you want. Models it writes are declared as accepting text and image input by default, and any managed route that ends up with no models after saving is removed automatically.

Before you start

  1. Launch DeepSeek Harness desktop once so it creates the desktop profile under ~/.dsh. If you have set the DSH_HOME environment variable, AI Helper reads that directory instead.
  2. In AI Helper, go to Settings → Path management (设置 → 路径管理) and click Detect (探测) to confirm the DeepSeek Harness install path is found. AI Helper checks running processes, the Windows registry, %LOCALAPPDATA%\Programs and /Applications on macOS, in that order. You can also pick DeepSeek Harness.exe or DeepSeek Harness.app by hand.

Option 1: one-click setup from the dashboard

After signing in to a Bob API account, click one-click setup on the DeepSeek Harness card in the dashboard. AI Helper uses the API key from the 国产Token计划 group — the key group in a Bob API account reserved for Chinese models (see key groups, in Chinese) — and creates one if your account doesn't have it yet. It writes every chat model available to that key and sets deepseek-v4.1-flash as the default model for new sessions. The batch Configure all (一键配置所有) run includes DeepSeek Harness too: it tests each route with its own protocol and writes everything in one go once they all pass.

Option 2: set it up manually with the wizard

  1. Open Configuration center → DeepSeek Harness (配置中心 → DeepSeek Harness).
  2. Choose a node: the BobAPI official node (BobAPI 官方节点, https://bob-api.com/, the default and recommended) or the TaijiAI accelerated node (TaijiAI 加速节点, https://taijiai.online/, a backup line).
  3. Paste your API key. AI Helper fetches every model available to the key's current group and filters out image, speech, embedding and other models that can't chat. The first time you use a hand-entered key with a node, click Confirm for this node (确认用于此节点). Keys picked from your Bob API account, and one-click setup, only work with the BobAPI official node.
  4. Tick the models you want (select all works, and you can add model IDs by hand), then choose the default model for new sessions. The default only applies to new sessions; you can switch models in DeepSeek Harness at any time.
  5. AI Helper runs a connection test for each route and only writes the configuration once every route passes. If any route fails, nothing is written to disk.
  6. After saving, restart DeepSeek Harness (you can do this straight from the test console or the path management card). New routes such as AI Helper · 国产模型 then appear in the model picker.

Using keys from several groups at once

Keys from different groups can be saved separately and used side by side — for example a Chinese-model key, a Claude key and a GPT key together:

  • Add a key from another group: in the overview, click Add a key from another group (添加其它分组的 Key). The new key sits alongside the keys you already connected, and only model types that are not connected yet are ticked by default.
  • Replace a key: the new key takes over the routes of the key it replaces; routes connected through other keys stay as they are.
  • Edit a single key: when you open the wizard from the overview, you only edit the routes that use that key.
  • Re-check: after switching a key's group on the bob-api website, you can re-check from the overview whether each route's models are still available.

What AI Helper changes — and what it doesn't

AI Helper only manages its own aihelper-* routes and AIHELPER_* key references. Everything else stays as it was:

  • It only reads and writes the desktop profile; CLI, web and other profiles are never modified.
  • It edits line by line, so your own routes, records, comments and !!js expressions are preserved byte for byte. Before every write it compares the result with the original file semantically to confirm that only the intended parts changed.
  • It shares a write lock with DeepSeek Harness, so it never writes the file at the same moment DSH does (for example when DSH refreshes your official account token).
  • Your official DeepSeek account sign-in and the official API-key route (api.deepseek.com) are never rewritten. If your default model points at an official model, it stays that way when you save.
AI Helper takes a configuration snapshot before it first takes over. When you reset client configuration on the Settings page, the managed routes and key references go back to the snapshot, and DeepSeek Harness's token binding records are cleaned up as well.

FAQ

I saved, but the new models don't show up in DeepSeek Harness. What now?

DeepSeek Harness reads its configuration at startup, so restart it after saving to load the new routes. You can restart it from the test console or from the client card under Settings → Path management. When AI Helper restarts it, it first sends the main process a graceful shutdown request, so you no longer get a "renderer exited: killed" crash dialog.

What does "group unavailable" mean?

The model was configured earlier but is no longer in the group your API key currently belongs to. This usually happens after switching the key's group on the bob-api website, in which case the API returns model_not_found. Fetch the available models again, untick the unavailable ones, or move the key back to its original group on the website. Model IDs you added by hand are never unticked automatically.

AI Helper says it cannot find the DeepSeek Harness desktop configuration. What should I do?

Launch DeepSeek Harness desktop once to finish its first-run setup. It then creates its configuration profile under ~/.dsh (or the directory set in DSH_HOME), and AI Helper can configure it normally.

Does configuring DeepSeek Harness affect my official DeepSeek account?

No. AI Helper only writes aihelper-* routes and AIHELPER_* key references. Your official DeepSeek account sign-in, the official API-key route and the routes you created yourself are kept exactly as they are, and a default model that points at an official model is left unchanged when you save.
