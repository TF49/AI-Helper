How to use a custom API endpoint with OpenAI Codex CLI

For AI Helper v1.0.88 · Windows & macOS · Last updated 2026-11-24 · By TF49

Short answer: Declare a [model_providers.custom] table in ~/.codex/config.toml (with a base_url and an env_key), point the top-level model_provider at it, set model to the model name, and put your key in CUSTOM_OPENAI_API_KEY. AI Helper, an MIT-licensed open-source app, can write these fields on your machine: pick the BobAPI official node, enter your API key and choose a model.

Option 1: edit config.toml by hand

Open (or create) ~/.codex/config.toml — on Windows that is C:\Users\<your-username>\.codex\config.toml:

model = "gpt-5.6-sol"
model_provider = "custom"

[model_providers.custom]
base_url = "https://bob-api.com/v1"
env_key = "CUSTOM_OPENAI_API_KEY"

Then put your API key in the CUSTOM_OPENAI_API_KEY environment variable (on Windows, add a user variable under System Properties → Environment Variables; on macOS or Linux, export it from your shell profile). Open a new terminal and run codex.

Option 2: configure it in one step with AI Helper

  1. Launch AI Helper and open the Codex panel. AI Helper locates the codex CLI automatically.
  2. Choose a node: the BobAPI official node (BobAPI 官方节点, https://bob-api.com/, recommended) or the TaijiAI accelerated node (TaijiAI 加速节点, https://taijiai.online/, a backup line). Enter your API key (or sign in to a Bob API account for one-click setup) and choose a model (for example gpt-5.6-sol). The first time you use a hand-entered key with a node, click Confirm for this node (确认用于此节点). Keys picked from your Bob API account, and one-click setup, only work with the BobAPI official node.
  3. Click Confirm and save Codex config (确认并保存 Codex 配置); AI Helper writes once the streaming connection test passes. It writes the fields shown in the example above. On Windows it also stores the key in the current user's CUSTOM_OPENAI_API_KEY environment variable and tells the system to refresh its environment. On macOS it does not touch your shell profile, so you need to set that variable yourself (see the FAQ below).
  4. Open a new terminal and run codex, or launch Codex straight from AI Helper.
In config.tomlWhat AI Helper does
modelWrites the model you chose
model_providerSets it to "custom"
base_url in [model_providers.custom]Writes the selected node's URL, adding /v1 if it's missing
env_key in [model_providers.custom]Always CUSTOM_OPENAI_API_KEY
Credential headers in custom, such as experimental_bearer_token or AuthorizationRemoved — the key is only read from the environment variable
Other providers, profiles, sandbox settings, etc.Left untouched
AI Helper only manages the provider named custom. Any other providers, profiles and sandbox settings you have in config.toml are kept. With one-click setup (which requires signing in to a Bob API account), Codex uses the key from the Codex-不降质 group — the key group in a Bob API account reserved for Codex CLI and ChatGPT Desktop (see key groups, in Chinese). The recommended model is gpt-5.6-sol.

How to restore your original settings

Before AI Helper changes your Codex settings for the first time, it saves a snapshot that covers both config.toml and the related environment variable. Use one-click restore on the Settings page to roll it back.

FAQ

Codex says it cannot find the API key. What's wrong?

Codex reads the key from the environment variable named in env_key. Terminals that were already open do not see newly set environment variables, so close them and open a new one.

Why do I get model_not_found?

The group your API key belongs to does not offer that model. Pick a model again from the list AI Helper fetched from the selected node.

On macOS, why can't codex find the key when I run it in Terminal?

AI Helper only stores the key persistently in the current user's CUSTOM_OPENAI_API_KEY environment variable on Windows. On macOS it does not modify your shell profile, so add export CUSTOM_OPENAI_API_KEY="your-api-key" to ~/.zshrc (or your shell's equivalent) yourself, then open a new terminal.

Saving fails with "the active Codex profile uses another provider". What does that mean?

The top-level profile in config.toml points at a profile that uses a different model_provider. To avoid showing one configuration in the app while Codex actually runs another, AI Helper stops saving. Switch to a profile that uses custom, or remove the top-level profile setting, then save again.
