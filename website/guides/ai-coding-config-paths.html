AI 编程客户端配置文件路径与环境变量大全（Windows & macOS）

适用于 AI Helper v1.0.88 · Windows 与 macOS · 最后更新 2026-11-24 · 作者 TF49

简短回答：Claude Code 读 ~/.claude/settings.json，Codex CLI 读 ~/.codex/config.toml，WorkBuddy 读 ~/.workbuddy/models.json，DeepSeek Harness 读 ~/.dsh/profiles/desktop/cordis.patch.yml 和 ~/.dsh/.credentials.yaml。Cursor 和 Accio Work 不能直接填第三方 API，AI Helper 把它们的配置放在 ~/.ai-helper/ 下，并通过本地 Bridge（127.0.0.1:8969 / 127.0.0.1:8787）接入。Windows 上 ~ 即 C:\Users\<用户名>。

本页按 AI Helper 源码中实际读写的路径整理，适合查找配置文件位置、手动修改或排查问题。AI Helper 是 MIT 开源的本地桌面工具，下表中「AI Helper 修改 / 保留」两列说明它在你保存配置时动哪些字段、不动哪些内容。在 AI Helper 面板中，接入节点可选「BobAPI 官方节点」（https://bob-api.com/）或「TaijiAI 加速节点」（https://taijiai.online/）。

Claude Code

配置文件Windows：C:\Users\<用户名>\.claude\settings.json
macOS：/Users/<用户名>/.claude/settings.json
关键字段env.ANTHROPIC_BASE_URL（API 地址）、env.ANTHROPIC_AUTH_TOKEN（API Key）、env.ANTHROPIC_MODEL（模型）、顶层 model
AI Helper 修改只写入上面 4 项；模型为空时不写 ANTHROPIC_MODEL 和 model
AI Helper 保留其他顶层字段（如 permissions）和 env 中的其他变量。文件不是合法 JSON 对象时停止写入，不覆盖原文件
备份 / 快照每次写入前备份为 settings.json.bak；首次修改前的快照记录在 ~/.ai-helper/reset_state.json
CLI 探测位置Windows：C:\Users\<用户名>\AppData\Roaming\npm\claude.cmd；macOS：/opt/homebrew/bin、/usr/local/bin、~/.npm-global/bin、~/.local/bin、~/.bun/bin、~/.nvm/versions/node/*/bin 等

OpenAI Codex CLI

配置文件Windows：C:\Users\<用户名>\.codex\config.toml
macOS：/Users/<用户名>/.codex/config.toml
关键字段顶层 model、model_provider = "custom"；[model_providers.custom] 中的 base_url（以 /v1 结尾）和 env_key = "CUSTOM_OPENAI_API_KEY"
环境变量CUSTOM_OPENAI_API_KEY：存放 API Key。Windows 上 AI Helper 写入当前用户环境变量（注册表 HKEY_CURRENT_USER\Environment）；macOS 上不写入持久环境变量，需要自行在 shell 配置文件中 export
AI Helper 修改上述字段；custom provider 缺少 name 时补为 Custom；移除 custom provider 中的 experimental_bearer_token、env_key_instructions、auth、requires_openai_auth 以及 http_headers / env_http_headers 中的鉴权类请求头；当前活动 profile 使用 custom 且覆盖了模型时，同步更新该 profile 的 model
AI Helper 保留其他 provider、其他 profile、sandbox 与审批设置等全部内容
备份 / 快照写入前备份为 config.toml.bak；快照同时记录 config.toml 和 CUSTOM_OPENAI_API_KEY 的原值
CLI 探测位置Windows：C:\Users\<用户名>\AppData\Roaming\npm\codex.cmd；macOS：与 Claude Code 相同的目录

Cursor

AI Helper 配置~/.ai-helper/cursor_config.json：base_url、api_key、model（默认 glm-5.3）、bridge_port（默认 8969）、auto_start_bridge、custom_models、cached_models、cursor_path
Agent 工作区授权~/.ai-helper/agent_workspaces.json
本地 Bridge127.0.0.1:8969（Connect-RPC / HTTP2），被占用时依次尝试 8970–8989
客户端补丁（安装目录）Windows 默认安装目录 C:\Users\<用户名>\AppData\Local\Programs\cursor，补丁文件位于 resources\app\out\vs\workbench\workbench.desktop.main.js（或 workbench.glass.main.js）和 resources\app\product.json；macOS 为 /Applications/Cursor.app/Contents/Resources/app/ 下的同名文件。原文件备份在 resources/app/.ai-helper-backup/
状态数据库Windows：C:\Users\<用户名>\AppData\Roaming\Cursor\User\globalStorage\state.vscdb
macOS：~/Library/Application Support/Cursor/User/globalStorage/state.vscdb
AI Helper 把其中的服务地址指向 http://127.0.0.1:<端口>，修改前备份为 state.vscdb.ai-helper-bak
还原Cursor 面板「恢复官方连接」，或设置页清除配置：停止 Bridge、还原补丁与状态库，删除 cursor_config.json 和 agent_workspaces.json

WorkBuddy

配置文件Windows：C:\Users\<用户名>\.workbuddy\models.json
macOS：/Users/<用户名>/.workbuddy/models.json
兼容路径：~/.workbuddy-ai/models.json（AI Helper 同时读写两处，按模型 id 合并）
环境变量WORKBUDDY_CONFIG_DIR 或 CODEBUDDY_CONFIG_DIR：设置后 AI Helper 只读写 <该目录>/models.json
格式顶层 JSON 数组，每个元素一个模型；也接受 {"models": [ ... ]} 包装对象
关键字段id、name、vendor（Custom）、url（以 /v1 结尾）、api、apiKey、supportsToolCall、supportsImages、supportsReasoning、onlyReasoning、useCustomProtocol、reasoning、maxInputTokens、maxOutputTokens
AI Helper 修改只新增或更新当前保存的那个模型（按 id）；同名原位更新，新模型追加到末尾；一键配置把推荐模型移到首位
AI Helper 保留其他模型；同名模型的 temperature、disabled、已有的 api 值及未知字段；包装对象的其他顶层字段
备份 / 快照写入前备份为 models.json.bak；多文件写入日志 ~/.ai-helper/workbuddy-transaction.json（临时）；快照在 ~/.ai-helper/reset_state.json

详细说明见 WorkBuddy 如何配置自定义 API 与多个模型。

Accio Work

AI Helper 配置~/.ai-helper/accio_config.json：base_url、api_key、model（默认 glm-5.3）、bridge_port（默认 8787）、official_gateway、prevent_official_leak（默认 true）、fallback_official、auto_start_bridge、cached_models、image_model
本地 Bridge127.0.0.1:8787，被占用时依次尝试 8788–8807；健康检查 http://127.0.0.1:8787/health
启动时注入的环境变量Windows：GATEWAY_BASE_URL、ADK_BASE_URL、ADK_MODEL、EMBEDDING_BASE_URL、EMBEDDING_MODEL；macOS：GATEWAY_BASE_URL。网关地址形如 http://127.0.0.1:<端口>/i/<实例凭据>，只对由 AI Helper 启动的 Accio Work 进程生效
AI Helper 修改不修改 Accio Work 安装目录和其用户数据，只读取 ~/.accio/logs/sdk.log 检查网关是否生效
还原不经 AI Helper 直接启动 Accio Work 即使用官方网关；设置页清除配置会停止 Bridge 并删除 accio_config.json

详细说明见 Accio Work 如何接入第三方模型（本地 Bridge）。

DeepSeek Harness（桌面版）

配置目录默认 ~/.dsh（Windows：C:\Users\<用户名>\.dsh）；设置了环境变量 DSH_HOME 时使用该目录
路由文件~/.dsh/profiles/desktop/cordis.patch.yml：llm-pi-ai 条目下的 aihelper-claude（Anthropic Messages）、aihelper-codex（OpenAI Responses）、aihelper-cn（Chat Completions）三条路由，以及默认模型条目 agent-default-model
凭据文件~/.dsh/.credentials.yaml：refs.AIHELPER_CLAUDE_API_KEY、refs.AIHELPER_CODEX_API_KEY、refs.AIHELPER_CN_API_KEY
AI Helper 修改只管理 aihelper-* 路由和 AIHELPER_* 引用，只处理 desktop 档案
AI Helper 保留自建路由、records、注释、!!js 表达式逐字节保留；DeepSeek 官方账号和官方 API Key 路由（api.deepseek.com）不改动；与 DSH 共用写锁
安装探测Windows：C:\Users\<用户名>\AppData\Local\Programs\DeepSeek Harness\；macOS：/Applications/DeepSeek Harness.app

详细说明见 DeepSeek Harness 怎么接入 Claude、GPT 和国产模型。

ChatGPT Desktop

AI Helper 做什么安装探测、启动；不写入 ChatGPT Desktop 的任何配置。AI Helper 中标为「ChatGPT (Codex)」的面板写入的是 Codex 的 ~/.codex/config.toml，与 Codex CLI 相同
Windows 安装探测Microsoft Store 应用包；C:\Users\<用户名>\AppData\Local\Programs\ChatGPT\ChatGPT.exe；C:\Users\<用户名>\AppData\Local\ChatGPT\ChatGPT.exe；C:\Program Files\ChatGPT\ChatGPT.exe
macOS 安装探测/Applications/ChatGPT.app、~/Applications/ChatGPT.app

AI Helper 自身的文件（~/.ai-helper）

Windows：C:\Users\<用户名>\.ai-helper\；macOS：/Users/<用户名>/.ai-helper/。

文件用途
reset_state.json各客户端首次被接管前的配置快照，以及 AI Helper 最后一次写入的文件哈希，用于「清除配置」时判断整文件恢复还是只清理受管字段
cursor_config.jsonCursor 的 API 地址、Key、模型与 Bridge 端口
agent_workspaces.jsonCursor Agent 被授权写入、删除的工作区
accio_config.jsonAccio Work 的 API 地址、Key、模型与 Bridge 设置
app_paths.json在「路径管理」中手动指定的各客户端安装路径
auth_session.jsonBob API 账号登录会话；会话凭据在 Windows 上用 DPAPI 保护，在 macOS 上存入钥匙串
managed_keys.jsonAPI Key 的 SHA-256 摘要，用于限制 Bob API 账号下发的 Key 只发往允许的节点（不含明文 Key）
workbuddy-transaction.jsonWorkBuddy 多文件写入过程中的临时日志，写入完成后删除
image_budget_ledger.jsonAccio Work 生图的本地次数预算记录
cursor_config.json 和 accio_config.json 中包含明文 API Key，请不要把 .ai-helper 目录打包分享。清除配置时这两个文件会被直接删除，不保存快照。

常见问题

Windows 上路径里的 ~ 指哪个目录？

~ 指当前用户的主目录，也就是 C:\Users\<用户名>（环境变量 %USERPROFILE%）。例如 ~/.claude/settings.json 在 Windows 上就是 C:\Users\<用户名>\.claude\settings.json。这些以点开头的目录可以直接在资源管理器地址栏输入完整路径打开。

哪些客户端需要本地 Bridge？端口是多少？

Cursor 和 Accio Work 需要。Cursor 的 Bridge 默认监听 127.0.0.1:8969，Accio Work 的 Bridge 默认监听 127.0.0.1:8787。首选端口被占用时，AI Helper 会依次尝试后面 20 个端口，并把实际端口写回配置。Claude Code、Codex CLI、WorkBuddy 和 DeepSeek Harness 直接连接配置文件中写入的 API 地址，不经过 Bridge。

macOS 上 Codex 提示找不到 CUSTOM_OPENAI_API_KEY？

在 Windows 上，AI Helper 会把 Key 写入当前用户的 CUSTOM_OPENAI_API_KEY 环境变量；在 macOS 上不会写入持久的系统环境变量。请在 shell 配置文件（如 ~/.zshrc）中加入 export CUSTOM_OPENAI_API_KEY=你的 Key，然后重新打开终端。

如何把所有客户端恢复到 AI Helper 修改前的状态？

在 AI Helper 的设置 → 客户端配置 → 恢复所有客户端原生配置中点击「清除配置」。Claude Code、Codex、WorkBuddy 和 DeepSeek Harness 会按 ~/.ai-helper/reset_state.json 中的快照恢复，文件在接管后被改动过的只清理受管字段；Cursor 和 Accio Work 会停止 Bridge、删除 AI Helper 专用配置，Cursor 的客户端补丁也会被还原。
