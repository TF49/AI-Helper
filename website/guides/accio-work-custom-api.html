Accio Work 如何接入第三方模型（本地 Bridge）

适用于 AI Helper v1.0.88 · Windows 与 macOS · 最后更新 2026-11-24 · 作者 TF49

简短回答：Accio Work 桌面端通过官方网关和专有的 ADK 接口通信，设置里没有填写第三方 API 的地方。AI Helper 在本机运行一个 Bridge（默认 127.0.0.1:8787），启动 Accio Work 时把网关地址指向它，再把模型请求转换成 OpenAI / Anthropic 兼容接口，发到你在面板中选择的 BobAPI 节点。配置保存在 ~/.ai-helper/accio_config.json。

为什么需要本地 Bridge

Accio Work 的模型推理、向量嵌入和模型目录都走官方网关 https://phoenix-gw.alibaba.com 上的专有接口（例如 /api/adk/llm、/api/llm/config/v2），请求和响应格式都不是 OpenAI 格式。因此不能像 Claude Code 或 Codex 那样只改一个 Base URL。AI Helper 的做法是：

  1. 在本机回环地址启动 Bridge，默认端口 8787。
  2. 启动 Accio Work 时设置环境变量 GATEWAY_BASE_URL=http://127.0.0.1:<端口>/i/<实例凭据>，让 Accio Work 把网关请求发给 Bridge。在 Windows 上还会同时设置 ADK_BASE_URL、ADK_MODEL、EMBEDDING_BASE_URL 和 EMBEDDING_MODEL。
  3. Bridge 把 Accio Work 的请求转换后发往所选的 BobAPI 节点，再把结果转换回 Accio Work 能识别的流式格式。

Bridge 接管哪些接口

Accio Work 请求Bridge 的处理
/api/llm/config/v2（模型目录）返回当前 API Key 实际可用的模型列表（见下一节）
/api/adk/llm（模型推理）按模型名选择上游接口：名称含 claude 的走 /v1/messages；gpt、o1、o3、o4、chatgpt 开头的走 /v1/responses；其他模型（如 GLM、DeepSeek、Qwen）走 /v1/chat/completions。上游明确不支持前两种接口（如返回 404 / 501）时改用 /v1/chat/completions
/api/adk/embedding/embed（向量嵌入）转发到所配置地址的 /v1/embeddings，模型为 text-embedding-3-small
登录、团队、技能、插件、功能开关等账号与元数据接口透传给官方网关，否则 Accio Work 无法正常登录和运行
其他官方接口开启「防官方直连熔断」（默认开启）时一律阻断

模型列表是怎么注入的

Accio Work 读取模型目录时，Bridge 用所选节点和当前 Key 请求 /v1/models，把返回的模型放进一个名为 AI-Helper (<API 域名>) 的服务商下，你在面板中选择的模型排在第一位并标为默认。

  • 不会注入写死的预设模型，只显示这个 Key 真实可用的模型。
  • 模型列表在内存中缓存 5 分钟，同时写入 accio_config.json 的 cached_models；更换节点或 Key 后缓存会失效，按新 Key 重新读取。
  • 读取失败且没有缓存时，只注入你选择的那个模型，避免下拉框为空。

配置步骤

  1. 准备：安装 Accio Work；准备 Bob API 账号的 API Key（也可以登录账号后一键配置）；安装 AI Helper（下载地址）。
  2. 打开面板：启动 AI Helper，进入 Accio Work 面板。如果没有检测到安装路径，可以在设置的路径管理中手动指定。
  3. 接入节点与 API Key：选择「BobAPI 官方节点」（https://bob-api.com/，推荐首选）或备用的「TaijiAI 加速节点」（https://taijiai.online/），输入 API Key。两个节点均使用 HTTPS。手动填写的 Key 首次用于某个节点时，需点击「确认用于此节点」；从 Bob API 账号选择的 Key 和一键配置只能用于 BobAPI 官方节点。
  4. 选择模型：从读取到的模型列表中选择默认模型（例如 glm-5.3），也可以手动输入。生图模型是可选项，留空时生图功能保持关闭。
  5. Bridge 网关：本地网关端口默认 8787；「随 AI Helper 自动拉起 Bridge」和「防官方直连熔断」默认开启，建议保持。
  6. 确认并保存：勾选确认后点击「确认并保存 Accio 配置」。AI Helper 先做流式连通性测试，通过后写入 ~/.ai-helper/accio_config.json，并启动本地 Bridge。
  7. 启动 Accio Work：点击面板底部的「启动客户端」（Accio Work 已在运行时显示为「重启客户端」）。必须通过 AI Helper 启动，网关地址才会被注入。然后在 Accio Work 的模型下拉框中选择 AI-Helper 服务商下的模型。
登录 Bob API 账号后，也可以对 Accio Work 执行「一键配置」：AI Helper 使用「国产Token计划」分组（Bob API 账号下国产模型专用的令牌分组，分组说明）的 API Key，账号下没有时会自动创建，默认模型设为 glm-5.3，打开「随 AI Helper 自动拉起 Bridge」并立即启动 Bridge。不登录时，也可以在面板中手动输入 API Key。

accio_config.json 字段

文件位于 ~/.ai-helper/accio_config.json（Windows：C:\Users\<用户名>\.ai-helper\accio_config.json；macOS：/Users/<用户名>/.ai-helper/accio_config.json）。这是 AI Helper 自己的文件，不会修改 Accio Work 安装目录或其用户数据中的任何文件。

字段默认值说明
base_urlhttps://bob-api.com/上游 API 地址，即面板中所选的节点
api_key空上游 API Key
modelglm-5.3默认模型；Accio Work 未指定模型时使用
bridge_port8787Bridge 首选端口
official_gatewayhttps://phoenix-gw.alibaba.com官方网关，只允许这个地址
prevent_official_leaktrue防官方直连熔断：只透传账号与元数据接口
fallback_officialfalse面板中的「业务接口透传」开关
auto_start_bridgetrueAI Helper 启动时自动拉起 Bridge（需已填写 API Key）
cached_models / cached_models_fingerprint空模型列表缓存及其对应的地址与 Key 指纹
image_model空生图模型，留空表示不启用生图

访问控制与安全

  • 只监听本机：Bridge 只绑定 127.0.0.1，局域网其他设备无法访问。
  • 实例凭据：AI Helper 每次运行时随机生成一个实例凭据，作为路径前缀 /i/<凭据> 写进注入给 Accio Work 的网关地址。除 /health 外，没有有效凭据的请求一律返回 401。
  • Host 与 Origin 校验：Host 只接受 127.0.0.1、localhost、tauri.localhost、::1，用于防范 DNS Rebinding；来自外部网页的 Origin 和跨站（Sec-Fetch-Site: cross-site）请求返回 403。
  • 频率限制：模型推理、向量嵌入、MCP 等会产生费用的接口限制为每 60 秒 120 次，生图限制为每 60 秒 6 次，超出返回 429。
  • 官方网关隔离：开启防官方直连熔断时，模型推理不会发往官方网关；转发到官方网关的目标只允许 https://phoenix-gw.alibaba.com。
  • Key 的去向：API Key 只保存在本机的 accio_config.json 中，只发送到所选的节点。AI Helper 是 MIT 开源项目，以上逻辑都可以在源码中查看。

排错

现象原因与处理
Accio Work 仍在使用官方模型Accio Work 不是由 AI Helper 启动的，没有拿到网关地址。完全退出 Accio Work，在面板中点击「启动客户端」
返回 401「本地实例凭据无效或已过期」AI Helper 重启过，Accio Work 还带着旧凭据。点击「重启客户端」
返回「API 密钥未配置」accio_config.json 中没有 API Key，回到面板填写并保存
返回 429触发了本地频率限制（每 60 秒 120 次），稍后重试
Bridge 显示「未启动」在面板底部点击「启动 Bridge」；端口冲突时 Bridge 会自动改用 8788–8807 中的空闲端口
想确认 Bridge 是否在运行访问 http://127.0.0.1:8787/health（按实际端口），正常会返回 "ok": true 和当前模型

如何恢复 Accio Work 官方连接

不经过 AI Helper、直接启动 Accio Work，它就会使用官方网关。如果要清除 AI Helper 的 Accio 配置，在 设置 → 客户端配置 → 恢复所有客户端原生配置 中点击「清除配置」：Bridge 会停止，~/.ai-helper/accio_config.json 会被删除。因为这是 AI Helper 自己的文件，不会为它保存快照（避免多存一份明文 Key）。注意这个操作会同时处理所有客户端。

常见问题

Accio Work 报「本地实例凭据无效或已过期」怎么办？

Bridge 用一个随机生成的实例凭据校验请求，这个凭据在 AI Helper 进程运行期间不变。AI Helper 重启后会生成新凭据，之前启动的 Accio Work 仍带着旧凭据，所以被拒绝。在 AI Helper 的 Accio Work 面板点击「重启客户端」即可。

端口 8787 被占用怎么办？

Bridge 会先重试 8787，仍被占用时依次尝试 8788 到 8807，找到空闲端口后自动写回 accio_config.json，并在下次启动 Accio Work 时使用新端口。如果这 21 个端口都不可用，会提示检查是否有残留进程占用，这时可以在面板中把「本地网关端口」改成其他端口。

Accio Work 的模型下拉框里只有一个模型？

Bridge 通过所选节点的 /v1/models 接口读取当前 Key 可用的模型。如果请求失败，Bridge 只会注入你在面板中选择的那个模型，避免下拉框为空。请确认 API Key 正确、本机能访问所选节点，必要时切换到另一个节点后重新保存。

直接双击桌面图标启动 Accio Work 可以用第三方模型吗？

不行。本地网关地址是 AI Helper 在启动 Accio Work 时通过环境变量注入的，自己从桌面图标启动的 Accio Work 不会带上这些变量，会连接官方网关。请在 AI Helper 中点击「启动客户端」或「重启客户端」。

关闭 AI Helper 窗口后 Bridge 还在运行吗？

在运行。关闭主窗口后 AI Helper 会留在系统托盘，Bridge 继续工作；从托盘彻底退出 AI Helper 后 Bridge 才会停止。开启「随 AI Helper 自动拉起 Bridge」并已填写 API Key 时，下次启动 AI Helper 会自动启动 Bridge。
