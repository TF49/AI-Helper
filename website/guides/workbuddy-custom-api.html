WorkBuddy 如何配置自定义 API 与多个模型

适用于 AI Helper v1.0.88 · Windows 与 macOS · 最后更新 2026-11-24 · 作者 TF49

简短回答：WorkBuddy 的自定义模型保存在 ~/.workbuddy/models.json，文件是一个 JSON 数组，每个元素就是一个模型（id、url、apiKey 等字段）。往数组里追加记录即可同时使用多个模型。AI Helper 可以写入这些字段，并保留你已有的其他模型。

配置文件在哪里

情况路径
默认路径~/.workbuddy/models.json
WindowsC:\Users\<用户名>\.workbuddy\models.json
macOS/Users/<用户名>/.workbuddy/models.json
兼容路径（部分版本）~/.workbuddy-ai/models.json
设置了环境变量 WORKBUDDY_CONFIG_DIR 或 CODEBUDDY_CONFIG_DIR<该目录>/models.json（AI Helper 此时只读写这个文件）

没有设置上述环境变量时，AI Helper 会同时读取默认路径和兼容路径，按模型 id 合并成一个列表，保存时把同一份列表写回两个文件。

models.json 的格式与字段

文件顶层是一个 JSON 数组。AI Helper 也能读取 {"models": [ ... ]} 形式的包装对象，此时只替换 models 数组，包装对象中的其他顶层字段保持不变。每个模型记录常用的字段如下：

字段含义AI Helper 写入的值
id / name模型 ID 与显示名称，id 也是请求时使用的模型名两者都写为你选择的模型名，例如 glm-5.3
vendor服务商类型Custom
urlAPI 地址所选节点地址加 /v1，例如 https://bob-api.com/v1；开启 useCustomProtocol 时不补 /v1
api接口类型新建模型时写 openai-responses；模型原本已有该字段时保留原值
apiKey该模型使用的 API Key你填写的 Key，每个模型可以不同
supportsToolCall / supportsImages / supportsReasoning是否支持工具调用、图片输入、思考模式默认都为 true
onlyReasoning仅思考模式只在开启时写入 true
useCustomProtocol是否原样请求 url默认 false
reasoning思考强度设置：supportedEfforts、defaultEffort、canDisableThinking手动配置默认 {"supportedEfforts": ["medium"]}；canDisableThinking 只在关闭时写入 false
maxInputTokens / maxOutputTokens输入 / 输出 Token 上限手动配置默认 262144 / 32768
temperature、disabled 及其他字段WorkBuddy 或你自己设置的其他参数不写入；更新同名模型时原样保留

方法一：手动编辑 models.json

下面的示例配置了两个模型，每个模型可以使用不同的 API Key（例如不同分组的 Key）：

[
  {
    "id": "glm-5.3",
    "name": "glm-5.3",
    "vendor": "Custom",
    "url": "https://bob-api.com/v1",
    "api": "openai-responses",
    "apiKey": "你的 API Key",
    "supportsToolCall": true,
    "supportsImages": true,
    "supportsReasoning": true,
    "useCustomProtocol": false,
    "reasoning": {
      "supportedEfforts": ["medium"]
    },
    "maxInputTokens": 262144,
    "maxOutputTokens": 32768
  },
  {
    "id": "deepseek-v4.1-flash",
    "name": "deepseek-v4.1-flash",
    "vendor": "Custom",
    "url": "https://bob-api.com/v1",
    "apiKey": "另一个分组的 API Key",
    "supportsToolCall": true,
    "supportsImages": false,
    "supportsReasoning": true,
    "useCustomProtocol": false
  }
]

注意事项：

  • 每个模型的 id 要唯一。AI Helper 按 id 识别模型，同名记录会被视为同一个模型。
  • 保存后文件必须仍是合法 JSON（不能有注释和结尾多余的逗号）。文件损坏时 AI Helper 会报错并停止写入，不会覆盖原文件。
  • 如果同时存在 ~/.workbuddy-ai/models.json，建议两处保持一致，或者直接用 AI Helper 同步。

多个模型如何排序

AI Helper 把列表中第一个 vendor 为 Custom 的模型当作默认模型，面板概览中显示的「当前操作模型」就是它。建议把最常用的模型放在数组第一位，其余模型依次排在后面。

  • 普通保存：如果模型 id 已存在，就在原位置更新；如果是新模型，就追加到数组末尾，不改变已有顺序。
  • 一键配置：会把推荐模型移动到数组第一位，其他模型保留并顺延。
  • 移除模型：在 WorkBuddy 面板的「已配置模型列表」中点击某个模型的移除按钮，只删除这一条。

方法二：用 AI Helper 配置

  1. 启动 AI Helper，进入 WorkBuddy 面板。AI Helper 会读取已有的 models.json，并在「已配置模型列表」中显示所有模型。
  2. 接入节点：选择「BobAPI 官方节点」（https://bob-api.com/，推荐首选）或「TaijiAI 加速节点」（https://taijiai.online/，备用专线）。
  3. API Key：输入 Bob API 账号中的 API Key。手动填写的 Key 首次用于某个节点时，需点击「确认用于此节点」；从 Bob API 账号选择的 Key 和一键配置只能用于 BobAPI 官方节点。
  4. 配置模型：从读取到的模型列表中选择，或直接输入模型名。输入已存在的模型名会更新该模型，输入新名字则新增一个模型。
  5. 高级参数：工具调用、图片输入、思考模式、思考强度和 Token 上限都已有默认值，不确定可以保持默认。
  6. 确认配置：勾选确认后点击「确认并保存」或「确认并新增」。AI Helper 会先做一次流式连通性测试，通过后再写入 models.json。

写入时，AI Helper 会先把原文件备份为同目录下的 models.json.bak。默认路径和兼容路径两个文件作为一次整体写入：任一文件写入失败，会把两个文件都恢复到写入前的状态（写入过程的记录临时保存在 ~/.ai-helper/workbuddy-transaction.json）。

一键配置（国产Token计划 分组）

登录 Bob API 账号后，可以在工作台对 WorkBuddy 执行「一键配置」。AI Helper 会使用「国产Token计划」分组（Bob API 账号下国产模型专用的令牌分组，分组说明）的 API Key，账号下没有该分组的 Key 时会自动创建。推荐模型 glm-5.3 会被写入并移动到列表第一位，参数为：开启工具调用、图片输入和思考模式，maxInputTokens 为 262144，reasoning.canDisableThinking 为 false。你已有的其他模型都会保留。

一键配置只是方便登录 Bob API 账号的用户。不登录也可以在 WorkBuddy 面板选择节点，手动填入 API Key 和模型。AI Helper 是 MIT 开源的本地桌面工具，Key 只写入本机的 models.json，只会发送到所选的节点。

如何恢复原来的配置

AI Helper 首次修改 WorkBuddy 配置前，会把原始的 models.json（以及兼容路径下的文件）保存为快照，记录在 ~/.ai-helper/reset_state.json。在 设置 → 客户端配置 → 恢复所有客户端原生配置 中点击「清除配置」，确认框会先列出每个文件的处理方式：

  • 如果文件在 AI Helper 最后一次写入后没有被改动，整个文件恢复为首次接管前的快照。
  • 如果文件之后又被你或 WorkBuddy 修改过，只清理 AI Helper 受管的模型（vendor 为 Custom 且 url 指向 bob-api.com 相关地址的记录），其他内容保留。

注意这个操作会同时处理所有客户端（Claude Code、Codex、Cursor 等），不是只恢复 WorkBuddy。

常见问题

保存后 WorkBuddy 里看不到新模型？

AI Helper 保存后会提示 WorkBuddy 通过热重载读取新模型。如果模型列表没有刷新，请重启 WorkBuddy；同时确认 models.json 仍是合法 JSON，并且没有通过 WORKBUDDY_CONFIG_DIR 或 CODEBUDDY_CONFIG_DIR 指向了其他目录。

AI Helper 会删除我手动添加的模型吗？

不会。保存时只新增或更新当前填写的那个模型 id，其余模型原样保留；只有在 WorkBuddy 面板中点击某个模型的移除按钮，才会删除该模型。

为什么 ~/.workbuddy-ai/models.json 也被修改了？

部分 WorkBuddy 版本使用 ~/.workbuddy-ai 目录。AI Helper 会同时读取 ~/.workbuddy 和 ~/.workbuddy-ai 两处的 models.json，按模型 id 合并后，把同一份模型列表写回两个文件，避免两处配置不一致。

url 要不要带 /v1？

需要。手动编辑 models.json 时，url 一般写到 /v1（例如 https://bob-api.com/v1），并保持 useCustomProtocol 为 false。用 AI Helper 保存时，它会写入所选节点的地址并自动补齐结尾的 /v1；只有在面板中开启 useCustomProtocol 时，才按节点地址原样写入 url、不补 /v1。
