# AI-Helper 资金与凭据安全整改开工文档

编制日期：2026-10-19。基线：项目 1.0.69，当前 HEAD `f94be405`。状态：任务待认领、待实现、待验证；本文不是修复完成证明。

适用人员：客户端 Rust、前端、Bob API 服务端、测试、安全复核、发布运维。依据：[安全复核意见](FINANCIAL_SECURITY_REVIEW.md)，并追溯[原始审计报告](FINANCIAL_SECURITY_AUDIT.md)。两份报告有分歧时，以复核后的事实和本次验收规则为准；实施时重新定位代码，不依赖旧行号。

**本次目标：阻止凭据被发往非预期目标、未授权调用消耗额度、切换配置撤销既有限制，以及异常重试和并发请求产生非预期扣费。资金安全结项必须包含服务端证据，不能只以客户端编译通过或界面出现警告为依据。**

## 1. 开工范围和必须保持的规则

| 编号 | 强制规则 | 验收方式 |
| --- | --- | --- |
| R1 | 登录密码、refresh cookie、sid、API Key、本地实例凭据只能用于已授权的目标和用途；不能由继承的旧 URL 或跳转改变接收者 | 假凭据与多目标模拟服务，非授权目标收到请求数为 0 |
| R2 | 未授权 Bridge 请求不得触达任何计费上游；监听失败不能继续连接默认端口 | 跨用户、无凭据、伪造请求头及端口占用测试，上游请求数为 0 |
| R3 | 修改模型、URL、Key、分组不能静默清空用户已有权限、沙箱、IP、模型、额度或到期限制 | 修改前后差异断言，另测服务端限制实际生效 |
| R4 | 超时、取消、断连和取图失败不等于“未扣费”；本地拒绝不能通过回退重新计费 | 模拟上游受理后失败，生成/付费提交次数符合明确策略，无自动重复计费 |
| R5 | 预算检查必须覆盖并发和未决请求；所有使用同一 Key 的工具最终由服务端额度硬限约束 | 并发、重复结算、崩溃恢复和跨工具消费测试 |
| R6 | 缺签名、签名错误、版本/平台不匹配的安装包不得执行；镜像不能成为信任根 | 假镜像、旧包重放、错平台、文件替换测试，安装启动次数为 0 |
| R7 | 主动退出后不能由旧 cookie、旧文件或在途请求恢复旧账号，旧账号响应不能覆盖新账号 | 断网退出、刷新并发、账号切换和重启测试 |
| R8 | 价格、授权、计费结果或安全状态未知时，不得默认为免费、1x、未扣费、已退出或可信 | 故障注入验证各未知状态和阻断行为 |

对 R8 的执行按功能限定：不能核实费率时阻止改组；不能核实来源时阻止外发 Key；不能建立预算约束时关闭相应受管付费功能；不能确认更新可信性时停止安装。不能以“兼容模式”绕过这些规则。

本地保护不承诺隔离已经控制同一操作系统用户的恶意软件；DPAPI、实例 Token 或输入框遮盖都不能独立做到这一点。这里要落实的是可验证的来源约束、用户间隔离、最小权限、额度硬限和可靠吊销。

## 3. 研发任务及完成标准

### SEC-01｜更新包信任、版本绑定与首个安全版本

来源：原 9/10。入口：`src-tauri/src/updater.rs`、`src/components/ForceUpdateModal.tsx`、`src-tauri/tauri.conf.json`、`scripts/package-release.ps1`、发布工作流。

**实现要求**

- 接入已配置公钥的 Tauri updater 验签能力，或实现经复核的等价方案，验证对象必须是将实际执行的文件字节；SHA256 只能作完整性检查，不能替代来源认证。
- 缺签名、缺清单、缺条目、读取/计算/验证失败均停止，不得 warn 后继续。镜像只负责传输；官方返回可信“无更新”后，不允许未认证镜像用任意高版本覆盖结论。
- 将产品身份、版本、系统、架构、发布渠道与安装包摘要绑定到可验证的元数据。普通包签名不自动证明未签名 manifest 中的版本是真的；需签名 manifest 或证明所选方案可验证对应绑定。持久记录已接受的可信发布序号和最小安全版本，处理元数据过期/时钟异常，默认拒绝重放降级、同版本不同内容和错平台包；不能仅比较当前版本或普通缓存。
- 使用安全临时目录/随机文件名，校验后到执行前防止文件替换、符号链接/重解析点和并发竞争；交付该窗口的保护方式及限制，不能只校验路径字符串。无效文件不得出现在可启动列表。
- 缺签名时打包/发布步骤必须失败，不能沿用当前“只 warning”行为。新版启动前不得因更新失败自动执行旧临时包。
- 为首个修复版写升级方案：旧客户端缺少的验签能力，不能靠服务器换清单凭空补齐。提供通过可信官方渠道取得安装包并独立验证签名/发布者的路径，使用预先可信的公钥或预期发布者；不得将镜像提供的新公钥一并当作信任根。分别验证“旧版→首个修复版”和“首个修复版→后续版”，不要仅依赖旧的不安全自动更新链传播首个安全版本。

**验收 SEC-01-T**：官方无更新+镜像伪造高版本；缺签名/缺条目/坏签名；合法签名旧包重放；过期元数据/时钟异常/重启及清普通缓存后重放；错误平台/渠道；校验后替换文件；断网/代理失败；并发更新。全部非法场景安装启动次数为 0，合法已签包可正常安装。保存首个修复版的验证与升级记录。

### SEC-02｜统一凭据来源和网络出口策略

来源：N1/N3。入口：`auth.rs::apply_api_key_to_agents`、`api_test.rs`、`model_fetch.rs`、`accio/bridge.rs`、各工具配置保存及前端同步入口。

**实现要求**

- 云端取得的 Key 在应用内关联发行方、账号/Key 标识和允许的目标 origin；从可信来源建立这些关联，不按 `sk-` 前缀猜发行方。新数据结构需版本化，并给旧配置定义迁移规则。
- 保存、单工具关联、全套同步、自动刷新模型、握手测试和 Bridge 实际请求共用 Rust 端校验。UI 可以预览，但不能作为唯一校验点。解析 URL 后精确比较 scheme/host/有效端口，不用字符串前缀或相似域名判断。
- 从 Bob 账号同步的 Key 不得自动发往旧第三方地址。同步前列出每个工具最终目标；受管 Key 仅允许服务端/产品核实的发行方节点。第三方用途需单独配置对应凭据，不能把一个“确认”当成发行方已经可信。
- 远程节点仅允许 HTTPS；loopback HTTP 仅用于明确启用的本地开发场景，不能扩展为任意私网 HTTP。拒绝 URL 内 userinfo、携秘密的 query/fragment 等不支持格式，禁止关闭 TLS 证书校验。
- 登录、刷新、付费 API、模型列表等带凭据请求默认不跟随跳转；确有必要的跳转只能采用明确的 HTTPS 同源策略。覆盖 `Authorization`、`x-api-key`、Cookie、`X-Auth-Session` 和请求体里的密码，不能依赖库仅剥离标准头。
- 校验通过前不得写新 Key、发起后台刷新或切换运行中 Bridge；批量执行返回逐工具结果，失败不能更新为成功绑定。

**验收 SEC-02-T**：旧第三方 URL 后全套同步；自动模型刷新；不同 host/port、HTTPS→HTTP、301/302/307/308；相似域名、userinfo、混合大小写/编码、本地开发模式。非授权目标请求数为 0；上游、日志和错误中均无本地实例凭据。

### SEC-03｜切组只改组，不动原有防护

来源：原 6。入口：`auth.rs::update_user_token_group`、服务端 Token 更新接口。

**实现要求**

- 删除“完整详情失败→从列表重建完整 Token”的写入降级。完整原配置无法取得时终止修改，不能生成安全字段默认值。
- 优先由服务端提供只更新 group 的接口；这是待确认/新增的契约，不假设当前 PATCH 已存在。若必须 PUT，先确认缺字段语义并使用版本号/条件更新等并发保护，禁止覆盖另一端新改的限额或白名单。
- 保留模型/IP/额度/过期、跨组重试等全部非本操作字段。成功后读取权威状态；更新成功但刷新失败显示“修改已提交，状态待确认”，不自动再写一次。

**验收 SEC-03-T**：详情 GET 的 403/500/超时/坏 JSON、列表仍成功时，不得提交修改；正常切组前后仅 group 有预期变化；并发调整额度/IP 不被覆盖；服务端实际拒绝被禁止模型、IP 和过期 Key。

### SEC-04｜保留 CLI 安全规则，正确报告批量结果

来源：N2、原 7。入口：`claude.rs`、`codex.rs`、`workbuddy.rs`、`ChannelGroupMonitor.tsx`、`TokenSelectModal.tsx`。

**实现要求**

- 从现有配置解析后仅更新本功能管理的 URL、Key 引用和模型字段。保留 Claude permissions/sandbox/hooks、Codex 其他 provider 和安全配置、WorkBuddy 未操作的模型及未知字段。
- 解析失败停止写入；不得将损坏配置当空对象，不先删原文件再重建。备份按 SEC-09 保护，写入采用安全原子替换及并发版本检查。
- 全套同步先完成目标和写入计划检查，再执行；不能宣称多个文件/工具天然具有跨文件原子性。记录逐工具结果和已提交状态，提供安全恢复路径，禁止静默 catch 后广播全部成功。
- 只对实际成功工具更新绑定、广播刷新。修改云端同一 Key 的 group 时，提示其所有使用者受影响；“不同步”不能被解释为其他共用 Key 的工具不受影响。

**验收 SEC-04-T**：含安全规则/未知字段/多 provider 的配置保存后完整保留；坏配置、磁盘满、权限失败、并发写入时原文件不损坏；部分同步失败时，磁盘、界面和绑定记录一致，失败工具未标记成功。

### SEC-05｜Bridge 鉴权与可靠启动，先验证外部客户端兼容性

来源：原 1、N8。入口：`accio/bridge.rs`、`process_manager.rs`、Accio 启动适配。

**实现要求**

- 先交付兼容性验证：用假 Key 和本地模拟服务，记录受支持 Accio Windows/macOS 版本的 LLM、embedding、MCP 和其他网关请求，验证能否稳定附带实例凭据。仅注入 `GATEWAY_AUTH_TOKEN` 环境变量不算实现，也不能假设第三方客户端会识别它。
- 能支持时使用安全随机实例凭据，绑定本次启动生命周期，仅在必要进程/内存传递，不放 URL、日志、持久配置或无关子进程环境。优先独立头，保留原业务 Authorization/Cookie，在任何上游转发前剥离本地凭据。
- 所有触达保存 Key、计费或敏感数据的路由都在读取大请求体/调用上游之前认证，包括备用路由和 fallback。预检/健康检查不得触发业务；Origin/Host 检查作为附加保护保留。
- 如果 Accio 无法支持所需认证，先给出可运行的适配方案；方案未验收前禁用对应受管计费通道，不得保留无鉴权“兼容放行”。单凭本地 Token 不能证明服务端身份。
- 只有成功持有监听且实例就绪后才启动客户端。删除 `unwrap_or(8787)`，处理过期 running 状态、并发启动、异常退出及凭据失效；不能靠陌生端口 `/health` 返回成功确认实例归属。

**验收 SEC-05-T**：合法 Accio 全链路正常；无/错/旧凭据、伪造 Origin、其他本地用户均不能调用计费服务；默认 8787..8807 全占用、自定义范围占用且假服务监听 8787、实例启动即退出时，不把请求送到假服务。记录上游请求计数与支持版本矩阵。

### SEC-06｜付费请求状态机和防重复计费

来源：原 2、N6。入口：`accio/bridge.rs`、相关前端请求状态，服务端幂等/查询能力。

**实现要求**

- 明确区分：本地拒绝、明确未发送/未受理、已受理、已完成、结果和计费未知。超时、取消、5xx、解析失败、断流不能自动归为未扣费。
- 策略拒绝、鉴权失败、参数错误、限流不得 fallback；对已受理或结果未知的逻辑操作，不自动跨供应商重发。明确未受理且协议允许的重试也需有限次数、同一操作标识和可审计结果。
- 生图生成与取图分开：生成成功后保存受保护的结果引用；取图失败只重取允许的原结果，不重新生成。不要只按相同 prompt 去重，用户可以合法生成相同内容多次。
- 以逻辑操作 ID、账号/Key 标识、目标、模型和参数摘要处理重复点击、并发和恢复；供应商确实支持时才能使用其幂等能力，不能假设跨供应商幂等。
- 界面明确显示“结果/扣费待确认”。用户明确发起新一笔生成时提示可能再次收费；取消只能表示本地停止等待，除非有上游证据证明取消并未计费。

**验收 SEC-06-T**：开启官方回退时第 7 次生图本地拒绝，第二上游调用数为 0；上游受理后超时/坏 JSON/取图失败，生成总次数保持 1；重复提交同一操作、跨窗口提交、重启恢复不重做；新操作可独立提交。

### SEC-07｜消费限制、并发预算和未决金额

来源：原 2/3/4、N10。入口：`accio/bridge.rs`、`accio/protocol.rs`、配置/设置 UI，服务端额度接口。

**实现要求**

- 区分默认模型与允许模型；Rust 后端验证模型、输入/输出 Token、图片模型/数量/尺寸及并发上限。拒绝负数、非整数、非法值、超范围配置；模型列表不作为授权证明。
- 生图模型与预算显式配置，未配置/无法取得可信价格和服务端限额时不启用对应受管生图功能，不静默固定到昂贵模型。预算和默认上限由产品/服务端填入交付策略表，禁止带空白/无限默认值发布。
- 受管 Key 必须有经服务端验证的有限额度、有效期及所需模型范围。不能给其他 CLI 建立本地请求计数就声称账户全局预算已受控；跨 CLI 和外部消费由 SEC-12 的服务端硬限兜底。
- 实现金额预留时，使用平台最小计费单位的整数/定点数，不用浮点累计余额。价格必须记录来源、版本、单位、费率和有效期；估算无法构成可信费用上界时，不称为金额硬限。
- 发出请求前原子检查 `已结算 + 未决预留 + 本次预留 <= 预算`。只有预留成功才发请求。结果未知保持预留，明确未发送/确认未计费才释放；结算及释放都幂等。
- 崩溃重启、跨日和多进程不能清掉未决占用；若额度上界受跨进程并发影响，需共享原子状态或只允许一个拥有者。实际费用超出预留要计入并停止后续消费，不得丢弃差额。

**验收 SEC-07-T**：预算只够一单，20 个并发请求最多一单到达上游；超时/取消/跨日/崩溃后预留仍在；重复结算不重复释放；改昂贵模型、超大 Token、未知价格均按策略阻断；验证所有受管工具的服务端额度边界。

### SEC-08｜统一费率确认、可用分组和账务展示

来源：原 5/7/8/15、N7。入口：`ChannelGroupMonitor.tsx`、`auth/TokenSelectModal.tsx`、`auth.rs::get_pricing_data`、`get_user_available_groups`、余额和日志展示。

**实现要求**

- 所有改组入口共用一个流程；获取服务端可用分组、规范标识、当前及目标费率和权威版本，展示影响范围后提交。不得另留直调更新的旁路；Rust/服务端不能仅信任前端“已确认”布尔值。
- 删除未知费率 `?? 1.0`、未知分组硬编码加入列表等放行方式。缺数据、过期、非有限数值、非法比例及大小写歧义均阻止改组并可重试；合法零费率是否支持由服务端契约明确，不能自己猜。
- 只采用服务端规定的大小写规则；不能把 `VIP`/`vip` 强行合并。所有 `>1x` 切换展示真实费率，`>=2x` 显式确认；该门槛延续现有产品规则，新增门槛需版本化。
- 费率或授权在确认后变化时要求重新获取/确认；需要服务端报价版本或等价原子校验。短期无法实现的，不得宣称杜绝报价与执行间的变化。
- 用平台权威额度换算配置显示余额/日志，明确平台额度与真实货币，避免自行套现实外汇。无有效配置时显示原始额度及“换算不可用”，不得硬编码成另一种确定金额。

**验收 SEC-08-T**：两个编辑入口同样受控；接口失败/空表/过期/歧义/非法比例均不提交；1x/高倍率/合法免费策略符合契约；确认后费率变化重新确认；无权分组服务端拒绝；更改兑换配置后余额与日志口径一致。

### SEC-09｜凭据存储、权限和迁移

来源：原 12/13、N4。入口：`auth.rs`、`claude.rs`、`codex.rs`、`workbuddy.rs`、`accio/config.rs`、`lib.rs` 及缓存写回。

**实现要求**

- 建立存储清单：会话 JSON、Claude 配置/备份、Codex 注册表及环境、WorkBuddy 兼容目录、Accio 配置及缓存、临时文件/诊断导出。为每处写明用途、读取主体、保留期限和清理责任。
- 应用会话使用 Windows 用户范围 DPAPI/Credential Manager；其他发布平台选择对应用户凭据存储。不可用时不能无提示退回明文长期会话；选择不持久化/重新登录等安全降级。
- Unix 文件创建时 0600、目录 0700；Windows 当前用户 ACL。原子替换、备份、迁移及既有文件不扩大读取权限，处理符号链接/重解析点和错误路径。不得仅先写明文再 chmod。
- 第三方 CLI 必须读明文的配置，不能直接加密到它无法识别；缩小副本、目录权限和保留期限。采用 CLI 实际支持的凭据库、helper、专用启动器或受限配置，分别验证 AI-Helper 启动及用户独立终端启动后，再迁移/移除现有全局环境项。需要时仅向目标 CLI 子进程注入；无法兼容的启动路径须明确调整支持范围，不能静默破坏独立启动或影响其他工具。
- `cached_models_fingerprint` 改为不含原文的摘要/键控摘要，审查所有写入路径并清除旧值；换 Key 后缓存正确失效。禁止只改函数名或只脱敏 `api_key` 字段。
- 迁移遵循“新存储写入→读回验证→切换→清理本应用管理的旧副本”，带版本和可恢复状态。备份同样保护，不再新增明文秘密备份；未成功迁移不能删除唯一有效凭据。清理失败可见，不能假装完成。
- 不自动吊销用户所有 Key、不删除非本应用管理的资料；提供旧 Key 在服务端撤销/轮换的独立指引。删除本地副本不代表云端吊销，也不承诺抹除 SSD/备份历史中的全部副本。

**验收 SEC-09-T**：全新安装和旧版升级；umask 022；其他 OS 用户读取；旧原文指纹；多兼容目录；凭据库不可用/权限失败/磁盘满/中途退出/重复迁移；CLI 仍能正常读取预期凭据。证据中只使用假 Key。

### SEC-10｜主动登出、并发刷新和账号切换

来源：N5。入口：`auth.rs::logout/refresh_session/ensure_access_token`、`src/lib/useAuth.tsx`、绑定/模型缓存。

**实现要求**

- 主动登出立即进入禁止自动刷新状态，清 CookieJar、access token、sid、磁盘会话及账号相关前端缓存，必要时重建 client。不能只清 is_logged_in 或只删文件。
- 引入会话代次或等价机制，使登出前的刷新、余额、Token 列表和模型请求即使随后返回，也不能重新落盘/恢复旧账号或覆盖新账号。切换账号必须隔离缓存、绑定及在途任务。
- 区分“本地已退出”和“远程吊销未确认”，检查服务端状态及本地删除结果；网络失败时不显示远程已吊销。不得持久保留可复活旧会话的凭据仅用于无限重试。
- 对跨重启恢复增加可持久验证的主动登出标记/会话代次。启动时先验证该状态及存储健康；无法可靠验证时禁止自动恢复。旧会话清理及持久阻断都失败时必须报告“本地退出未完成”，不能仅用内存状态显示成功。
- API Key 从 CLI 清理作为独立明确操作，不能把退出账号偷偷变成删除全部工具配置；登出后界面也不能继续展示缓存的其他账号明文 Key。

**验收 SEC-10-T**：断网/5xx/文件删不掉；旧会话文件仍存在而应用重启并恢复网络；刷新与登出同时发生；A 退出后立刻登录 B；旧响应延迟返回。旧账号不能恢复，新账号数据不被污染，持久阻断失败不得显示本地退出完成；服务端吊销另由 SEC-11 验证。

### SEC-11｜服务端认证、会话与 Token 对象授权

本仓库不含服务端实现。本项必须由对应服务端负责人认领，输出实际接口契约和测试证据；不能因客户端缺代码而标为通过。

**实现/核验要求**

- 密码采用合适的慢哈希及参数，不明文存储/日志；登录、2FA、验证码与恢复入口有服务端限速和校验，不能仅依赖 UI。
- 确认 access/refresh 生命周期、refresh 轮换与重放处理、sid 是否必需、退出/改密后的失效范围，测试客户端现行行为与之匹配。
- 按 Token ID 取明文、改组、改额度/模型/IP 等操作必须校验当前账号对该对象和动作的权限；管理功能也要服务端授权。
- 提供允许分组/节点/模型、费率版本、额度配置等真实契约；清楚定义 PATCH/PUT 字段缺失和并发更新语义，供 SEC-02/03/08 使用。

**验收 SEC-11-T**：A 账号读取/修改 B 的 Token 被拒绝且无状态变化；普通用户管理接口被拒绝；无权分组/模型/IP 被拒绝；缺 2FA/重放 flow/错误 sid/旧 refresh/注销后刷新符合已确认策略。使用隔离测试账号，交付接口/服务版本及脱敏请求结果。

### SEC-12｜服务端额度硬限、并发记账与充值核验

此项是资金安全的最终依赖。本地限频或预算估算不能替代服务端实现。

**实现/核验要求**

- 按账号/Key 实施有限额度、模型/IP/过期限制；并发请求、重试、切组、跨工具、多个节点不得绕过。定义余额/预扣/未决/结算/退款的状态及原子更新方式。
- 流式中断、上游超时和实际 usage 迟到时不提前释放可再次花费的额度；请求结算和退款必须幂等。明确定义单笔费用上界和预扣不足处理，不能在账面隐藏超支。
- 用最小计费单位整数/定点数核算，服务端定价和费率版本为权威；保证不同日志、余额及计费接口可对账。
- 对有充值/退款业务的平台，验证回调签名、商户/订单/金额/币种/状态、重放防护和幂等；异步回调、查询补单、人工补单不重复入账。拒绝负数、溢出及金额精度异常。
- 如果本次关联服务确实没有某类支付业务，服务端负责人提供路由/业务清单证明并标记“不适用”；不能把“客户端只是打开网页”当作支付核验通过。

**验收 SEC-12-T**：余额只够一单时，从多个 CLI/节点同时请求，接受数量和实际消费不超已定义边界；重复 usage/退款/充值回调只结算一次；错误签名/金额/币种/订单无状态变化；超时、跨日、重启、切组不恢复未决额度。交付前后余额、订单/请求状态及计费台账核对结果。

### SEC-13｜图片 URL、内网访问与流式大小限制

来源：N9。入口：`accio/bridge.rs` 图片生成、取图及上游响应读取；通用下载辅助代码。

**实现要求**

- 图片下载使用独立的最小权限 client，不继承 API Key、Cookie 或本地实例凭据。仅允许明确可信 HTTPS 图片源，逐次验证解析地址与跳转；防 loopback、私网、link-local、IPv6/映射地址、编码地址和 DNS 重新解析绕过。
- 将地址验证与实际连接绑定，不能校验一个 IP 后又无约束解析连接另一个 IP。企业私有图片服务如确需支持，使用单独授权范围，不开放任意内网。
- 读取时累计解压后字节上限，达到即停止；Content-Length 只能辅助，不可代替真实读取限制。覆盖 JSON、二进制、chunked 和自动解压响应。
- 验证状态码、MIME、图片文件格式和必要尺寸/像素上限，不把任意响应强行标作 PNG；下载失败按 SEC-06 处理，不重新生成。

**验收 SEC-13-T**：127.0.0.1、私网、link-local、IPv6、跨域/内网跳转、DNS 变化、无限流/压缩大响应、错误 MIME 和假图片。受限目标未被访问，内存使用受测试阈值约束，无实例凭据或 Key 出现在图片服务。

### SEC-14｜安装包发布者及高权限 IPC

来源：原 14/16/17、N12。入口：`auth/LoginModal.tsx`、`auth/TokenSelectModal.tsx`、`ApiKeyInput.tsx`、`api_test.rs`、日志与排障导出。

## 4. 开工前必须落地的接口与策略表

下表是本次需要确认/新增的契约，**不是当前已存在的 API 清单**。相关研发可以并行开工，但消费、切组、同步等功能在依赖项未通过前不能验收为已安全。

| 契约 | 负责人角色 | 必填内容 | 未具备时的行为 |
| --- | --- | --- | --- |
| 凭据发行方及允许节点 | 服务端、客户端 | 可信来源、origin 列表、变更和迁移方式 | 不向未核实地址外发受管 Key |
| Token 修改与并发控制 | 服务端 | group 更新方式、缺字段语义、对象授权、版本冲突 | 完整详情/契约不足则不改组 |
| 可用分组与权威费率 | 服务端、产品 | 规范 ID、大小写规则、费率单位/版本/有效期、免费策略 | 禁止未知费率/授权状态下切组 |

## 5. 测试执行和交付证据

### 5.1 测试原则

- 自动化优先使用假 Key、本地模拟服务和隔离临时配置，不读写研发人员真实主目录/注册表凭据，不发生产付费请求。HTTPS/跨 origin 用隔离测试证书及模拟环境，不为测试在生产代码关闭证书验证。
- 同时记录“上游收到多少次请求”“安全字段发生什么变化”“余额/预留如何变动”；只检查错误文案不足以证明未扣费。
- 服务端联调用隔离测试账号和测试订单；必要的真实计费验证单独限定 Key、模型和有限预算，由对应业务流程安排，不使用个人无限额 Key 做回归。
- Windows 覆盖当前用户/其他普通用户、注册表、ACL、安装器；macOS/Linux 按实际发布范围验证凭据存储、文件权限、启动和迁移。未发布平台由负责人列明，不得对未测平台宣称通过。
- 基于真实风险写负向和并发测试，不以逐行镜像实现的测试取代系统行为验证。

## 6. 发布门槛、迁移和故障处理

### 6.1 完整整改版发布门槛

- [ ] SEC-01—SEC-17 的所有适用任务有负责人、变更和验收记录；未决项没有被写成已完成。
- [ ] R1—R8 在成品构建上验证；未授权目标/调用者的付费上游请求数为 0。
- [ ] 服务端 SEC-11/12 有对象授权、会话吊销、并发额度与账务幂等证据；仅客户端截图不能替代。
- [ ] 旧版用户的会话/配置/缓存/备份迁移及失败恢复通过，安全规则不丢失，工具可用。
- [ ] 产物实际验签、版本平台绑定、首个安全版本升级、发布物一致性通过；签名失败不执行、不发 latest。
- [ ] 预算/重试测试覆盖并发、超时、取消、崩溃恢复；无未经授权的无限额默认 Key 或自动跨服务商补单。
- [ ] 日志、诊断包、安装产物和仓库扫描无应移除的真实秘密；公开 Webhook 的撤销有运维记录。
- [ ] 当前构建检查、平台回归和安全负向用例全部通过；高风险依赖漏洞有修复或明确隔离证据。
- [ ] 发布负责人、测试负责人和安全复核人依据证据记录放行结论；平台/功能不适用项有说明。

任一资金/凭据关键验收失败，则修复或关闭受影响功能，不能增加“继续使用不安全模式”来绕过门槛。紧急封堵版可以先交付已验证的止损修复，但必须明确未完成项、限制剩余风险功能，不能作为本次完整整改已结项。

### 6.2 迁移和发布步骤

1. 在测试环境生成受保护的旧版样本配置、有限额测试 Key、未决请求与账务样本，验证升级及幂等恢复。
2. 发布前确认新接口和受管 Key 策略就绪；服务不可用时采用表中规定的安全阻断，不默认为旧策略。
3. 在可信发布路径产出新版本、包/签名/元数据并核对，按 SEC-01 提供首个修复版取得方式；不覆盖同版本文件。
4. 使用可控测试账号/设备分批验证升级，先验证拒绝场景，再启用受管付费功能；以操作 ID 对账，不记录原始 Key。
5. 按任务证据检查迁移失败、外发拒绝、未决计费、额度拒绝、签名失败、退出清理和余额差异；发现异常暂停相关功能并保留脱敏诊断证据。
6. 运行稳定后扩大分发；完整门槛全部满足后，才记录本轮整改完成。

### 6.3 恢复规则

- 应用恢复不能重新启用无鉴权 Bridge、无签名更新、清空限制的分组降级或不受控跨供应商重试。
- 旧版本无法读取新凭据存储时，允许重新登录/重新配置；不得为了降级兼容重新导出明文 refresh cookie。
- 配置恢复仅使用经过保护的必要备份，保留安全策略和权限，不重引入已撤销 Key；云端策略和账务不随客户端版本回退。
- 未决计费和预留跨版本保留/核对，不能因安装旧版本清零；若旧版不能安全识别该状态，禁止恢复至该版，或先由仍可实施约束的服务端/受控网关禁用或撤销对应 Key，再执行经核实的恢复方案。不能指望旧程序执行新增的停用逻辑；任何 Key 撤销须明确对象及业务影响。
- 恢复功能优先发布具有可信签名的新版本；确需显式降级时，必须由独立可验证的签名授权限定产品、目标版本、平台、渠道及有效范围，继续满足持久最小安全版本要求。普通前端参数、清缓存或镜像响应不得降低安全下限。
