## 固定的验证入口

```powershell
pnpm test:security
pnpm test:workflows
./scripts/verify-improvements.ps1
```

CI 的 Unix 原生服务通过 `scripts/test-native-credentials.sh` 创建临时用户 Keychain 或私有 D-Bus/Secret Service，只使用合成值。真实 DMG 回归通过 `scripts/test-macos-release-artifacts.mjs` 运行。脚本和生产验证器均留在仓库，开发人员可审查具体行为。

工作流契约会拒绝删掉关键回归、缩减 Unix 库过滤、丢失签名 env、浮动 action tag、重复 tag 发布入口、破坏构建门控或增加覆盖资产命令。更改安全存储和发布方案时，应连同对应失败反例和正常使用证据一起审查。

## 仍需明确的边界

- 普通文件系统没有多文件原子提交，也没有对不遵锁外部写者的通用 compare-and-swap；版本检查与最终替换之间仍有竞争窗。当前修复保证检测到的第三方版本不被恢复快照静默覆盖，不声称强制所有外部程序遵守锁。
- 原生凭据测试验证 Rust 与系统服务及实际会话提交链，不等于已签名安装成品的所有系统授权交互。DMG 回归验证真实格式、更新签名和验签，不代表 Apple 生产签名、公证、产品安装、旧版升级或实际 Accio 协议已验证。
- 第三方 CLI 配置和受保护备份仍含其必须读取的明文 Key；应用会话由系统凭据服务保护。旧全局环境项不自动删除，避免破坏用户其他旧启动方式。
- 服务端对象授权、撤销、group-only 契约、报价、并发金额硬限和幂等记账，及运维旧凭据撤销，继续按用户要求保留 TODO。这些不能通过客户端测试宣称完成。
