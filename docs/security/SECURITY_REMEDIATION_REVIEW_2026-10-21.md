## 1. 本轮确认的问题

### S01 · P1 · Windows 文件替换保留旧 DACL，写入后的新凭据仍可能被其他用户读取

位置：`src-tauri/src/safe_fs.rs:108`；临时文件限权在 `82`。

新实现先给临时文件限权，但随后使用 `ReplaceFileW` 替换已有正式文件。该 API 保留旧正式文件的 DACL。因此，升级前存在宽松权限的配置或会话文件，写入新内容后仍可能保留旧读取权限。备份权限收紧也不能修正正式文件的权限。

本地隔离测试使用假配置直接调用与实现一致的 WinAPI，结果为：

```text
旧正式文件允许 Everyone 读取：True
新临时文件允许 Everyone 读取：False
ReplaceFileW 成功：True
替换后正式文件允许 Everyone 读取：True
替换后内容：新的假 Key
```

这与 [Microsoft 对 ReplaceFileW 保留原文件 DACL 的说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)一致。

建议：在受控事务中处理旧正式文件的安全描述符，确保最终文件权限符合目标；验证最终文件及备份，而非只检查临时文件。另外，创建时即应设置受限权限，避免空文件阶段取得的外部句柄绕过后续限权。

### S02 · P1 · 自带 Key 的来源登记没有可达入口，正常保存、模型发现和测试被整体阻断

位置：`src-tauri/src/credential_policy.rs:79`、`104`；调用包括 `codex.rs:206`、`model_fetch.rs:42`、`api_test.rs:19`。

Unknown 不再被当成 BYOK 放行，这是正确修复。但 `register_external_key()` 在当前仓库只有定义，没有调用者，也没有对应 IPC/UI。用户手填第三方 Key、从旧配置读取未登记 Key，甚至手填尚未从账号接口重新取得的 Bob Key，都会被分类为 Unknown，无法正常保存、发现模型或测试。

错误提示要求“重新关联并保存”，但保存本身先被拒绝，用户没有完成来源确认的正常路径。旧 HashSet 文件格式兼容不能代表旧版实际工具配置已完成来源迁移。

建议：提供显式、可验证的自带凭据确认流程及旧配置迁移；保持 Managed 分类优先，不能为恢复可用性而把所有 Unknown 自动当成 External。

### S03 · P1 · 文件锁在崩溃后永久残留，预算故障还会阻断整个 Bridge

位置：`src-tauri/src/paid_request.rs:80`、`90`；`src-tauri/src/safe_fs.rs:19`、`26`；`src-tauri/src/accio/bridge.rs:601`。

两类锁均通过 `create_new` 创建哨兵文件，只在闭包正常结束后删除。进程崩溃、强制退出或 panic 后，文件继续存在，没有存活校验或安全恢复机制。预算锁重试 100 次仍失败；普通配置锁则立即拒绝后续保存。操作系统关闭文件句柄不会删除普通文件。

隔离测试在临时目录创建同语义的排他文件后让子进程异常退出，确认文件残留，随后 100×10ms 重试全部失败。本测试验证文件锁协议，未执行 Rust 二进制。

Bridge 启动又无条件执行 `reset_image_budget(...)?`，即使生图预算默认是 0、用户仅用文本也一样。预算锁残留、坏账本或账本写入失败，都会阻止整个 Bridge 启动，扩大到文本和 embedding 功能。

建议：使用随进程终止自动释放的操作系统锁；覆盖 panic 和异常退出。预算故障限制生图通道并保留未决账本，其他无关功能应保持可用。不能简单删除仍被活进程使用的锁文件。

### S04 · P1 · macOS 清单改用 tar.gz，但客户端仍按 DMG 打开

位置：`scripts/finalize-update-manifest.ps1:31`；`src-tauri/src/update_trust.rs:552`；`src-tauri/src/updater.rs:895`。

本轮打包和清单汇总已经可以生成 Darwin 条目，地址指向 `.app.tar.gz`。客户端却仍将 Darwin 下载内容保存为 `payload.dmg`，只执行 `open` 后退出，没有安装 tar.gz 中 `.app` 的流程。

即使清单和包验签成功，格式与安装动作也不匹配，不能完成当前自定义更新流程。此项是打包成功后仍存在的客户端安装阻断。

建议：接入与 tar.gz 产物匹配的 Tauri 安装能力，或显式签署 DMG 并保持完整一致的 DMG 安装流程。用真实成品完成 macOS 升级成功路径验证。

### S05 · P2 · 备份恢复太晚，恢复出的安全配置随即被空基底覆盖

位置：`src-tauri/src/claude.rs:181`、`194`；`src-tauri/src/codex.rs:222`、`234`；`src-tauri/src/safe_fs.rs:174`、`183`。

正式文件缺失但 `.bak` 存在时，调用方先按空配置构建新内容；进入安全写入函数后才恢复旧备份，随后立即用已经生成的新内容覆盖恢复结果。

例如 `settings.json` 缺失，备份含 permissions/sandbox/hooks，下一次保存仍会丢失这些字段。新增文件锁也只包住最后写入，没有保护“恢复→读取→合并→提交”的完整事务。

建议：把恢复和读取移动到合并之前，并将完整读改写事务置于同一锁内，覆盖缺正式文件但有备份、多写者并发修改的场景。

### S06 · P2 · 清空生图模型后保存会恢复旧值，无法按界面承诺关闭生图

位置：`src-tauri/src/lib.rs:275`；`src/components/AccioWorkPanel.tsx:427`。

UI 已支持编辑 `image_model`，并说明“未填写时生图保持关闭”。但后端把任何空字符串都当成旧 UI 漏字段，自动恢复已保存的模型。已经启用生图的用户清空并保存，会收到成功结果，原付费模型却继续有效。

建议：用可选输入字段区分“未传字段”和“显式空串”；只有未传字段才保留，显式空串必须关闭。验证启用→清空→保存→读取→实际调用被阻断的完整行为。

### S07 · P2 · 最终清单重新签署后，SHA256SUMS 仍包含旧清单和旧签名的哈希

位置：`scripts/finalize-update-manifest.ps1:40`、`44`；`scripts/package-release.ps1:99`。

Windows 打包先生成清单、签名和 SHA256SUMS；finalizer 随后覆写清单和签名，没有重建校验文件。隔离执行原始 finalizer，提供三平台假资产并模拟 signer 后，旧 SHA256SUMS 对清单及签名的校验均失败。新增 macOS 资产也没有统一校验条目。

建议：所有平台资产汇总、最终清单签名完成后，统一生成最终 SHA256SUMS，并实际执行整份哈希校验。此处没有发现因此绕过 minisign 的路径，但发布物自校验与手动验证会失败。

### S08 · P2 · 只给“揭示 Key”补了代次校验，“复制 Key”仍可在关闭后回填明文

位置：`src/components/auth/TokenSelectModal.tsx:375`、`376`；对比已修复的 `400`。

`handleToggleReveal` 新增代次校验有效，但 `handleCopyKey` 仍在 `await getTokenKey()` 后无条件恢复明文缓存并写剪贴板。关闭弹窗/账号变化时清空缓存和增加代次，不能阻止这一路旧请求回填。

实际执行该源码片段：先开始复制请求，模拟关闭并清空状态，再返回假 Key，最终缓存重新出现 Key，剪贴板写入一次。

建议：对复制、选择、全套同步、令牌列表、费率加载等异步路径使用一致的窗口/账号代次，在结果产生副作用前核验；不能只保护一个揭示按钮。

### S09 · P2 · 钱包 callback 未依赖用户 ID，直接换账号后仍捕获旧 ID

位置：`src/lib/useAuth.tsx:94`、`99`、`124`。

新增保护从 callback 闭包读取 `authState.user.id`，但依赖数组仍只有登录布尔值和 `refreshState`。登录状态保持 true 而用户 ID 从 A 变为 B 时，React 复用旧 callback；请求结果按旧 A 与当前 B 比较，连 B 的合法钱包响应也被丢弃。

用源码 callback 和等价依赖缓存模拟两次渲染，确认复用旧函数，B 的合法响应没有触发 `setWallet`。这是 hook 依赖模拟验证，未运行完整 React 挂载测试。通过完整退出再登录会改变布尔值，不属于这一触发场景。

建议：加入用户 ID/会话代次依赖，或使用明确的当前身份引用；所有 await 后的成功、错误和 finally 更新都核对请求代次。

### S10 · P2 / 既有遗漏 · 另一个改组入口仍使用失效的旧费率

位置：`src/components/ChannelGroupMonitor.tsx:375`、`380`、`514`。

Token 弹窗已补齐未知、过期费率阻断，但监控组件未做同等修复。定价刷新失败时保留旧 `pricingInfo`，提交只检查它是不是有限数值，没有有效期或刷新失败状态。

在已加载低倍率后，后续定价失效/不可取得的场景，模拟旧倍率并执行当前提交函数仍调用一次改组接口。此项在本次提交前已存在，但本轮要求“统一两个入口”的目标仍未完成。

建议：共用费率有效性和确认策略，刷新失败使相应数据失效，账号变化清理缓存；禁止凭失效缓存确认实际费用。
