## 🧰 Claude Messages：工具调用链路补全 🧠🔗

Claude 模型现在通过 Anthropic Messages 协议与上游交互，减少 OpenAI 消息格式与 Anthropic 工具格式之间的错位 🧩。请求会使用 Messages 端点及对应的认证头，工具定义转换为 Anthropic `input_schema`，流式响应则按内容块顺序解析 📡⚙️。

- 📨 **请求格式正确转换**：处理 system、assistant、user、tool 等消息，并合并连续的同角色消息
- 🧩 **工具定义符合 Anthropic 结构**：项目文件工具使用 `input_schema` 描述参数，工具结果以 `tool_result` 返回
- 🖼️ **多模态内容保持可用**：支持将常见图片输入转换为 Anthropic 图片内容块
- 🌊 **流式内容按序处理**：解析文本、工具参数、思考块、签名块与结束原因
- 🔁 **多轮上下文不丢信息**：工具执行后将调用和结果放回下一轮请求，延续原有签名与内容块

> 💡 现在 Claude 可以沿着“读取文件 → 执行工具 → 查看结果 → 继续回答”的完整路径工作 📖➡️🛠️➡️🔍➡️💬

## 🆔 工具调用 ID：严格配对，不再混类型 🔗🛡️

部分兼容接口会返回数字型、空值或重复的 `tool_use.id`，导致后续 Messages 请求出现 `Input should be a valid string` 等 400 错误 ❌📨。v1.0.84 会在进入下一轮请求前修正工具 ID，并同步更新对应的 `tool_result.tool_use_id` ✅🔧。

- 🔤 **确保 ID 为字符串**：遇到非字符串或空 ID 时生成可用的替代 ID
- ♻️ **处理重复 ID**：为重复调用生成唯一 ID，避免不同工具结果落到同一调用上
- 🧷 **调用与结果同步改写**：修复 ID 时同时更新对应结果引用，保持历史记录一致
- 🧹 **过滤孤立工具结果**：缺少匹配调用的结果会转为普通文本，避免无效工具块继续触发上游校验错误

## 🔄 中转站兼容：工具选择失败时自动降级 🛣️🧩

Anthropic Messages 的默认工具选择为 `auto`，但部分 API 中转站会错误地把显式 `tool_choice` 判定为强制调用，并返回“does not support forced tool_choice”一类错误 ⚠️🌐。

当错误明确指向工具选择参数时，AI Helper 会移除请求中的 `tool_choice` 后重试；Anthropic 默认行为仍为自动选择工具，因此工作区文件工具仍可正常参与请求 🤖🧰。Claude 连接探测也省略显式字段，避免测试请求触发同类兼容问题 🩺✅。

- 🎯 **只针对明确的工具选择错误重试**：其他请求错误不会被误判为 `tool_choice` 问题
- 🧠 **思考参数错误单独处理**：仅在错误明确涉及 thinking、budget 或 token 参数时调整思考配置
- 🚫 **无关 HTTP 400 不再重复发送**：减少重复失败请求、额外等待与中转站日志噪声
- ↩️ **端点缺失时保留兼容路径**：Messages 不可用时，可按既有策略回退到 Chat Completions

## 🈶 中文进度：清楚提示当前操作 💬🌏

模型生成的内部思考文本可能使用英文，也不适合作为面向用户的详细推理展示 🧠🔒。v1.0.84 不再将 Claude 原始思考块直接转发到 Cursor，而是显示简洁的中文进度提示；实际工具动作仍以中文明确呈现，例如“正在执行 `read_file`”📖✅。

- 🈶 **中文状态提示**：分析请求与准备下一步操作时显示中文进度
- 🧰 **工具动作更直观**：执行的工具名称以独立提示显示，方便追踪 Agent 正在做什么
- 🔏 **模型思考仍保留在内部上下文**：需要继续多轮工具调用时，完整思考块与签名会传回上游，不在界面中暴露原始文本
- 💬 **回复语言指引更明确**：系统提示要求面向用户的回复和简短进度信息使用中文

## 🧭 模型版本识别：思考参数按型号选择 🎛️🧠

旧版的简单字符串匹配会把 `claude-3-5-sonnet` 误判为 Claude 5 自适应思考模型，从而发送不兼容参数并产生多余重试 🐛🔍。现在按模型家族与其后的版本段识别思考模式，减少旧版模型的错误配置。

- 🟣 **Claude 5 / 5.5 系列**：使用自适应思考配置
- 🔵 **Claude Opus 4.8**：按自适应思考模型处理
- 🟢 **Claude 3.5 / 3.7**：继续使用兼容的传统思考预算格式
- 🧩 **其他模型**：不会仅因为名称中出现数字 `5` 就误启用自适应思考

## ❓ 常见问题 FAQ 🧭💬

### Cursor 中的 Claude 仍会在内部使用英文思考吗？ 🤔

模型内部推理语言由模型生成，无法可靠地强制为中文。v1.0.84 不再把原始思考文本显示给用户，而是提供中文进度提示；模型面向用户的回复仍由系统提示引导使用中文 🈶🔒。

### 为什么重试时没有显式 `tool_choice`？ 🧰

Anthropic Messages 默认工具选择就是 `auto`。当中转站错误地拒绝显式字段时，省略它仍会保留自动工具选择行为，同时避开中转站对强制调用的错误判断 🔄✅。

### 升级后文件工具调用仍失败怎么办？ 🩺

请确认模型服务支持 Anthropic `/v1/messages` 或兼容的 Chat Completions 工具调用协议 🌐。随后检查 Base URL、API Key 和模型名称，并在 API 测试中确认端点可用及工具调用能力已通过 🔑📍🧪。

### 这次更新会公开模型的思考内容吗？ 🔏

不会。原始思考块不会转发到 Cursor 界面；为满足 Anthropic 多轮请求格式要求，签名思考块仍会保留在内部对话上下文中 🛡️🧠。
