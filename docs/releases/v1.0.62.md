## 🌟 核心升级亮点 (Core Highlights) 💡✨💎📦

### 1. 📦 官方安装包智能嗅探 + 流式下载：WorkBuddy / Accio Work 一键拿到最新安装包 🔍📥💚🧡

**v1.0.62 新增独立模块 [`installer_download.rs`](file:///e:/Developer%20Tool/AI%20Helper/src-tauri/src/installer_download.rs)，并把完整向导嵌进 [`AppPathsPanel.tsx`](file:///e:/Developer%20Tool/AI%20Helper/src/components/AppPathsPanel.tsx)！** 🎉🎨

#### 🌈 1. 并发下载与卡片级进度条
- WorkBuddy 与 Accio Work **按应用类型独立维护下载状态**，互不阻塞！🔀✨
- 进度条展示百分比、已下 / 总量（MB）、当前文件名，下载完成后切换为「安装包已就绪」引导条！📊💚

#### 🛟 2. 嗅探失败也不慌
- Accio 回落 `work-download.accio.com` 稳定包；WorkBuddy 回落官方 `download.codebuddy.cn` 历史已知版本；  
- 文件名会做 Windows 非法字符净化，避免路径穿越与保存失败！🛡️🧹

#### 🧪 3. 原子写入，拒绝半截 exe
- 下载中使用 `.downloading` 临时扩展名；中断、超时、校验失败都会删除临时文件，**不会在 Downloads 留下损坏安装包**！💎🚫

### 2. 🏪 ChatGPT 官方安装三通道：微软商店直装 · WinGet 静默装 · 官网兜底 🪟💚💻

ChatGPT 桌面端走 Microsoft Store 分发，不能像普通 exe 那样直接下载。  
**v1.0.62 在路径卡片里展开专属安装抽屉，三条官方渠道并列可选！** 🎯✨

| 通道 | 怎么装 | 适合谁 |
|---|---|---|
| 🏪 **微软应用商店（推荐）** | `ms-windows-store://pdp/?productid=9NT1R1C2HH7J` 原生唤起商店 | 日常桌面用户，自动增量更新 💚 |
| 💻 **WinGet 静默安装** | 独立终端执行官方 `winget install --id=9NT1R1C2HH7J --source=msstore` | 喜欢命令行、可复制命令的开发者 ⌨️ |
| 🌐 **OpenAI 官方下载页** | 打开 `https://chatgpt.com/download` | 商店唤起失败时的浏览器兜底 🚀 |

- 商店协议唤起失败会自动改走浏览器商店详情页，**不会卡死在黑框或无响应**！🛡️
- `open_system_uri` 优先 `opener` / ShellExecute，避免弹出一闪而过的 cmd 黑窗！👻🚫
- 安装完成后点【探测】即可绑定 `WindowsApps (OpenAI.Codex)` 或 `ChatGPT.exe` 路径！🔎✅

### 3. 🧹 Claude / Codex 配置纯净覆写：先备份 `.bak`，再清空旧文件写入白名单字段 🛡️📝✨

以往写入 Claude `settings.json`、Codex `config.toml` 时会**合并旧文件内容**。损坏 JSON / 残缺 TOML、历史脏字段、错误 `profiles` 都可能被带进新配置，导致「看起来保存成功了，Agent 却读到幽灵字段」。👻

**v1.0.62 改为「归档备份 → 删除旧文件 → 只写当前必要字段」！** 🎉

```
+-----------------------------------------------------------------------------------+
|            🧹 纯净写入策略 (Clean Rewrite + Backup)                                 |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  发现已有配置文件                                                                 |
|         │                                                                         |
|         ▼                                                                         |
|  📄 copy → settings.json.bak  /  config.toml.bak                                  |
|         │                                                                         |
|         ▼                                                                         |
|  🗑️ remove 旧文件（彻底丢掉脏合并基线）                                            |
|         │                                                                         |
|         ▼                                                                         |
|  ✍️ 仅写入本轮需要的干净结构                                                       |
|         ├── Claude：env.ANTHROPIC_BASE_URL / AUTH_TOKEN / MODEL + 顶层 model      |
|         └── Codex ：model + model_provider=custom + model_providers.custom        |
|                     (name / base_url / api=openai-responses / env_key)            |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

- 连通性测试终端日志同步改写：会明确提示「旧配置已备份至 `.bak`」！📟✨  
- 旧文件仍在旁边，**出问题可以手动回滚，但新写入不再被污染**！🛟💎

### 4. ⚡ 热更新与安装包共用「大文件稳传引擎」：超时、停滞、代理三重容灾 🛰️📥🛡️

自更新安装包体积大、国内网络环境复杂，过去用「全局 60 秒超时」的普通 HTTP 客户端，容易在低带宽或代理异常时**整包被掐断**。  

**v1.0.62 在 [`updater.rs`](file:///e:/Developer%20Tool/AI%20Helper/src-tauri/src/updater.rs) 拆出专用下载客户端，并与安装包下载共用策略：** 🔌

| 能力 | 表现 |
|---|---|
| ⏱️ **生命周期** | 下载客户端最长 **30 分钟**，连接超时单独 15–30 秒 |
| 💓 **TCP Keepalive** | 15 秒保活，减少「假死连接」 |
| 🧊 **分块停滞检测** | **45 秒**收不到新 chunk 即判定停滞，切镜像 / 报错并清理临时文件 |
| 🛰️ **代理容灾** | 国内 CDN 在代理下失败时，`create_direct_download_client` **强制 `no_proxy` 直连重试** |
| 📡 **进度事件** | 应用内热更新与第三方安装包下载都走流式 `Progress` 回传 |

常规 API / 配置嗅探仍用短超时 `create_client`，**不会把探活请求拖成半小时**！🎯✨

### 5. 🔌 Accio Bridge 协议加固：tool_choice 透传 · Anthropic SSE 收口 · Responses 工具对齐 🧠🧡✨

Accio Work 本地桥在复杂工具调用与多协议中转场景下继续打磨：

- **优先使用客户端指定的 `tool_choice`**，不再无条件写成 `"auto"`，避免强制自动选工具干扰上游意图！🎛️  
- Anthropic SSE 合并解析增加 `message_stop` 识别、事件计数与失败行告警，流结束状态更可观测！🏁📋  
- Bridge 侧补齐模型上下文窗口映射、Responses API 工具定义 / 工具历史转换、`function_call` 顶层输出与 `incomplete_details` / `error` 处理，减少「工具调用对不齐、半截流当成功」的情况！🧩🛡️  
- gzip 请求体解压设 **64MB** 上限，防御 gzip 炸弹；上游响应体上限 **128MB**！💣🚫
