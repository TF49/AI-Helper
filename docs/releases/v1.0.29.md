## 🚀 详细更新亮点

### 1. 📂✨ 独创「全场景原生直达配置文件」联动引擎与多层级降级架构 (Native Config File Viewer & Multi-Tier Fallback)

#### 📉 痛点背景
在过去的版本中，当用户需要检查、微调或排错各类 Agent 的配置文件（例如 `~/.codex/config.toml`、`~/.claude/settings.json` 或 `~/.workbuddy-ai/models.json`）时，只能通过界面上的「复制路径」按钮复制文本，随后打开运行窗口（Win+R）或进入文件管理器手动粘贴寻找。对于新手或频繁调试模型的进阶开发者而言，链路冗长且体验割裂 😵💫。

#### 🔬 核心技术落地
在 Rust 后端我们新增了高性能原生指令 `open_config_file`，以前端极简触发、后端全异步保障的架构，实现了系统原生编辑器的秒级唤起 ⚡🚀：

```rust
#[tauri::command]
async fn open_config_file(path: String) -> Result<(), String> {
    let trimmed = path.trim().to_string();
    if trimmed.is_empty() {
        return Err("配置文件路径为空".to_string());
    }

    // 1. 智能波浪号路径展开 (~/ 或 ~\ 转换为真实家目录绝对路径)
    let expanded_path = if trimmed.starts_with("~/") || trimmed.starts_with("~\\") {
        dirs::home_dir().map(|h| h.join(&trimmed[2..])).unwrap_or_else(|| PathBuf::from(&trimmed))
    } else {
        PathBuf::from(&trimmed)
    };

    if !expanded_path.exists() {
        return Err(format!("配置文件不存在: {}", expanded_path.display()));
    }

    // 2. 借助 Tokio 异步非阻塞线程池执行打开任务，绝不阻塞 UI 主事件循环
    tokio::task::spawn_blocking(move || {
        match opener::open(&expanded_path) {
            Ok(()) => Ok(()),
            Err(open_err) => {
                // 3. 智能三级降级容灾方案 (Multi-Tier Fallback)
                #[cfg(target_os = "windows")]
                {
                    // 兜底一：调用系统默认 notepad.exe 强行打开
                    if Command::new("notepad.exe").arg(&expanded_path).spawn().is_ok() {
                        return Ok(());
                    }
                    // 兜底二：调用 explorer.exe /select,path 定位并高亮选中文件
                    if Command::new("explorer.exe").arg(format!("/select,{}", expanded_path.display())).spawn().is_ok() {
                        return Ok(());
                    }
                }
                #[cfg(target_os = "macos")]
                {
                    if Command::new("open").arg("-t").arg(&expanded_path).spawn().is_ok() {
                        return Ok(());
                    }
                }
                #[cfg(target_os = "linux")]
                {
                    if Command::new("xdg-open").arg(&expanded_path).spawn().is_ok() {
                        return Ok(());
                    }
                }
                Err(format!("无法打开配置文件: {}", open_err))
            }
        }
    }).await.map_err(|e| format!("执行异常: {}", e))?
}
```

### 2. 🛡️🔒 Codex CLI Windows 管理员提权模式加固方案 (`--no-daemon`)

#### 💥 痛点与深度机理剖析
在 Windows 操作系统中，部分开发者习惯以 **“管理员身份运行（Run as Administrator）”** 打开终端或 IDE。然而，Codex CLI 默认采用后台守护进程（Daemon）模式运行。在 Windows UAC 提权安全隔离机制（Integrity Levels）下，提权进程与普通用户会话之间的 IPC/命名管道通信会受到操作系统严格的安全拦截，容易诱发：
- `codex` 启动后无响应或直接崩溃退出；
- 守护进程未能正确监听，提示连接超时或拒绝访问 💥；

#### 🛠️ 解决方案与稳健升级
1. **自动参数注入 (`process_manager.rs`)** 🚀：
   在 `launch_app` 中拉起 Codex CLI 时，自动为 Windows 平台追加 `--no-daemon` 核心参数：
   ```rust
   // 🛡️ 在独立 CMD 窗口中启动 Codex CLI (追加 --no-daemon 避免在 Windows 管理员提权环境下触发 Daemon 安全限制)
   cmd.args([
       "/c",
       "start",
       "Codex CLI",
       &comspec,
       "/k",
       &path_str,
       "--no-daemon",
   ]);
   ```
2. **应用路径管理面板新增指南 (`AppPathsPanel.tsx`)** 💡📝：
   在 Codex 路径卡片下方贴心新增蓝色醒目标签，指导手动在控制台输入指令的用户：
   > ℹ️ **Windows 提示**：若在管理员终端中手动运行 Codex CLI，请使用 `codex --no-daemon`（本软件“测试启动”已自动附带该参数）。

### 3. 🐚💻 动态 `COMSPEC` 系统解释器解析与环境隔离 (Dynamic Shell Isolation)

#### 📉 告别死板硬编码
以往代码中，Windows 下的外部终端呼出命令硬编码为 `"cmd"` 或 `"cmd.exe"`。在部分深度定制的 Windows 镜像、WinPE 或配置了特殊环境变量的开发机上，极易由于 PATH 缺失或命令拦截导致派生子进程失败 ⚠️。

#### 🌟 全面接入动态环境变量探测
在 `process_manager.rs` 中，全面采用操作系统环境标准读取：
```rust
let comspec = std::env::var("COMSPEC").unwrap_or_else(|_| "cmd.exe".to_string());
let mut cmd = Command::new(&comspec);
```
- **Claude Code 终端拉起**：基于 `%COMSPEC%` 动态实例化 🐚✨；
- **Codex CLI 终端拉起**：基于 `%COMSPEC%` 动态实例化 🤖⚡；
- **CLI 手动安装与更新终端 (`execute_in_terminal`)**：基于 `%COMSPEC%` 动态实例化 📦🛠️；
- 全方位保障多终端环境下的健壮性与兼容度！

### 4. ⚡🔄 进程内纳秒级即时环境变量同步 (`std::env::set_var`)

- **问题根源**：过去当用户更新 OpenAI / Codex API Key 时，程序会写入 Windows 用户注册表（`Environment`）。然而，Windows 注册表修改后，当前正在运行的本进程内部并不能自动接收注册表变更，导致后续同进程内的测试请求仍读取旧变量 ⌛。
- **瞬时同步保障 (`codex.rs`)**：
  ```rust
  env.set_value(name, &value.to_string())
      .map_err(|e| AppError::Registry(e.to_string()))?;
  // ⚡ 同步注入当前运行进程环境，无需重启即可立即可用
  std::env::set_var(name, value);
  ```
- 使得配置修改即刻在内存上下文中生效，连通性测试与派生诊断探针享受 0 延迟刷新 ⚡🎉！
