## 🧰 Cursor Agent 本地工具运行时：项目文件终于“够得着”了 📁🔎🖼️

Cursor 会把当前工作区信息发送给 Bridge，但第三方上游模型本身无法访问你的本地磁盘 💽。v1.0.78 在 Bridge 内置了一个**范围明确、边界清晰**的本地工具循环，同时兼容 OpenAI Chat Completions 与 Responses 两种协议 🔗🤖。

### 🛠️ 可用工具一览

| 工具 🧩 | 作用 💬 | 是否需要授权 🔐 |
| :--- | :--- | :--- |
| 📂 `list_directory` | 列出工作区目录内容，可选递归 | ❌ 无需授权 |
| 📖 `read_file` | 读取文本文件，可指定起止行 | ❌ 无需授权 |
| 🔎 `search_files` | 按文件名或 glob 片段搜索文件 | ❌ 无需授权 |
| 🧵 `search_text` | 在文本文件中搜索字符串，可区分大小写 | ❌ 无需授权 |
| 🖼️ `read_image` | 读取图片并提供给支持视觉的模型 | ❌ 无需授权 |
| ✍️ `write_file` | 写入或创建工作区内文件 | ✅ 需要授权 |
| 🔁 `replace_in_file` | 唯一替换一段文本（`old_text` 必须只出现一次） | ✅ 需要授权 |
| 🏗️ `create_directory` | 在工作区内创建目录 | ✅ 需要授权 |
| 🗑️ `delete_file` | 删除单个文件（**移入系统回收站**，不能删目录） | ✅ 需要授权 |

### 📏 资源上限：防止“无底洞”式扫描 🧱

- 🔁 单次 Agent 运行最多 `24` 步、`128` 次工具调用
- 📄 单文件读取上限 `2 MB`，工具输出上限 `128 KB`，超出部分标记为 `...[输出已截断]` ✂️
- 🔍 搜索结果最多 `200` 条，目录列举最多 `1000` 项，扫描最多 `20000` 个条目
- 🧮 文本搜索累计读取上限 `64 MB`，上游响应上限 `16 MB`，会话总量上限 `24 MB`
- 🚰 FIFO、设备文件、目录等非常规文件在打开前后都会被拒绝，读取方不会卡在管道上，也不会把无限设备流读进内存 🛑
- ⏹️ 请求被取消时，后台长时间扫描会及时停止，不再继续占用阻塞线程池 🧵

### 🧭 路径边界：只在工作区里活动 🗺️

- 🏠 只有 Cursor 提供的 `workspace_paths` 会成为工作区根目录；项目目录、进程工作目录只用于选择根内的当前路径
- 🚷 路径中不允许出现 `..`，工作区外的路径一律拒绝访问
- 🔤 Windows 下路径大小写不敏感，`C:\Repo` 与 `c:\repo` 视为同一根；Unix 下则作为不同目录分别保留
- 💬 没有合法工作区根时自动进入“纯对话模式”，Agent 不会访问任何文件
- ⚛️ 写文件采用原子替换并保留原有权限，不会在项目目录里留下锁文件或备份文件 🧼

## 📂 Agent 工作区写入授权：读可以，改要先问你 ✋🔐

Cursor 面板新增 **「Agent 工作区授权」** 区域 🆕。Agent 第一次尝试修改某个未授权工作区时，请求会被拒绝并登记为“待授权请求”，由你在 AI Helper 中决定是否允许 🙋‍♂️🙋‍♀️。

### 🧾 面板功能

- 📥 **待授权请求**：按路径去重，最多保留 `20` 条，超出时丢弃最早的一条
- ✅ **允许**：授权后 Agent 才能在该工作区内写入、替换、新建目录和删除
- ❌ **拒绝**：直接移除该请求，Agent 的修改继续被拦截
- 📋 **已授权工作区**：集中展示所有已授权路径，可随时 **撤销** ↩️
- 🗂️ 即使目录已被删除，也可以按记录路径撤销授权
- 🔄 面板打开期间每 `3` 秒轮询一次请求列表；关闭面板后不留任何监听 💤

### 🚧 不能被授权的目录

| 目录类型 🚫 | 原因 💡 |
| :--- | :--- |
| 💽 盘符根目录 / 文件系统根目录 | 范围过大，风险不可控 |
| 🏠 用户主目录本身 | 包含大量个人数据与其他应用配置 |
| 🔒 `~/.ai-helper` 及其子目录 | AI Helper 自身的数据与凭据目录 |
| 📄 非目录路径 | 只能授权目录 |
| ❓ Agent 从未请求过的路径 | 只能授权已出现在待授权或已授权列表中的路径 |

### 🛡️ 额外保护

- 🚫 **任何 `.git` 目录内的文件都禁止修改**，Windows 下大小写不敏感匹配 🧬
- 🗑️ 删除只会把文件移入系统回收站，误删可以找回 ♻️
- 💾 授权记录保存在 `~/.ai-helper/agent_workspaces.json`，使用配置写锁与原子写入
- 🧯 授权文件损坏时直接拒绝写入，而不是放行
- 🧹 执行“一键恢复原生配置”时，授权文件与内存中的待授权请求会一并清除

> 💡 小提示：如果你只是想让 Agent 帮忙阅读、解释、搜索代码，完全不需要授权；只有在需要它动手改文件时，再到面板里点一下“允许”即可 👍✨。

## 🪪 Cursor Bridge 调用方认证：只认“自己人” 🔒🧑‍💻

Bridge 只监听回环地址 🔁，但同一台机器上的其他进程（包括其他系统用户）同样能连上它。v1.0.78 为 Cursor Bridge 的全部路由增加了**调用方进程身份校验** 🕵️：

- 🔌 每条 TCP 连接在第一次请求时，根据对端端口找到发起连接的进程
- 👤 只接受与 AI Helper **属于同一系统用户** 的进程
- ❓ 查询失败、无法确认身份、缺少连接信息时 **一律拒绝** 🙅
- ⚡ 结果按连接缓存，同一 keep-alive 连接不重复查询；并发请求只触发一次查询
- 🏷️ 程序名只用于日志，**不参与判断**，无法靠改名绕过
- 🧱 继续叠加 Host / Origin 与 Content-Type 校验

### 🖥️ 各平台实现

| 平台 💻 | 识别方式 🔍 |
| :--- | :--- |
| 🪟 Windows | `GetExtendedTcpTable` 定位进程，比较进程令牌中的用户 SID |
| 🐧 Linux | 解析 `/proc/net/tcp` 与 `/proc/net/tcp6`，比较 uid |
| 🍎 macOS | 通过 libproc 在当前用户进程中查找持有该套接字的进程 |

## 🧠 Cursor 协议与会话：第二轮不再“失忆” 💬🔁

部分 Cursor 版本在后续轮次中不会内联完整历史，而是依赖服务端保存会话状态 🗄️。此前本地 Bridge 不保存跨轮状态，导致第二轮只把当前问题发给模型 😵。本版本做了以下改进：

- 🧾 **跨轮会话历史缓存**：按 `conversation_id` 保存已成功完成的轮次，仅在请求缺少内联历史时用于补全
- ✏️ **识别重新生成 / 编辑旧消息**：根据 `message_id` 截取该轮之前的历史，不会把旧回答重复喂给模型
- 💨 **只驻留内存**：Bridge 停止或执行一键恢复时立即清空，不落盘 🔒
- 📦 **乱序包合并更稳**：较旧的内容包只补齐仍为空的字段，先到的空控制包不会让真正的用户请求失效
- 🧱 **防止根目录被替换**：后续 BidiAppend 试图替换已有工作区根目录时直接忽略 🛑
- 🔬 **结构化诊断日志**：只记录 protobuf 字段 tag、类型与长度（如 `1:L120,5:L36,9:V`），**不含任何正文** 🕶️
- #️⃣ **标识符脱敏**：日志中的会话标识只显示 SHA-256 前 8 位，可跨日志关联但不暴露原值
- 🔇 **心跳不刷屏**：同一形状的控制包只在首次出现时以 info 级别记录
- ⏹️ **任务可中止**：停止 Bridge 时会中止所有进行中的 Agent 流，连带停止内部工具任务

## 🧪 Cursor 连通性测试：新增工具调用能力探测 📡🧩

Cursor Agent 依赖 Function Calling 才能使用项目文件与 Agent 工具 🛠️。v1.0.78 的 Cursor 连通性测试在握手之外，还会**要求模型调用一个只读探测函数**：

- 🔄 优先按运行时协议（Responses）测试；上游没有 Responses 端点时，自动改测 Chat Completions 工具调用

- ⚠️ 未返回工具调用：显示 **“连接成功，但未验证工具调用能力”**，并提示切换支持 OpenAI Function Calling 的模型或中转站
- 📏 探测响应限制在 `1 MB` 以内，避免异常上游拖垮测试

## ♻️ 一键恢复所有客户端原生配置：随时“全身而退” 🧹⏪

设置页新增 **「客户端配置」** 区块，提供 **“恢复所有客户端原生配置”** 操作 🆕。它会清除 AI Helper 写入的地址、密钥、模型和本地 Bridge 设置，并优先恢复首次接管前的配置 📸。

### 🔍 先预览，再确认

点击“清除配置”后会先生成**只读预览** 👀，逐个客户端、逐个文件展示即将执行的动作，再由你确认：

| 客户端动作 🎯 | 含义 💬 |
| :--- | :--- |
| 📸 恢复首次接管前的快照 | AI Helper 首次修改前保存了完整快照，直接恢复 |
| 🧽 只清理受管字段 | 文件被外部修改过，只移除 AI Helper 管理的字段，其他修改保留 |
| 🗑️ 删除 AI Helper 专用配置 | Accio Work / Cursor 专用配置文件属于 AI Helper，直接删除 |
| 🖱️ 还原 Cursor 补丁并删除专用配置 | 还原 Cursor 客户端补丁后再删除专用配置 |
| ⏭️ 不处理 | 未检测到 AI Helper 的修改 |

> 💡 预览失败也可以继续执行；实际处理会按执行时的文件状态重新判断，最终以返回结果为准 🧾。

### 🧩 覆盖范围

- 🟢 **Codex / ⚪ ChatGPT**：恢复 `config.toml` 中受管配置，并清理 `CUSTOM_OPENAI_API_KEY` 环境变量 🔑
- 🟠 **Claude Code**：恢复或清理受管的环境变量字段，保留其他安全规则
- 🟩 **WorkBuddy**：恢复配置快照，或只移除 AI Helper 管理的模型条目，主配置与备份一起处理
- 🔵 **Accio Work**：停止 Bridge，删除 AI Helper 专用配置
- 🖱️ **Cursor**：停止 Bridge，还原补丁，删除专用配置与工作区授权

### 🖱️ Cursor 补丁还原更精细

- 🎯 `state.vscdb` 只写回补丁实际改过的路由键，Cursor 之后写入的其他新数据（包括 WAL）原样保留 🧬
- 🪟 新增 `workbench.glass.main.js` 的备份与还原
- ⏪ `workbench.desktop.main.js` 与 `product.json` 原子恢复；第二个文件失败时自动回滚第一个 🔁
- 🧯 补丁仍指向 AI Helper 但缺少原始备份时，明确报错而不是盲目修改
- ⚠️ 还原补丁时会**强制关闭正在运行的 Cursor**，请先保存未完成的工作 💾

### 🔒 恢复过程的一致性保障

- 🚦 恢复执行期间拒绝新的配置写入，同一时间只允许一个恢复任务
- 🧬 引入“配置代际”机制：恢复开始前读取的过期任务无法再写回配置或拉起 Bridge
- 🌉 Accio / Cursor Bridge 启动前校验代际，恢复后不会被旧任务“复活” 🧟‍♂️🚫
- 🔄 前端单卡片终端与批量终端在会话切换后不再启动 Bridge
- 💾 快照保存在 `~/.ai-helper/reset_state.json`，沿用本地配置文件的访问保护
- 🧹 启动时自动清理旧版本写入快照中的 Accio / Cursor 配置（其中可能含明文凭据）🔐

### ℹ️ 关于旧版本用户

由于 v1.0.78 之前没有记录接管快照，旧版本写入的配置只能**清理明确识别的 AI Helper 项**；被覆盖的原值无法推断恢复 🙏。从 v1.0.78 开始，AI Helper 首次修改某个客户端前都会自动保存快照 📸✅。

## 🚦 Bob API 请求更稳：限流感知 + 智能缓存 🧠⏱️

### ⏳ HTTP 429 限流处理

- 🔍 识别 HTTP 429 响应并读取 `Retry-After` 头
- 🧊 进入本地冷却期，期间直接提示 **“Bob API 请求受限 (HTTP 429)，请在 N 秒后重试”**，不再继续发请求
- 🏷️ 对失败原因进行结构化分类：限流、未发出请求、服务端状态码等，不靠错误文本猜测
- 🛡️ 对于本地冷却或连接失败等“请求未发出”的情况，可以确认非幂等 POST 没有生效，避免重复创建令牌

### 🗃️ 令牌查询缓存

- ⚡ 分组令牌等读请求加入短时缓存，减少重复查询
- 🔄 创建 / 更新令牌后立即使缓存失效
- 👤 记录账号与会话代际，**账号切换后旧请求结果会被丢弃**：“账号已切换，已丢弃旧令牌请求” 🗑️

### 🏷️ 首页分组显示更稳

- 🌐 限流或网络故障只说明“这次没查到”，**不再把已展示的分组清空** 🧷
- 🎯 只有在同一账号、会话、工具和 Key 下才沿用上一次解析的分组
- 🔑 服务器返回的令牌缺少明文 Key 时明确报错，不写入空 Key

## ❓ 常见问题 FAQ 🧭💬

### Cursor Agent 修改文件时提示“该工作区尚未授权”怎么办？ 🤔

打开 AI Helper 的 Cursor 面板，在「Agent 工作区授权」的“待授权请求”中找到对应路径，点击 **允许** ✅，然后回到 Cursor 让 Agent 重试即可 🔁。

### 为什么不能授权我的用户主目录？ 🏠

主目录包含大量个人数据和其他应用的配置，范围过大。请授权具体的项目目录 📁。

### Agent 删除的文件还能找回吗？ 🗑️

可以。`delete_file` 只会把文件移入系统回收站，且只能删除单个文件，不能删除目录 ♻️。

### 一键恢复会删掉我自己写的配置吗？ 🧹

不会。被外部修改过的文件只会清理 AI Helper 管理的字段，你自己添加的其他内容会保留 💚。

### 旧版本配置为什么不能完全恢复？ 📸

v1.0.78 之前没有记录首次接管前的快照，被 AI Helper 覆盖的旧值无法推断。恢复时只会清理能明确识别的 AI Helper 配置项 🙏。

### Bridge 拒绝了我的连接？ 🪪

Cursor Bridge 只接受与 AI Helper 属于同一系统用户的进程。请确认 Cursor 与 AI Helper 由同一用户运行，不要以管理员 / 其他账户单独启动其中一方 🔐。
