### 2. 🔐 令牌绑定精准失效与自动重配：根治旧 Key 幽灵残留 · 智能解绑清缓存 · 瞬时重匹新分组 🛡️🔄⚡

在多 Token、多工具混合使用的场景中，用户经常会手动更换输入框中的 API Key，或在云端后台删除过期 Token。  
在过去，本地一旦缓存了 `bound_token_*`，即使输入框中换成了完全不一样的 Key，逻辑仍然以为「该输入框属于旧 Token」，导致**界面显示了错误的旧 Token 名字与旧通道分组**！👻🤦‍♂️

**v1.0.60 在 [`ApiKeyInput.tsx`](file:///e:/Developer%20Tool/AI%20Helper/src/components/ApiKeyInput.tsx) 中构建了坚不可摧的绑定自愈核对机制！** 🛡️💎

```
+-----------------------------------------------------------------------------------+
|               🔐 ApiKeyInput 智能解绑与自愈重配逻辑 (v1.0.60)                       |
+-----------------------------------------------------------------------------------+
|  输入框值变更或拉取云端令牌列表                                                    |
|         │                                                                         |
|         ▼                                                                         |
|  本地是否存在 boundToken 缓存？                                                   |
|         ├─ [否] ──────────────────────────────────────────┐                       |
|         │                                                 │                       |
|         └─ [是]                                           │                       |
|              │                                            │                       |
|              ▼                                            │                       |
|       核对该 Token 是否依然匹配当前输入框的 Key？          │                       |
|       (明文全等 OR 长度>=12 前7位+后4位匹配)              │                       |
|              │                                            │                       |
|              ├─【依然匹配】──> 同步云端最新 Group ──> 完成 ✅  │                       |
|              │                                            │                       |
|              └─【已不匹配 / 云端已删】                     │                       |
|                     │                                     │                       |
|                     ▼                                     │                       |
|             🧹 立即解除旧绑定 (setBoundToken(null))        │                       |
|             🗑️ 清除 localStorage 幽灵持久化数据           │                       |
|                     │                                     │                       |
|                     ▼                                     ▼                       |
|             🔍 重新向下比对当前输入框 Key                                          |
|             ├── 1️⃣ 令牌列表精确明文比对                                           |
|             └── 2️⃣ 前 7 后 4 启发式智能匹配                                       |
|                     │                                                             |
|                     ▼                                                             |
|             🏷️ 重新锚定新 Token ID、名称与所属通道分组！ 🎉                        |
+-----------------------------------------------------------------------------------+
```

#### 🛡️ 1. 深度比对算法：兼顾明文全等与脱敏匹配
- 无论是刚从剪贴板粘贴的完整明文 Key，还是部分脱敏保存的 Key，算法通过 `val.startsWith(prefix) && val.endsWith(suffix)` 双重特征校验，确保绑定的准确度达到 100%！🎯

#### 🧹 2. 干净利落的缓存清理
- 只要检测到用户手动变更了 Key 且不属于原绑定，毫秒级清理 `localStorage` 中的残留碎片，彻底终结「换了 Key 分组却还是老分组」的历史顽疾！🚫👻✨

### 3. 📍 步骤条实时动态微摘要：所填即所见 · Active 状态同步渲染 · 编辑过程全程透明 📝⚡👀

在向导式配置界面中，顶部 `StepIndicator` 是开发者掌控全局进度的方向盘。  
在 v1.0.59 中，步骤条下方的微摘要（如节点域名、脱敏 Key、当前模型等）仅在步骤处于 `isDone`（已完成）或 `canClick`（可点击）时显示；**一旦当前正停留在该步骤进行输入（`isActive`），微摘要就会突然消失隐藏！** 这种断续感降低了界面的沉浸度。

**v1.0.60 优化 [`StepIndicator.tsx`](file:///e:/Developer%20Tool/AI%20Helper/src/components/StepIndicator.tsx) 显示逻辑：** 🌟

```tsx
// 🚀 v1.0.60 核心升级：增加 isActive 实时渲染
- {(isDone || canClick) && step.summary && (
+ {(isDone || canClick || isActive) && step.summary && (
    <div className={cn("text-[10px] font-mono truncate mt-0.5 max-w-full px-0.5", ...)}>
      {step.summary}
    </div>
  )}
```

#### ✨ 实时微摘要带来的绝佳体验：
- 🌐 **接入节点**：输入或切换 URL 的瞬间，下方立即动态提炼出主机域名（如 `bob-api.com`）；
- 🔑 **API 凭据**：选择或填入 Key 时，下方立即呈现脱敏字样与状态；
- 🤖 **模型选择**：在模型下拉列表中点选时，步骤条下方立刻跟随跳动所选模型名称；
- 📊 **随时可见**：不再需要切换到下一步才能回看当前步的配置摘要，边填边看，行云流水！🌊🚀
