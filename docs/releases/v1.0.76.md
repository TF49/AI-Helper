本次 **v1.0.76** 聚焦 Agent 矩阵的一键配置一致性 🧩🛠️。当用户将分组专属 API Key 分发给不同 Agent 时，AI Helper 现在会同步切换到该分组对应的推荐模型，彻底解决过去只更新密钥、却继续保留旧模型而可能触发 `model_not_found` 的半配置状态 🚫⚠️➡️✅。

同时，WorkBuddy 的推荐模型会被提升为自定义模型列表首项，在不删除其他手动模型的前提下，确保 AI Helper 与 WorkBuddy 实际选中的默认模型保持一致 🥇📚💚。桌面端、官网、诊断页与全平台下载渠道也已统一升级至 **v1.0.76** 🌐📦🍎🪟。

- 🎯 **分组模型精准匹配**：一键配置时按目标 Agent 自动写入对应推荐模型
- 🔑 **API Key 与模型同步切换**：避免“新密钥 + 旧模型”的不完整配置组合
- 🛑 **修复 `model_not_found`**：防止旧模型不在新分组可用渠道中导致请求失败
- 🥇 **WorkBuddy 默认模型校正**：推荐模型自动提升到列表首项并成为默认选择
- 🧰 **保留手动模型资产**：WorkBuddy 其他自定义模型不会被覆盖或删除
- 🌐 **全渠道版本同步**：客户端、官网、诊断引擎及 Windows/macOS 下载链接统一更新
- 🧪 **补充回归测试**：覆盖 Agent 分组映射和 WorkBuddy 模型排序逻辑

## 🎯 核心升级：不同 Agent 自动匹配专属推荐模型 🤖🧭✨

### 🧩 推荐模型分组

执行一键配置时，AI Helper 会根据目标 Agent 所属分组，自动应用以下推荐模型：

| Agent / 客户端 🖥️ | 自动配置模型 🧠 | 适用分组 🏷️ |
| :--- | :--- | :--- |
| Codex / ChatGPT 💻 | `gpt-5.6-sol` | Codex 专属分组 ⚡ |
| Claude Code 🟠 | `claude-sonnet-5-5` | Claude 专属分组 🧡 |
| WorkBuddy 🟢 | `glm-5.3` | 国内模型分组 🇨🇳 |
| Accio / Accio Work 🔵 | `glm-5.3` | 国内模型分组 🇨🇳 |
| Cursor 🖱️ | `glm-5.3` | 国内模型分组 🇨🇳 |

### 🔄 从“缺省补全”升级为“主动对齐”

旧版本仅在本地尚未设置模型时填入默认模型；如果 Agent 中已经保存过其他模型，一键配置会保留旧值 📌。当 API Key 已切换到新的专属分组，而旧模型并不属于该分组时，就可能出现以下问题：

1. 🔑 API Key 已成功切换到目标分组
2. 🧠 Agent 仍保留上一次使用的旧模型
3. 📡 请求被发送到新分组中不存在的模型渠道
4. 💥 服务返回 `model_not_found`
5. 😵 用户看到“配置成功”，实际使用却立即失败

v1.0.76 将一键配置语义调整为完整的分组对齐 ✅：不仅写入专属 API Key，还会同步覆盖为该 Agent 分组的推荐模型，让密钥、模型与渠道始终保持同一套配置逻辑 🔗🛡️。

```mermaid
flowchart LR
    A[🚀 点击一键配置] --> B[🎯 识别目标 Agent]
    B --> C[🔑 写入分组专属 API Key]
    C --> D[🧠 写入对应推荐模型]
    D --> E[💾 保存完整配置]
    E --> F[✅ Agent 可直接使用]
```

## 🥇 WorkBuddy 默认模型顺序修复 🟢📚🛠️

WorkBuddy 与 AI Helper 都会把自定义模型列表中的**第一项**作为默认模型 🥇。过去即使一键配置成功写入了 `glm-5.3`，如果列表前面已经存在其他模型，新模型仍可能只被追加到末尾，导致界面展示、配置结果与 WorkBuddy 实际默认选择不一致 🔀⚠️。

### ✨ v1.0.76 的新行为

- 🥇 一键配置时，将推荐模型 `glm-5.3` 提升到自定义模型列表首项
- ♻️ 如果 `glm-5.3` 已经存在，则更新该条目并移动到首位，不创建重复记录
- 🧰 其他手动添加的模型全部保留，不删除、不覆盖、不丢失
- 🧩 保留模型条目中由 WorkBuddy 或用户维护的额外字段
- ✍️ 普通手动保存仍维持原有行为：更新原位置，或把新模型追加到末尾
- ✅ AI Helper 读取到的默认模型与 WorkBuddy 实际使用的默认模型保持一致

```text
配置前：keep-model → glm-5.3
一键配置后：glm-5.3 → keep-model
                  🥇          🧰
```

这项调整只作用于“一键配置”流程，不会改变用户日常手动维护多模型列表的习惯 💚🔒。

## 🛡️ 告别半配置状态：配置结果更可预期 🔐✅

本次更新重新明确了一键配置的目标：它不是只替换一段密钥，而是为目标 Agent 建立一套可以立即使用的完整配置 🎯📦。

- ✅ **模型始终属于当前密钥分组**：降低渠道不匹配造成的请求失败
- ✅ **旧模型不再干扰新配置**：切换分组后无需再逐个 Agent 手动修改模型
- ✅ **多 Agent 批量分发更可靠**：Codex、Claude、WorkBuddy、Accio Work 与 Cursor 各自获得正确推荐值
- ✅ **默认模型表现更统一**：配置文件、AI Helper 界面与目标客户端的实际选择保持一致
- ✅ **错误排查更简单**：避免出现“密钥已更新但模型没更新”的隐蔽组合

> 💡 **说明**：一键配置会主动覆盖目标 Agent 当前选中的模型，以保证新 API Key 与推荐模型配套生效；WorkBuddy 中的其他自定义模型仍会完整保留 📚✨。

## 💡 升级指南与温馨提示 🔄💖

1. 📥 **升级到 v1.0.76**：建议完全退出旧版 AI Helper 后，再安装或替换新版本，确保桌面进程与配置逻辑同步更新。
2. 🚀 **重新执行一键配置**：如果你此前切换过分组 API Key，建议在 Agent 矩阵中重新执行一次一键配置，让推荐模型自动完成对齐。
3. 🧠 **注意模型会被主动切换**：一键配置会将当前模型改为目标 Agent 的分组推荐模型，这是本次更新的预期行为。
4. 🟢 **WorkBuddy 用户无需整理列表**：推荐模型会自动移动到首位，其他手动模型仍然保留，可继续随时切换。
5. 🔍 **遇到问题先核对版本**：请确认客户端与下载文件均显示 `v1.0.76`，再重新执行配置并尝试请求。
6. 📮 **问题反馈**：如遇到 Agent 配置、模型选择或下载问题，可通过应用内「意见反馈」提交日志，或前往 [GitHub Issues](https://github.com/TF49/AI-Helper/issues) 交流 💬🙌。
