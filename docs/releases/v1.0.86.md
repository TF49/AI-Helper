## 🌟 更新速览：遥测通道搬进 HTTPS 新家 🏠🔒

AI Helper 内置的客户端遥测与故障诊断模块 🩺📊，负责在后台默默上报设备配置 🖥️、运行异常 🐛 和活跃心跳 💓，帮助我们第一时间发现并修复问题 ⚡。

此前，这条上报通道直接连接服务器的 IP 地址，并使用明文 HTTP 传输 📭😬。v1.0.86 将它整体迁移到了专属域名 **`monitor.bob-api.com`**，并全面启用 **HTTPS 加密传输** 🔐✨，让诊断数据在传输过程中更安全、更可靠 🛡️💎。

- 📡 **遥测地址迁移至专属域名**：告别裸 IP 直连，统一使用 `https://monitor.bob-api.com` 🌐
- 🔒 **全程 HTTPS 加密**：设备信息与错误报告在传输中全程加密，杜绝明文暴露 🙅‍♂️👀
- 🛡️ **服务端安全加固**：遥测服务端口不再直接暴露在公网，统一经由安全网关转发 🚪🔐
- 🧹 **部署配置更规范**：本地部署覆盖配置不再纳入版本管理，避免误提交 📦✅
- 🌐 **版本与下载资源同步更新**：Windows、macOS、官网及在线诊断信息统一至 `v1.0.86` 🔄

## 📡 核心变更：遥测上报地址迁移 🚚🌐

### 🔍 变更内容

| 项目 🧾 | 旧版本 ⏪ | v1.0.86 ⏩ |
| :--- | :--- | :--- |
| 🌐 连接方式 | 服务器 IP 直连 🔢 | 专属域名 `monitor.bob-api.com` 🏷️ |
| 🔐 传输协议 | HTTP 明文 📭 | HTTPS 加密 🔒 |
| 🚪 服务端口 | 直接对外暴露 ⚠️ | 仅经安全网关访问 🛡️ |
| 📮 上报路径 | `/api/telemetry/report` | `/api/telemetry/report`（保持不变 ✅） |

### 💡 为什么要迁移？ 🤔

- 🔐 **数据更安全**：HTTPS 加密可防止设备信息、错误堆栈在网络传输中被窥探或篡改 🕵️‍♂️🚫
- 🏷️ **地址更稳定**：使用域名后，即便日后服务器迁移或扩容 🏗️，也只需调整域名解析，客户端无需感知 🔄
- 🛡️ **攻击面更小**：后端服务不再直接暴露端口，所有请求统一经过网关，安全性大幅提升 🧱💪
- 📶 **网络兼容性更好**：标准 HTTPS 443 端口在企业网络、校园网及各类代理环境下都更容易畅通 🏢🏫✅

## 🛡️ 服务端：安全加固 🔐🧱

本次同步对遥测后端的部署方式进行了收敛 🛠️：

- 🚪 遥测 API 服务端口仅监听服务器本机，不再直接对外开放 🔒
- 🌉 外部请求统一由 HTTPS 安全网关接收后转发至后端服务 🔁
- 🧾 本地部署覆盖配置（`docker-compose.override.yml`）已加入忽略列表，避免把个人环境配置误提交到仓库 🙅📦

> 🙌 以上调整均在服务端完成，对你的日常使用没有任何影响，无需做任何操作 😊。

## ❓ 常见问题 FAQ 🧭💬

### 遥测会收集我的哪些信息？ 🤔

仅包括诊断所需的基础信息 📋：随机生成的匿名设备 ID 🎲、操作系统与架构 🖥️、CPU 核心数与内存规格 🧠💾、屏幕分辨率与显卡型号 🖼️🎮、系统语言与时区 🌏🕒、客户端版本号 🏷️、使用时长心跳 💓，以及运行时异常的错误信息与堆栈 🐛。遥测 **不会主动读取** 你的 API Key 🔑、对话内容 💬 或个人文件 📁。

### 这次更新会改变遥测收集的内容吗？ 🔍

不会 🙅。本次只更换了上报的地址与传输协议 🚚🔒，收集的数据范围与之前完全一致 ✅。

### 我不升级会怎样？ 😶

AI Helper 的所有功能仍可正常使用 👍，只是旧版本的崩溃与异常报告将无法送达，我们难以及时发现你遇到的问题 📭。为了获得更好的支持体验，建议尽快升级 ⬆️✨。

### 我在公司 / 学校网络下，上报会被拦截吗？ 🏢🏫

新地址使用标准 HTTPS 端口 🔐，通常比之前的非标准端口更容易通过企业防火墙与代理 ✅。即使上报失败，也会被静默忽略，**绝不会影响客户端的正常运行** 🛡️🍃。
