## 🌟 核心升级亮点 (Core Highlights) 💡✨💎💚🧡

### 1. 💚 WorkBuddy 官方标准路径落地：`~/.workbuddy` 为主，`~/.workbuddy-ai` 双向兼容 📂🔁✨

过去 AI Helper 一律读写 **`~/.workbuddy-ai/models.json`**。  
现实里不同发行版 / 用户环境会把配置放在 **`~/.workbuddy/`**，于是出现「Helper 写进去了，客户端却读不到」或「旧目录里有模型，新客户端一片空白」。😫

**v1.0.63 在 [`workbuddy.rs`](file:///e:/Developer%20Tool/AI%20Helper/src-tauri/src/workbuddy.rs) 重构路径探测、聚合读取与双写同步！** 🎉💚

```
+-----------------------------------------------------------------------------------+
|            💚 WorkBuddy 双路径读写时序 (Dual-Path Pipeline)                         |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  🧭 解析主路径                                                                    |
|         ├── WORKBUDDY_CONFIG_DIR / CODEBUDDY_CONFIG_DIR（若设置）                 |
|         └── 默认 ~/.workbuddy/models.json                                         |
|                                                                                   |
|  📥 读取聚合                                                                      |
|         ├── 先读主路径                                                            |
|         └── 再合并 ~/.workbuddy-ai（按 model id 去重，不覆盖主路径同名）          |
|                                                                                   |
|  🪄 智能回填                                                                      |
|         └── 主路径不存在或模型数少于聚合结果 → 自动把完整列表写入 ~/.workbuddy    |
|                                                                                   |
|  📤 保存 / 删除                                                                   |
|         ├── 主路径必须写成功                                                      |
|         └── 其余候选路径尽力同步（失败只打 warn，不阻断主流程）                    |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

#### 🌈 1. 界面路径会跟着真实文件走
- [`WorkbuddyPanel.tsx`](file:///e:/Developer%20Tool/AI%20Helper/src/components/WorkbuddyPanel.tsx) 顶部路径条与 Key 存储位置文案，按实际 `config_path` 显示 `~/.workbuddy` 或 `~/.workbuddy-ai`，并注明「双向兼容」！💚👀  
- 初始化向导、快速工具说明、连通性测试成功日志、通道分组技术备注全部同步新口径！🧭✨

#### 🛟 2. 自定义配置目录也不掉队
- 支持 `WORKBUDDY_CONFIG_DIR`、`CODEBUDDY_CONFIG_DIR` 指向的 `models.json`，企业 / 便携安装场景可精确落地！🏷️🧪

#### 🧪 3. 回归测试锁死双路径契约
- 候选路径必须同时包含标准目录与历史目录；主路径默认指向 `.workbuddy`；聚合读取不会 panic，有模型时会自动同步到主路径！💎✅

### 2. 🧡 Accio 模型列表「所见即该 Key 所有」：动态注入 · 去掉写死预设 · 节点来源可识别 📋🚫✨

Accio Work 通过本地 Bridge 的 `/api/llm/config/v2` 拉模型下拉框。  
过去容易把**写死的通用预设**和**上一把 Key 磁盘缓存**混进列表，换通道后仍看到用不了的模型。👻

**v1.0.63 改为：只组装当前凭据真实可用的模型 ID！** 🎯🧡

| 能力 | 表现 |
|---|---|
| 📋 **真实列表** | 调用 `fetch_models(base_url, api_key)`，只注入该 Key 能用的模型 |
| 🏷️ **来源标签** | `providerDisplayName` = `AI-Helper (主机名)`，描述为 `模型 via 主机名` |
| ⭐ **默认模型** | 当前配置模型若在真实列表中，排到第一并标记 `isDefault`；不在列表则绝不硬塞 |
| 🛟 **空白保底** | 上游没有 `/v1/models` 或离线时，仅保底当前配置的那一个模型，避免下拉框全空 |
| ❌ **拒绝幽灵预设** | 不再注入 gpt-4o / claude-3-7 / qwen / deepseek 等写死条目 |

Bridge 复用或新启动时都会后台 `refresh_model_list_cache()`，打开 Accio 就能尽快看到最新清单！🔌⚡

### 3. 🔐 凭据指纹缓存：换 Key 立刻失效旧模型 · 磁盘回写防覆盖 · 一键应用到 Agent 同步清缓存 🛡️🔄✨

模型列表按 **`clean_base_url(base_url) || api_key`** 做指纹。斜杠、`/v1`、首尾空格都会被规整，避免「同一节点被当成两套缓存」。🧹

```
+-----------------------------------------------------------------------------------+
|            🔐 Accio 模型缓存生命周期 (Fingerprint + SWR)                            |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  set_accio_config / apply_api_key_to_agents                                       |
|         │                                                                         |
|         ├── 指纹未变且前端省略 cached_models → 保留磁盘缓存 💚                    |
|         └── 指纹已变 → 清空 cached_models + invalidate 内存缓存 🧹                |
|                                                                                   |
|  GET /api/llm/config/v2 → load_key_model_ids                                      |
|         ├── 内存新鲜缓存 (TTL < 300s) → 直接返回 ⚡                                |
|         ├── 陈旧内存 / 匹配的磁盘缓存 → 先返回，后台 refresh (SWR) 🛰️             |
|         ├── 无缓存 → 同步拉取一次                                                 |
|         └── 拉取失败 → 再试陈旧内存；仍空则保底当前配置模型 🛟                    |
|                                                                                   |
|  磁盘回写                                                                         |
|         └── 拉取完成后再 load 最新配置，指纹仍一致才写 cached_models               |
|             （用户中途换 Key 不会被旧请求覆盖）🛡️                                  |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

- 并发刷新用 `IS_REFRESHING` 原子锁，避免连打多次 `/v1/models`！🔒✨  
- [`auth.rs`](file:///e:/Developer%20Tool/AI%20Helper/src-tauri/src/auth.rs) 一键把 API Key 应用到 Accio 时，强制清空模型缓存；若 Bridge 在跑，立刻后台刷新！🔑🧡
