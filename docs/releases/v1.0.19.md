# AI Helper v1.0.19

**发布日期**: 2026-09-25

AI Helper v1.0.19 重点重构并理顺了**客户端启动生命周期的时序依赖与并发控制机制**。本版本彻底解决了以往启动流程中“软件初始化向导”与“自动更新检查”无序并行、导致在初始化配置中途被更新强制重启打断的痛点问题，确立了“**更新检查与自动升级优先、重启进入新版本后再判定并运行初始化**”的健壮启动状态机。

---

## 🚀 核心更新

### 1. 启动生命周期严格串行化：优先更新，绝不打断初始化向导（Boot Lifecycle State Machine）
过去在应用挂载时（`t = 0`），`App.tsx` 会立即同步读取本地存储并弹出 `InitializationModal`，直接发起网络探针和本地配置遍历；与此同时，后台的 `useAppUpdater` 延时 1.5 秒发起版本更新检查。这种并发设计会导致两大严重缺陷：
- **全屏模态框层级争抢**：更新弹窗与初始化向导同时处于全屏遮罩（`z-50`）状态，互相覆盖破坏交互一致性；
- **配置中途重启丢失**：当检测到新版本并下载安装完成时，用户可能正在初始化向导第 4 步仔细填写或修改 API 密钥，客户端触发 `relaunch()` 重启直接销毁了未保存的向导上下文；且在有 Bug 的旧版本中完成初始化毫无意义。

**新版本解决方案**：
- **引入生命周期状态信号**：在 [`ForceUpdateModal.tsx`](file:///e:/Developer%20Tool/AI%20Helper/src/components/ForceUpdateModal.tsx) 的 `useAppUpdater` 中引入 `isBootCheckComplete` 明确标记启动版本检测阶段；
- **严格时序锁机制**：在 [`App.tsx`](file:///e:/Developer%20Tool/AI%20Helper/src/App.tsx) 中重构初始化的唤起条件，**必须满足**「启动检查更新阶段完全结束」且「当前未处于下载中 (`downloading`)、安装中 (`installing`) 或安装就绪等待重启 (`ready`) 的任何更新活跃阶段」时，才判定并唤起初始化向导。

---

### 2. 自动更新极速前置与 2 秒倒计时自动重启（Auto-Update & Auto-Relaunch）
为了确保“有更新立马自动更新，更新完成重启后再进入初始化向导”的流畅体验，全面升级了自动更新的响应与重启机制：
- **检测前置加速**：将应用启动静默检测的触发延时由原先的 `1500ms` 缩减为 `100ms`，确保应用首帧渲染后即刻优先启动版本探测；
- **更新就绪自动重启**：新版本安装包经 Tauri 原生接口校验并静默安装就绪后，更新弹窗启动 **2 秒自动倒计时重启**，倒计时归零后自动调用 `relaunch()` 重启生效；
- **灵活的交互通道**：弹窗同步提供「立即重启生效 (2s)」即时按钮与「稍后」跳过通道。若用户选择稍后或关闭，系统将平滑放行至初始化向导或主界面，绝不造成死锁。

---

### 3. 全局网络安全兜底与离线平滑降级（Resilience & Timeout Safeguards）
针对无代理环境或弱网、断网等极端边界场景，建立了多层容错保障：
- **Rust 后端请求超时收敛**：在 [`updater.rs`](file:///e:/Developer%20Tool/AI%20Helper/src-tauri/src/updater.rs) 中，将多源版本检测（updater.json、GitHub API、Raw、jsDelivr）单次请求超时从 `10s` 优化调整为 `5s`，大幅降低连续 Fallback 带来的等待开销；
- **前端 6 秒安全超时熔断**：在 `useAppUpdater` 中设立 6 秒兜底保护定时器。即使因 DNS 丢包或系统网络挂起，6 秒后仍将自动置位 `isBootCheckComplete = true`，安全放行进入初始化向导或主界面，杜绝应用白屏或无响应卡死。

---

### 4. 首次使用平滑过渡层（Zero-Flicker Transition UI）
- 针对尚未初始化的新用户，在启动更新检测的极短时间窗口（~100ms - 1s）内，呈现设计精致的过渡状态层（「正在检查软件版本与更新...」），有效防止未配置的主仪表盘提前暴露或闪烁；
- 针对已经初始化完成的老用户，应用依然保持秒开主界面，更新检查在后台完全静默进行，体验无缝无打扰。

## 🔄 启动状态流转机制

```
                           【应用启动 App Launch】
                                      │
                                      ▼ (100ms 快速启动)
                        【阶段一：启动版本与更新检查】
                        (未初始化用户展示平滑过渡遮罩)
                                      │
                 ┌────────────────────┴────────────────────┐
                 │ 发现新版本                              │ 无可用更新 / 检查超时 / 离线跳过
                 ▼                                         ▼
         【展示下载安装进度】                     【阶段二：初始化状态判定】
                 │                               (读取 localStorage 标记)
                 ▼                                         │
        【2 秒倒计时自动重启】                   ┌──────────┴──────────┐
          relaunch() 重启新版                   │ 未初始化            │ 已初始化
                 │                              ▼                     ▼
                 ▼                       【唤起初始化向导】        【直接进入主界面】
          (重启进入新版本后,             InitializationModal          Main Dashboard
       版本已是最新，自动流转至阶段二)            │
                                                ▼
                                         【完成向导并保存标记】
                                                │
                                                ▼
                                          【进入主界面】
```
