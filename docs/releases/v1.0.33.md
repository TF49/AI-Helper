## 🚀 详细更新亮点 (Deep Dive)

### 1. 🛡️⚡ 多源容灾智能下载器与死代理残留自愈引擎：构建牢不可破的更新网络铁壁

#### 📉 痛点背景
在以往版本与常规 Tauri 应用中，客户端自动更新经常面临两大棘手难题：
1. **死代理残留导致 10061 积极拒绝 (WSAECONNREFUSED)**：许多开发者在日常开发中会开启 Clash、V2Ray、Surge 等本地代理工具（如监听 `127.0.0.1:7890` 或 `7897`）。一旦用户关闭了代理软件，系统环境变量（`HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`）或 Windows 注册表中的 WinINet 代理配置可能未及时清理。当应用发起网络请求时，底层网络库仍执着连接该本地端口，瞬间抛出 `os error 10061: 目标计算机积极拒绝，无法连接`，导致更新检测和下载直接崩盘 💥😵；
2. **单点镜像抖动与原生更新器超时脆弱**：单一依赖 GitHub 官方 Releases 或单一镜像，一旦遭遇国内运营商 DNS 污染或 CDN 节点波动，下载过程便直接阻断中断，且无法动态换源 ⚠️。

#### 💡 创新机制 1：200ms TCP 极速探测与死代理直愈 (Zombie Proxy Auto-Healing)
v1.0.33 在 Rust 核心层实现了轻量高精度的代理健康探测机制：

```rust
/// 快速验证代理端口是否真正存活（防止用户关闭 VPN 后残留死代理导致 10061 积极拒绝错误）
pub fn is_proxy_alive(proxy_url: &str) -> bool {
    if let Some((host, port)) = parse_host_port(proxy_url) {
        use std::net::{TcpStream, ToSocketAddrs};
        let addr_str = format!("{}:{}", host, port);
        if let Ok(mut addrs) = addr_str.to_socket_addrs() {
            if let Some(addr) = addrs.next() {
                // 仅消耗 200ms 快速探测握手
                if let Ok(stream) = TcpStream::connect_timeout(&addr, Duration::from_millis(200)) {
                    drop(stream);
                    return true;
                }
            }
        }
    }
    false
}
```

- **双源全量采集** 🔍：全面读取环境变量（`HTTPS_PROXY`, `HTTP_PROXY`, `ALL_PROXY`）与 Windows 注册表（`HKCU\Software\Microsoft\Windows\CurrentVersion\Internet Settings` ➔ `ProxyEnable` + `ProxyServer`）；
- **死锁自愈脱困** 🛡️：若检测到配置了代理但该本地端口在 200ms 内无法完成 TCP 握手（说明代理客户端已关闭），系统会自动丢弃该死代理配置，并平滑回退至**系统直连模式**！再也不会因为残留代理而出现 10061 报错！

#### 💡 创新机制 2：多源容灾高速下载器与自动秒切 (Multi-Source Disaster Recovery)
我们在 Rust 端实现专门的 `download_and_install_update` 下载中枢，构建了多通道镜像阵列：

```
                ┌──────────────────────────────────────────────────────────┐
                │        download_and_install_update(version, on_event)    │
                └────────────────────────────┬─────────────────────────────┘
                                             │
                        ┌────────────────────┼────────────────────┐
                        ▼                    ▼                    ▼
                国内高速镜像 1        国内高速镜像 2        国内稳定通道 3
                 (ghfast.top)         (gh-proxy.com)        (ghproxy.net)
                        │                    │                    │
                        └──────────────┬─────┴────────────────────┘
                                       ▼
                        (全部失败备用) GitHub 官方直链
```

- **自动竞速与故障秒切** ⚡：按候选优先级逐一尝试，一旦发现网络中断、HTTP 非 200 或传输停滞，立即通过 IPC Channel 向上抛出 `SwitchSource` 事件，前端 Toast 毫秒级提示：*“通道 [国内高速通道 1] 波动，已自动无缝切换至 [国内高速通道 2]”*，整个切换过程对用户近乎无感；
- **分块流式落盘与实时推流** 🌊：使用 60 秒大包超时，通过 `response.chunk().await` 逐块写入系统临时目录，实时广播下载进度（百分比、已下载字节数、总字节数）；
- **双重完整性安全防线** 🔒：下载完成后自动核验文件大小必须大于 1MB 且严格吻合上游 `Content-Length`，杜绝下载到 404 HTML 错误页的情况；
- **Windows 静默拉起与优雅交接** 🪟：
  ```rust
  let spawn_res = std::process::Command::new(&temp_file_path)
      .arg("/UPDATE")
      .arg("/passive")
      .creation_flags(0x00000008 | 0x00000200) // DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP
      .spawn();
  std::process::exit(0);
  ```
  下载校验通过后，使用分离进程标志静默拉起 NSIS 安装包并安全退出当前应用，实现丝滑更新！

### 2. 🗄️🎯 Trae Work 本地数据库智能选库、事务化写入与写后回读双重自验

#### 📉 痛点背景
Trae Work 采用本地 SQLite 数据库（`state.vscdb`）管理扩展与模型配置。在日常使用中存在三大挑战：
1. **多数据库共存导致写入“迷航”**：当机器上同时安装或升级过 Trae Canary、Trae 稳定版、旧版残余目录或多用户目录时，系统存在多个 `state.vscdb`。如果单纯按固定路径顺序抓取第一个文件，很可能将配置写进了一个已经废弃的旧库中，导致**“AI Helper 界面提示保存成功，但在 Trae 中却怎么也找不到模型”** 😵；
2. **数据库结构破坏与未知字段丢失**：Trae 官方版本迭代极快，若粗暴全量覆盖 JSON 节点，容易抹掉 Trae 新增的字段，引发客户端不可预知的异常；
3. **缺乏写后闭环核验**：数据库写入后若遇到锁争用、权限受限或序列化异常，可能没有真正落盘，但上层却报告成功。

#### 💡 核心突破 1：`choose_traework_db` 智能数据库优选打分算法
v1.0.33 抛弃了简单的文件存在判断，改为对候选文件进行深度只读嗅探与动态打分 🧠：

```rust
/// 选择真正包含 Trae 状态数据的数据库，而不是仅按目录名称命中第一个文件
fn choose_traework_db(candidates: &[PathBuf]) -> Option<PathBuf> {
    candidates
        .iter()
        .filter(|path| path.is_file())
        .map(|path| {
            let mut model_keys = 0usize;
            let mut selection_keys = 0usize;
            if let Ok(conn) = Connection::open_with_flags(
                path,
                OpenFlags::SQLITE_OPEN_READ_ONLY | OpenFlags::SQLITE_OPEN_URI,
            ) {
                let _ = conn.busy_timeout(std::time::Duration::from_millis(250));
                model_keys = conn
                    .query_row(
                        "SELECT COUNT(*) FROM ItemTable WHERE key LIKE '%AI.agent.model.model_list_map'",
                        [],
                        |row| row.get::<_, i64>(0),
                    )
                    .unwrap_or(0).max(0) as usize;
                selection_keys = conn
                    .query_row(
                        "SELECT COUNT(*) FROM ItemTable WHERE key LIKE '%AI.agent.model.recent_user_selection_by_agent_label'",
                        [],
                        |row| row.get::<_, i64>(0),
                    )
                    .unwrap_or(0).max(0) as usize;
            }
            let modified = path.metadata().and_then(|m| m.modified())...;
            (path.clone(), model_keys, selection_keys, modified)
        })
        .max_by_key(|(_, model_keys, selection_keys, modified)| {
            (*model_keys > 0, *selection_keys > 0, *model_keys, *selection_keys, *modified)
        })
        .map(|(path, _, _, _)| path)
}
```
- **智能权重决策** ⚖️：优先选出包含模型列表映射表项最多的数据库；若数量相同则按最新修改时间优选，精准定位正在使用的活跃工作库！

#### 💡 核心突破 2：SQLite 事务原子合并与写后回读双重自验 (Post-Write Verification)
- **事务保护与安全合并 (Transactional Merge Patch)** 🛡️：
  - 开启 `tx = conn.unchecked_transaction()`；
  - 仅对已存在的分类进行字段级合并（Merge），完美保留 Trae 原有或未来新增的未知扩展字段；
  - 自动保留已存的 `custom_model_id`、已加密 `ak` 密文及自定义图标 `icon`；
  - 级联同步 `recent_user_selection_by_agent_label` 与新版 `session_selected_model`，保证新老会话即刻生效；
- **写后回读强制二次验证** 🔍：
  ```rust
  // 写后重新读取验证，避免数据库被锁、路径选错或 JSON 结构变化时仍向前端报告成功
  let (_, verified_models) = read_traework_models(&db_path)?;
  let verified = verified_models.iter().any(|entry| {
      entry.name == composite_name
          && entry.custom_model_id.as_deref() == Some(final_custom_model_id.as_str())
  });
  if !verified {
      return Err(AppError::Other(
          "Trae 状态库写入后校验失败，模型未出现在可解析的自定义模型列表中".to_string(),
      ));
  }
  ```
  写入事务提交后，系统立即重新查询并解析数据库；唯有确认模型在列表中解析成功，才返回成功结构！
- **透明的持久化机制提示** 💡：
  返回全新类型 `TraeWorkSaveResult`，附带合规指引与友好警示，向用户坦诚告知本地缓存写入机制，建议长期保留可在官方管理器中配置，彻底消除用户疑惑！
