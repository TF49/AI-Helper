### 2. 🐞 运行时异常与崩溃堆栈全量捕获：直击问题代码行 🔍🚨📋

过去用户遇到“卡住”、“闪退”或“报错”，客服往往只能收到一张截图，没有任何调用堆栈和环境参数。😵❌  
**v1.0.70 让任何未知异常无所遁形！** ⚡🐞

- 🪤 **全局拦截体系**：同时挂载 `window.onerror` 与 `window.onunhandledrejection`；
- 📦 **完整崩溃快照**：错误发生瞬间，自动采集：
  - **报错类型**（如 `JsRuntimeError`, `UnhandledPromiseRejection`, `ApiTimeout` 等）；
  - **报错摘要**（精确的错误 message）；
  - **完整调用堆栈**（包含调用文件名、行号、列号，甚至精确定位到组件源码位置）；
  - **现场机器硬件快照**（GPU、OS、内存等，排查显卡渲染还是内存不足）；
  - **用户操作前置轨迹（Breadcrumbs）**（报错发生前点击了哪个按钮或切换了哪个面板）；
- 💾 自动入库 `error_logs` 表，并在后台运维大盘提供**一键排查弹窗**与**一键复制完整堆栈**功能！📋🚀

### 4. 🔐 内部开发者口令鉴权 (Admin Token)：严防数据泄露 🛡️🔑🚫

由于监控网页后续将部署在公网服务器上，若没有鉴权，任何人只要扫描到端口就能看到所有用户的设备信息与报错堆栈。🚨  
**v1.0.70 构筑了严密的安全防线：**

- 🔓 **上报通道保持开放**：`POST /api/telemetry/report` 保持开放，客户端静默打点无阻碍；
- 🔐 **查询与管理接口严格鉴权**：
  - `/api/telemetry/dashboard`（大盘总览）
  - `/api/telemetry/devices`（所有设备档案）
  - `/api/telemetry/device/:deviceId`（单机硬件与历史报错）
  - `/api/telemetry/clear-test-data`（数据清除）
  必须在请求头中携带 `x-admin-token: ADMIN_TOKEN`（或 URL 参数 `?token=`）；
- 💡 **网页端无缝对齐**：
  - 监控网页在 Tab 4 设置中内置口令输入框，并持久化到本地 `localStorage`；
  - 首次未授权或口令错误时，自动弹出输入口令窗口并重新加载，防止非法外部访问！

### 5. 🌐 未来域名平滑自动迁移：零发版换域名神器 🚀🔄✨

如果未来为监控服务购买并绑定了专属域名（例如 `https://monitor.yourdomain.com`）：
- 传统做法：必须把客户端代码里的 IP 改成域名，重新打包并强迫所有用户再次升级客户端。😫
- **v1.0.70 优雅方案**：
  1. 服务端在 `server/.env` 中配置 `SERVER_PUBLIC_URL=https://monitor.yourdomain.com/api/telemetry/report`；
  2. 客户端在下一次发送心跳或错误上报时，会自动从服务端的响应体中解析出 `new_server_url`；
  3. 客户端静默将内存和本地存储中的上报地址更新为新域名；
  4. **后续所有上报自动切换至新域名，完全不需要重新发版客户端！** 🥳🍾

### 6. 🐳 Docker 生产编排与数据库自愈重连 🐬⚙️🔄

- 🛠️ **修复静态托管 404**：将 Dockerfile 构建上下文提升至仓库根目录，把 `website/` 完整复制至容器 `/app/website`，实现一个端口同时托管 API 和内部诊断大盘（`/diagnostics.html`）；
- 🩺 **MySQL 容器健康检查**：在 `docker-compose.yml` 中为 MySQL 容器配置 `mysqladmin ping` 健康检查，API 容器配置 `condition: service_healthy`，杜绝因 MySQL 初始化较慢导致 Node 启动时 `ECONNREFUSED`；
- 🔄 **代码层双保险自愈重试**：Node 启动时具备 8 次指数退避重试，运行中每 15 秒主动探测一次，无论容器何时启动，只要 MySQL 就绪即可自动无缝连接并同步数据；
- 🧹 **数据保留策略**：支持配置 `DATA_RETENTION_DAYS=90`，每日自动清理 90 天以前的旧活跃事件，防止磁盘被长期日志填满。
