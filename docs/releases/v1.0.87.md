## 🐳 重磅新功能：DeepSeek Harness 一站式接入 🧩🚀

### 🧭 分步配置向导

打开 **配置中心 → DeepSeek Harness** 🖱️，跟着向导走即可 👣：

1. 🌐 **接入节点**：默认 `https://bob-api.com/`，也可以填写自己的服务网关节点 🏗️
2. 🔑 **填入 BobAPI 密钥**：下一步会自动拉取该 Key 当前分组下的全部可用模型 📥
3. ✅ **勾选模型**：支持全选 / 手动添加模型 ID，已自动过滤图像、语音、向量等无法对话的模型 🧹🖼️🔇
4. ⭐ **选择新会话默认模型**：只影响新会话的默认选择，在 DSH 里随时可以切换 🔄
5. 🧪 **连通性测试 + 一键写入**：每条路由都测试通过后才统一写入，任一失败都不会落盘 🛡️💾

### 🔀 一个 Key 通吃三大协议

AI Helper 会根据模型协议，自动把模型写入 DSH 中对应的专属路由 🎯：

| 路由 🛣️ | 显示名称 🏷️ | 协议 📡 | 适用模型 🤖 |
| :--- | :--- | :--- | :--- |
| `aihelper-claude` | AI Helper · Claude 🟠 | Anthropic Messages | Claude 系列 🧠 |
| `aihelper-codex` | AI Helper · Codex 🟢 | OpenAI Responses | GPT / Codex 系列 💻 |
| `aihelper-cn` | AI Helper · 国产模型 🔴 | OpenAI Chat Completions | DeepSeek、Qwen、GLM 等国产模型 🇨🇳 |

- 🧠 **协议由后端自动判定**：你只管勾选模型，路由归属交给 AI Helper 🪄
- 🖼️ **图文输入全开**：写入的模型默认声明支持文本 + 图片输入 📝🖼️
- 🧹 **自动收拾空路由**：本次保存后没有模型的托管路由会自动移除，配置干干净净 ✨

### 🤝 多分组 Key 和平共处

不同分组的 Key 可以分别保存、同时生效 🔑➕🔑：

- ➕ **添加其它分组的 Key**：在概览中点击「添加其它分组的 Key」，新 Key 与已接入的 Key 并存，默认只勾选尚未接入的模型类型 🧩
- 🔄 **更换 Key**：新 Key 接管被替换 Key 的路由，其它 Key 已接入的路由保持不变 🛡️
- ✏️ **编辑单个 Key**：从概览进入向导，只编辑使用该 Key 的路由，其余一律不动 🎯
- 🔍 **重新核对**：在 bob-api 网页切换分组后，可在概览中一键重新查询各路由的模型是否仍然可用 🩺

### 🛡️ 无损写入：你的配置我们一个字节都不乱动 💎

AI Helper 只管理 **自己的 `aihelper-*` 路由** 和 **`AIHELPER_*` 密钥引用** 🏷️，其余内容全部原样保留：

- 📂 **只读写 `desktop` 档案**：仅配置 DSH 桌面版（`~/.dsh/profiles/desktop/cordis.patch.yml`），CLI / Web / 开发用的其它档案一律不碰 🙅
- 🧷 **逐行精准编辑**：你的自建路由、`records`、注释和 `!!js` 表达式全部逐字节保留 ✍️
- 🔬 **写入前语义校验**：每次写入前都会和原文件做语义比对，确认只改了该改的部分 ✅
- 🔐 **与 DSH 共用写锁**：避免和 DSH 自身（比如刷新官方账号 Token）同时写文件导致冲突 🔒🤝
- 🐳 **官方路由零干扰**：DeepSeek 官方账号登录、官方 API Key 路由（`api.deepseek.com`）绝不改写；如果你的默认模型指向官方模型，保存时也会保持不变 👑
- 🧭 **支持 `DSH_HOME`**：优先读取 `DSH_HOME` 环境变量，未设置时使用 `~/.dsh` 📁

> 💡 首次使用前，请先启动一次 DeepSeek Harness 完成初始化，AI Helper 才能找到桌面版配置哦 🐳✨

## 🔁 体验优化：重启客户端不再"崩溃" 😌🪟

以前重启 Electron 类客户端（如 DeepSeek Harness）时，偶尔会弹出 **"renderer exited: killed"** 崩溃对话框 💥😱。v1.0.87 重写了进程关闭流程 🛠️：

1. 🙋 **先礼后兵**：只向进程树的根（Electron 主进程）发送优雅退出请求（Windows `WM_CLOSE` / Unix `SIGTERM`）🕊️
2. 🎯 **先主后子**：仍未退出时，先单独强制结束主进程，再清理渲染进程，彻底避免崩溃弹窗 💪
3. 🧹 **清理残留**：最后收尾主进程拉起的 Node 后端、终端等子进程 🧽
4. 🛡️ **防误杀**：只清理仍挂在原父进程下的子进程，避免 PID 被系统复用后误伤无关程序 🚫🔪

## 🔔 智能诊断：模型"不在分组"专属提醒 🩺💡

在 bob-api 网页切换 Key 的分组后，原先勾选的模型可能已经没有可用渠道，中转站会返回 `model_not_found`（状态码常为 503）📭。以前这会被误报成"上游故障" 😵，现在：

- 🧾 **API 测试给出准确原因**：明确提示「该模型不在此 API Key 当前分组中」，并引导你重新拉取可用模型 🔄
- 🏷️ **DSH 面板标记「分组不可用」**：上次拉取时已不在当前分组的模型会被自动取消勾选并标记 ⚠️
- ✋ **手动添加的模型除外**：你明确添加的模型 ID 不会被自动取消，尊重你的选择 🙌
- 🧪 **保存前预警**：若勾选了不在当前分组的模型，会提前告诉你连通性测试为何不通过 📢

## ❓ 常见问题 FAQ 🧭💬

### 配置 DSH 会影响我的 DeepSeek 官方账号吗？ 🐳🤔

不会 🙅。AI Helper 只写入 `aihelper-*` 路由和 `AIHELPER_*` 密钥引用，DeepSeek 官方账号登录、官方 API Key 路由以及你自建的路由都原样保留 🛡️✅。如果你的默认模型指向官方模型，保存时也会保持不变 👑。

### 为什么我的 Claude 模型和国产模型被写进了不同路由？ 🔀

因为它们使用的协议不同 📡：Claude 走 Anthropic Messages，GPT 走 OpenAI Responses，国产模型走 Chat Completions。AI Helper 会按协议自动分流，让同一个 Key 下的不同模型都能正常对话 🧠✨。

### 保存后在 DSH 里看不到新模型？ 👀

DeepSeek Harness 在启动时读取配置 📖，保存后需要**重启客户端**才能加载新路由 🔁。可以直接在测试终端或路径管理卡片里点击「重启 DeepSeek Harness」⚡。

### 提示"分组不可用"是什么意思？ ⚠️

说明该模型此前配置过，但已不在这个 Key 当前所属的分组中，常见于在 bob-api 网页切换了分组 🔄。请重新拉取可用模型、取消勾选不可用的模型，或在网页上把 Key 切回原分组 🩺。

### 提示"未找到 DeepSeek Harness 桌面版配置"怎么办？ 📂

请先启动一次 DeepSeek Harness 桌面版完成初始化 🐳，它会在 `~/.dsh`（或 `DSH_HOME` 指定的目录）下生成配置档案，之后回到 AI Helper 即可正常配置 ✅。
