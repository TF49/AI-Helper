## 🚀 详细更新亮点

### 1. 🔍 WorkBuddy 全维度智能深度寻径体系 (Multi-tier Discovery Engine)

为了让 **WorkBuddy** 桌面客户端在各种复杂的操作系统与安装环境下均能“即开即用、自动感知”，本次更新对其寻径与进程匹配逻辑进行了革命性的升级与加固 🌟🟢🤖：

- 🚫🛡️ **干扰伴生进程精确拦截与防伪过滤 (`matches_process`)**：
  - **背景痛点**：WorkBuddy 在运行时会启动多个后台辅助进程（如 `WorkBuddySupervisor.exe` 守护进程、`sharetarget` 共享目标服务、卸载更新进程以及 `crashpad` 崩溃日志收集器），此前由于进程匹配规则较为宽泛，极易误将守护进程或辅助组件识别为主程序，导致启动或路径记录出现偏差 😵💥；
  - **加固升级**：引入了严格的黑名单过滤机制，全面拦截 `supervisor`、`sharetarget`、`uninstall`、`crashpad` 等辅助程序 🛑；
  - **精准匹配**：将原先松散的命令行匹配收紧为精准的 `.exe` 结尾校验（`workbuddyai.exe` / `workbuddy.exe`），彻底消除误判，确保 100% 锁定客户端主界面程序 🎯✨！

- 🗄️📜 **全新 Windows 注册表深度穿透探测 (`find_workbuddy_in_registry`)**：
  - **全架构注册表扫描**：同时支持扫描 `HKEY_LOCAL_MACHINE`、`HKEY_LOCAL_MACHINE\Software\Wow6432Node`（64位系统兼容32位项）以及 `HKEY_CURRENT_USER` 的软件卸载登记表 🏛️🔍；
  - **三重容错提取策略**：
    1. 🖼️ **DisplayIcon 解析**：优先读取应用图标路径，并智能剔除末尾的 `,0` 资源标识符与双引号；
    2. 📁 **InstallLocation 校验**：直接获取软件官方安装根目录，自动搜寻 `WorkBuddyAI.exe` 与 `WorkBuddy.exe`；
    3. 🔄 **UninstallString 反向寻径**：若前两者均未提供，智能读取卸载程序位置并反推父目录，精准锁定主程序入口；
  - 🌐 **App Paths 终极兜底**：深度遍历注册表 `App Paths\WorkBuddyAI.exe` 与 `WorkBuddy.exe`，即便绿色安装或免安装注册也能瞬时定位 ⚡💎！

- 💽📦 **多盘符 Microsoft Store / WindowsApps 智能择优扫描**：
  - 支持横跨 `C:`、`D:`、`E:`、`F:` 等全部分区智能遍历 `Program Files\WindowsApps` 与 `WindowsApps` 目录 📂；
  - 智能采集所有匹配的 WorkBuddy 应用包，并按照**版本号降序排序**，确保在用户系统残留旧版更新包时始终选用最新的可执行程序 🚀📈！

- 🪜✨ **7 大层级立体化寻径全景一览**：
  1. 🏃‍♂️ **第 1 层**：运行中进程实时抓取 (`running_process` / `windows_apps`)；
  2. 📦 **第 2 层**：多盘符 WindowsApps 商店包版本最新择优 (`windows_apps`)；
  3. 🏛️ **第 3 层**：Windows 注册表全局与当前用户安装记录深度穿透 (`registry`)；
  4. 🏠 **第 4 层**：用户主目录标准路径 (`%LOCALAPPDATA%\Programs\WorkBuddyAI` 等) (`standard_dir`)；
  5. 💻 **第 5 层**：系统 Program Files 矩阵 (`ProgramFiles` / `(x86)` / `ProgramW6432`) (`standard_dir`)；
  6. 🛠️ **第 6 层**：全盘符开发者工具目录嗅探 (`C:` ~ `F:\Developer Tool\...` 等) (`standard_dir`)；
  7. 🌐 **第 7 层**：系统 `PATH` 环境变量自适应解析 (`path_env`)；
  - 🍏 **跨平台支持**：针对 macOS 平台预置 `/Applications/WorkBuddy.app` 与 `/Applications/WorkBuddyAI.app` 自动探测。

### 2. 🧩 后端架构解耦与复用升级 (Architecture Unification & DRY)

- 🔄🤝 **统一全局探测源，终结多头维护**：
  - **重构前**：`workbuddy.rs` 与 `app_paths.rs` 各自维护了一套探测路径列表，规则不一且难以同步更新，存在逻辑分化的风险 🔀⚠️；
  - **重构后**：`workbuddy.rs` 中的 `detect_workbuddy_installation()` 直接调用 `crate::app_paths::detect_workbuddy_client_path()`，全局仅保留一套高内聚、高鲁棒的寻径实现 🎯；
  - **收益**：应用路径管理面板、WorkBuddy 配置面板、连通性探测以及托盘运行状态感知实现 100% 行为一致，维护成本降至最低 🧹💎！
