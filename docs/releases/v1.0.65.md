## 🌟 核心升级亮点 (Core Highlights) 💡✨💎🤖🛰️

### 1. 🤖 官方 Webhook 内置：终端用户零配置，一键送达开发团队飞书群 🛰️📨✨

过去反馈通道依赖本机或打包环境里配齐飞书凭据，没配就会走「复制到剪贴板」兜底，开发团队收不到结构化卡片。😫  
**v1.0.65 在 [`feedback.rs`](file:///e:/Developer%20Tool/AI%20Helper/src-tauri/src/feedback.rs) 内置官方反馈群自定义机器人地址！** 🎉🎨

- 📦 安装包开箱即用：点「提交」就能把互动卡片推到开发团队飞书群；  
- 🧑‍💻 开发者仍可用自己的 Webhook 覆盖，互不影响；  
- 🛟 只有地址非法（非 `http://` / `https://`）才回落剪贴板，真正「能发就发、发不了也不丢」！

```
+-----------------------------------------------------------------------------------+
|            🛰️ v1.0.65 提交送达路径 (Webhook Fast Lane)                             |
+-----------------------------------------------------------------------------------+
|                                                                                   |
|  🖱️ 用户点击「提交」                                                              |
|         │                                                                         |
|         ▼                                                                         |
|  🧩 组装互动卡片（类型徽章 · 邮箱 · 版本 · 系统 · 配置目标 · 正文 · 时间戳）      |
|         │                                                                         |
|         ▼                                                                         |
|  🔐 resolve_webhook_url 四级解析                                                  |
|         │                                                                         |
|         ├── ✅ 合法 http(s) → POST msg_type=interactive → 飞书群 🎉               |
|         └── ❌ 非法地址 → 前端复制全文到剪贴板 🛟                                  |
|                                                                                   |
+-----------------------------------------------------------------------------------+
```

### 2. ✂️ 双通道精简为单通道：去掉 App ID / App Secret / Chat ID 换票路径 🧹🔐✨

v1.0.64 同时支持「开放平台自建应用机器人」和「群自定义机器人 Webhook」。自建应用需要三件套凭据、先换 `tenant_access_token` 再发消息，对终端用户几乎不可用。  

**v1.0.65 只保留 Webhook 互动卡片通道：** 🎯

| 维度 | 🔴 v1.0.64 | 🟢 v1.0.65 |
|---|---|---|
| **默认能否送达** 📬 | 未配凭据则失败，只能复制剪贴板 ❌ | 内置官方机器人，默认就能送达 ✅ |
| **通道数量** 🛰️ | 自建应用 + Webhook 双通道 ⚖️ | Webhook 单通道，链路更短 ✅ |
| **前端载荷** 📦 | 携带 `app_id` / `app_secret` / `chat_id` 🔑 | 前端类型已移除三件套，只保留可选 `webhook_url` ✅ |
| **`.env.example`** 📄 | 四个飞书变量 📋 | 只保留 `FEISHU_WEBHOOK_URL` ✅ |
| **`build.rs` 注入** 🏗️ | 注入四枚环境变量 🔑 | 只注入 Webhook 地址 ✅ |

后端结构体仍对旧字段做 `serde(default)` 兼容，历史调用不会因为少传字段而反序列化失败。🧩💚

---

### 3. 🔐 四级覆盖策略：参数 > 运行期环境 > 编译期注入 > 官方默认 🪜🛡️✨

```
请求参数 webhook_url
        │ 有值且非空？
        ▼
运行期环境变量 FEISHU_WEBHOOK_URL
        │ 有值且非空？
        ▼
编译期 option_env!("FEISHU_WEBHOOK_URL")   ← .env / CI secrets 在打包时写入
        │ 有值且非空？
        ▼
官方内置 DEFAULT_FEISHU_WEBHOOK_URL         ← 永远兜底，开箱即用 🏆
```

适用场景一览：

- 🧪 **本地开发**：复制 `.env.example` 为 `.env`，填自己的测试群 Webhook；  
- 🏗️ **正式发版**：GitHub Secret `FEISHU_WEBHOOK_URL` 在构建时注入，可覆盖默认地址；  
- 👤 **普通用户**：什么都不用管，用官方内置机器人直达开发群！🎉

### 4. 🏗️ 发版流水线安全注入：Windows + macOS 同步带上飞书 Secret 🔑🪟🍏✨

[`.github/workflows/release.yml`](file:///e:/Developer%20Tool/AI%20Helper/.github/workflows/release.yml) 在构建步骤新增：

```
FEISHU_WEBHOOK_URL: ${{ secrets.FEISHU_WEBHOOK_URL }}
```

覆盖范围：

1. 🪟 **Windows x64 NSIS 安装包**（`pnpm tauri build --bundles nsis`）；  
2. 🍏 **macOS Apple Silicon + Intel DMG**（`--target` 矩阵双架构）。  

配合 [`build.rs`](file:///e:/Developer%20Tool/AI%20Helper/src-tauri/build.rs) 的 `cargo:rustc-env`，正式安装包在编译期就带上可覆盖的 Webhook，仓库里依然只有空模板，真钥不进 Git！🚫🔓💎
