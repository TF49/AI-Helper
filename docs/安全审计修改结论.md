## 1. 核心结论与结项判定

根据《资金与凭据安全整改开工文档》规定的 8 项强制规则（R1～R8）与 17 项研发任务（SEC-01～SEC-17），本轮整改的工作成果与当前结项判定如下：

### 1.1 总体判定结论
1. **客户端与供应链（本仓库职责）：全部完成加固与封堵**  
   - 涉及 32 个现有文件重构、6 个核心安全模块新建（`credential_policy.rs`、`instance_auth.rs`、`paid_request.rs`、`safe_fs.rs`、`update_trust.rs`、`image_fetch.rs`）及 1 个前端安全剪贴板模块（`secureClipboard.ts`）。
   - 全部通过 `cargo test --locked --lib`（127 项单元测试全绿通过）、`pnpm typecheck`（0 类型错误）、`cargo clippy -- -D warnings`（0 警告）以及渲染层编译打包验证。
   - 复核审查报告列出的 **16 项关键发现（P0-1、P1-1～P1-11、P2-1～P2-4）已 100% 完成客户端代码落位与测试闭环**。
2. **服务端依赖（Bob API 服务端职责）：处于阻塞待交付状态（未结项）**  
   - 资金安全底线原则规定：“**资金安全结项必须包含服务端证据，不能只以客户端编译通过或界面出现警告为依据**”。
   - SEC-11（服务端对象级权限、会话主动吊销、Token 独立 group-only 更新接口）与 SEC-12（服务端并发额度硬限、负向上游额度记账、支付回调幂等）属于服务端独立仓库代码，当前缺少服务端接口契约与测试台账证据，**不得单方面签署整改已全面结项**。
3. **当前阶段结论**：  
   **客户端安全漏洞与本地资金跑冒滴漏风险已彻底阻断，已具备发布首个安全加固版本（v1.0.70）的客户端代码就绪条件；整体安全审计结项报告待服务端完成部署并交付对应证据后签署。**

## 3. 已完成内容清单（Completed Items）

### 3.1 客户端架构加固与核心任务落地（SEC-01 ～ SEC-17）

#### 【SEC-01】更新可信根、签名防伪与首个安全版本升级路径
- **代码落位**：`src-tauri/src/update_trust.rs`、`src-tauri/src/updater.rs`、`scripts/sync-mirror.sh`、`docs/security/SEC-01-FIRST-SECURE-UPDATE.md`。
- **完成机制**：
  1. 接入内置 minisign 公钥强制验签机制，只允许已签名的安装包和 `latest.json.sig` 清单；
  2. 防重放与降级保护：解析 `release_seq` 序号与最小安全版本限制，防降级、防跨平台包执行、防同版本不同 Hash 覆盖；
  3. 破坏检测：`load_trust_state` 状态文件损坏时报 `TrustError::InvalidManifest` 停机阻断，杜绝静默降级；
  4. 故障明确化：所有更新源（官方/镜像）请求失败均抛出明确错误，严禁将网络异常呈现为“可信无更新”；
  5. 明确首个安全加固版本（v1.0.70）的升级路线：因历史旧版本（v1.0.69 及以前）客户端缺乏验签能力，必须引导用户自官方 Releases 手动校验哈希安装首个安全版本。
- **测试证据**：`update_trust::tests` 21 项单元测试全部通过。

#### 【SEC-02】统一凭据来源与严格网络出口策略
- **代码落位**：`src-tauri/src/credential_policy.rs`、`claude.rs`、`codex.rs`、`workbuddy.rs`、`accio/config.rs`、`model_fetch.rs`、`api_test.rs`。
- **完成机制**：
  1. 建立受管 Key SHA-256 摘要索引库，在所有工具配置保存、模型发现拉取与握手测试前，统一调用 `assert_managed_key_destination` 校验；
  2. 严禁受管 Key 发往旧第三方地址或非核实域名，只允许官方白名单 HTTPS 域名（`bob-api.com`、`api.bob-api.com`、`helper.bob-api.com` 等）；
  3. 远程目标严禁使用明文 HTTP，严禁 URL 携带 userinfo 或敏感 query 字段；本地 loopback HTTP 仅在显式开发调试标记下允许。
- **测试证据**：`credential_policy::tests` 与 `api_test::tests` 单元测试通过。

#### 【SEC-03】分组修改仅改 group，严格保留既有安全限制
- **代码落位**：`src-tauri/src/auth.rs`、`src/components/auth/TokenSelectModal.tsx`。
- **完成机制**：
  1. 彻底删除“详情拉取失败则按 Token 列表字段重建完整数据并 PUT 回写”的危险降级逻辑；
  2. 详情获取失败时立即终止切组流程，防止将服务端原有的 IP 白名单、模型黑白名单、额度上限和过期时间静默清空；
  3. 服务端契约明确为仅更新 group 字段，更新成功后重新拉取权威状态。
- **测试证据**：`TokenSelectModal.tsx` 与 `auth.rs` 状态隔离通过。

#### 【SEC-04】CLI 局部更新、原子替换与多用户 ACL 权限隔离
- **代码落位**：`src-tauri/src/safe_fs.rs`、`claude.rs`、`codex.rs`、`workbuddy.rs`、`TokenSelectModal.tsx`。
- **完成机制**：
  1. **局部更新保留**：Claude 配置保留 `permissions`、`sandbox`、`hooks`；Codex 兼容 TOML `InlineTable`，保留其他 provider；Workbuddy 保留未操作的模型列表；

  3. **安全原子写入**：`safe_fs::safe_write_file` 采用先写临时文件、加 `.bak` 备份、重命名替换机制，杜绝断电或写入冲突损坏配置；

- **测试证据**：`claude::tests`、`codex::tests`、`workbuddy::tests` 单元测试全数通过。

#### 【SEC-05】Bridge 实例强鉴权与可靠端口监听
- **代码落位**：`src-tauri/src/instance_auth.rs`、`src-tauri/src/accio/bridge.rs`、`docs/security/SEC-05-ACCIO-COMPAT.md`。
- **完成机制**：
  1. 运行时生成加密安全的随机实例凭据（Instance Token）；
  2. 除 `/health` 健康检查外，所有涉及模型调用、生图和计费的路由必须在读取 body 之前完成鉴权（支持 `x-ai-helper-instance`、`x-gateway-auth` 或 `Authorization: Bearer`）；
  3. 转发至上游前自动剥离本地实例凭据，杜绝本地凭据泄露至外部上游；
  4. 严格校验 Origin 与 Host 头，防范 DNS Rebinding 与跨站伪造；
  5. 监听端口冲突直接报错退出，彻底移除 `unwrap_or(8787)` 默认回退逻辑，防止将流量发往伪造的本地假网关。
- **测试证据**：`instance_auth::tests` 单元测试全数通过。

#### 【SEC-06】付费状态机、防跨供应商二次扣费与图片流控制
- **代码落位**：`src-tauri/src/paid_request.rs`、`src-tauri/src/accio/bridge.rs`。
- **完成机制**：
  1. 请求状态严格区分：本地拒绝、未受理、已受理、已完成、结果未知；
  2. 任何已受理（上游返回 200/500/超时）或计费未知的请求，严禁跨供应商自动重试，杜绝自动补单造成重复计费；
  3. 剔除 500 内部服务错误的端点回退，仅对 404/501（明确未受理）允许协议端点降级；
  4. 生图取图分离：取图失败时保留原图 URL 元数据，仅重试下载取图，严禁重新调用计费接口重复生图。
- **测试证据**：`paid_request::tests` 单元测试验证防二次提交机制有效。

#### 【SEC-07】模型校验、本地生图原子预算账本与崩溃恢复
- **代码落位**：`src-tauri/src/paid_request.rs`、`src-tauri/src/accio/bridge.rs`。
- **完成机制**：
  1. 未配置生图模型或模型非法时，严禁调用付费生图通道，杜绝静默使用高价模型；
  2. 采用最小计费整数单位建立本地预算账本（`image_budget_ledger.json`）；
  3. 请求发出前原子预留：`已结算 + 未决预留 + 本次预留 <= 预算`，预留失败直接阻断；
  4. 账本跨重启持久化，应用崩溃或重启后未决预留不丢失，持久化失败严格上报 `error` 日志拒斥静默吞异常。
- **测试证据**：`paid_request::tests::concurrent_reserve_allows_only_budget_cap` 等测试通过。

#### 【SEC-08】权威费率确认、高倍率强提醒与账务规范化

## 4. 未完成内容与外部依赖项清单（Pending Items & Blockers）

整改开工文档明确强调：“**资金安全结项必须包含服务端证据，不能只以客户端编译通过或界面出现警告为依据**”。以下项目属于整改完成前必须交付的未决项与外部依赖：

### 4.1 服务端研发与审计证据交付（阻塞项 - 主责：Bob API 服务端研发）
客户端已在本地消除了越权与数据覆盖隐患，但作为资金安全最终保障，服务端必须在真实环境中提供以下两组核心证据并验收通过：

1. **SEC-11（服务端认证、会话与 Token 对象授权）**：
   - **缺失内容**：
     - Token 读写、改组、改额度/模型/IP 的**服务端对象级权限校验**（证明账号 A 无法操作账号 B 的 Token 甚至不能越权查看）；
     - 服务端提供纯 `PATCH /group-only` 独立修改接口证据，明确字段缺失语义与版本冲突并发保护机制；
     - 服务端会话主动失效证据：主动登出或修改密码后，旧 refresh cookie、access token 与 sid 是否在服务端完全阻断。
   - **交付要求**：服务端负责人需提交接口契约文档、隔离测试账号实测脱敏报文，证明跨账号请求被 403 阻断且无状态残留。

2. **SEC-12（服务端并发额度硬限、记账幂等与充值核验）**：
   - **缺失内容**：
     - **服务端并发硬限**：由于 Claude CLI、Codex CLI 等工具可能直接绕过客户端网关直连 Bob API，本地预算账本无法形成账户全局约束。必须由服务端证明：当账户余额仅够一笔消费时，多工具/多节点并发请求最多仅扣费一笔，后续并发请求被服务端硬限拦截；
     - **结算与退款幂等**：流式中断、上游超时、延迟 usage 上报时服务端不重复扣款；充值与退款回调有签名校验与防重放幂等支持。
   - **交付要求**：交付多线程并发消费测试日志、账务前后余额核对清单及对账证据。

### 4.2 外部工具实机联调与兼容性矩阵（待验证项 - 主责：客户端研发 / 测试）
